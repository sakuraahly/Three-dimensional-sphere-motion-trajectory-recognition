# 高清摄像头与动态分辨率计划（2026-10-23）

> 状态：**P1–P3 已交付；2026-10-24 真机验证后默认已改为 2560x1440@24。**
> 原计划曾以 1080p@30 为默认（当时 1440 主循环未验证）。2026-10-24 真机确认：
> 两台外接相机**无视 1920/1280 请求、恒给 2560x1440**，旧默认会让 `record_stereo`
> 的实际分辨率校验必然失败；且 1440p@30 主循环实测仅 24.07fps（242/300 帧/路），
> **24 才是稳定目标**。旧 1080 档与旧 1080 会话仍可读，不再默认。

---

## 1. 原问题（修复前，来自 GUI Specialist 审计）

- GUI 分辨率列表最高 `1920x1080`（`apps/gui_main.py:69`）；标定和录制共用这个下拉；
- 实时入口 `_start_realtime` 不传 width/height，`run_realtime.py` 默认 **1280x720**；
- 录制默认 1920x1080（当时；2026-10-24 已改 2560x1440@24），HFYU 在 1080p30 约 34 fps/路；4K 不在现有 GUI 链路；
- `cameras.py doctor` 接受 `--width/--height`，默认 1920x1080（当时；现已跟 profile = 2560x1440）；
- seed 半径是**原图像素**，分辨率变化必须重点；
- 显示宽度固定 960；4K 最终也会缩到 960 显示，实时视觉收益有限；
- 最大风险：**标定/录制/离线分辨率混用**，内参和极线会错，界面未必报错。

### 1.1 已接入（2026-10-23，默认值已于 2026-10-24 更新）

- `video_profiles.DEFAULT=RECORD_DEFAULT=2560x1440`，1920x1080 / 1280x720 仍为可选档；
- GUI `RESOLUTIONS` 来自 profile；标定/录制仍共用下拉，面板帧率默认 24；
- 实时入口按当前 `calib_res` 传 `--width/--height`，>1920 时加 `--detect-width 1280`；
- `_common` / `run_realtime` / doctor 默认从 profile 读；`record_stereo` 默认 1440@24，
  请求 30 时告警（主循环实测 24.07fps）；
- 选 1440 时 GUI 提示：`record_stereo` 主循环实测 24.07fps（242/300 帧·10 秒·HFYU，
  两路一致），**24 是稳定目标、请求 30 会丢帧**；长录/其他机型未验证。

## 2. 目标

- 分辨率/帧率/编码不再散落在 GUI、录制、标定、检测各处；
- 由一个 **profile/能力探测** 决定“能用什么”，不能用的明确回退；
- 标定、录制、离线分析必须绑定同一分辨率并校验；
- 1080p 旧路径和旧数据保持兼容；
- 4K 只在真机证明两路稳定后启用，不作为默认。

## 3. 设计（动态，不是简单加下拉项）

### 3.1 单一来源

新增 `sphere_tracker/video_profiles.py`（纯逻辑）：

```python
@dataclass(frozen=True)
class VideoProfile:
    width: int
    height: int
    # properties: label / pixels / high_res

PROFILES = (...)                 # 6 档，按高到低
DEFAULT = PROFILES[1]            # 2560x1440（2026-10-24 起）

parse("1920x1080") -> VideoProfile   # 旧 1080 档仍可读
options() / labels() -> list[str]
get(width, height) -> VideoProfile
resolve(requested, actual_w, actual_h) -> (VideoProfile, fallback: bool)
validate_pair(left, right) -> None
detection_width(width, target=1280) -> int
```

规则：

- `options()` 含 6 档，`DEFAULT=2560x1440`；
- GUI 的 `RESOLUTIONS`、`_common` 双目默认、实时入口、doctor 默认都从本模块读取；
- `record_stereo` 默认 `RECORD_DEFAULT=2560x1440`、帧率默认 24；显式请求 >24fps
  时打印主循环吞吐警告（1440@30 会丢帧）；
- 选 1440 后 GUI 提示“`record_stereo` 主循环实测 24.07fps（242/300 帧·10 秒·
  HFYU，两路一致）；24 是稳定目标、请求 30 会丢帧；长录未验证”；
- 旧标定/旧会话的 `image_size` 不变：旧 1080 标定、旧 1080 会话照常可读。

### 3.2 入口绑定

| 入口 | 要改 |
| --- | --- |
| GUI 标定/录制 | 选项来自 `video_profiles.options()`；录制读同一个 profile |
| `_start_realtime` | 传 `--width/--height`，不再固定 720p |
| `run_realtime.py` | `--width/--height` 默认来自 profile；GUI 按当前档显式传 |
| `record_stereo.py` | 默认 `RECORD_DEFAULT`（2560x1440）@24；显式请求 >24fps 告警；录制前校验标定 `image_size` |
| `calibrate_stereo.py` | 默认来自 profile；帧率默认 24；分辨率写到标定 |
| `cameras.py doctor` | 默认来自 profile（2560x1440）；文案不再假设只有 1080p |
| 离线双目 | 1440p 时显式 `--detect-width 1280`；GUI 默认 1440p，暂不自动改检测宽度 |
| 检测 | 高分辨率按 `detection_width` 降采样，坐标映射回原图 |
| seed | 预览缩放不改变坐标；半径按原图，分辨率变时提示重选 |

### 3.3 一致性校验

- 标定 `image_size` == 会话视频分辨率，否则报错；
- 录制实际分辨率 == 请求/标定分辨率，否则报错；
- 离线 `run_stereo_video` 视频分辨率 == 标定 `image_size`，否则报错；
- 不允许“标定 1080p、录制 4K、离线再缩放”这种静默混用。

### 3.4 实时/录制策略

- 默认：**2560x1440@24**（真机实测恒给 1440；主循环 24.07fps，30 会丢帧）；
- 1440p@30 不稳定，4K 只有两路实测稳定、磁盘/带宽足够才启用；
- 4K 不默认无损录制；需要单独 profile 和编码/存储验证；
- 高分辨率检测必须走 `--detect-width`/`detection_width()`，不直接全图 4K。

## 4. 角色与阶段

| 角色 | 任务 | 产物 |
| --- | --- | --- |
| **Leader（主 agent）** | 定默认/能力边界，拆四条线，集成与提交；不直接写大批量实现 | 计划、接口、最终验收 |
| **Specialist A** | GUI/入口审计（已完成） | 事实 + 风险 |
| **Specialist B** | 标定/录制/极线审计（待重派） | 5 分钟结论 |
| **Human** | 提供 doctor 结果，批准 4K/硬件策略 | 实测数据 |
| **Executor C** | 实现 `video_profiles.py` + 指定入口接入 | 代码 + 自测 |
| **Critic D** | 独立验收 1080 回归/1440/4K 分支/一致性 | PASS/FAIL/BLOCKED |
| **Memory** | 更新本文/交接/决策 | 文档 |

阶段：

```text
P0 规格确认（当前）  → 用户 doctor 数据
P1 profile 模块      → 单一来源
P2 入口接入          → GUI/实时/录制/标定/doctor
P3 一致性校验        → 三处绑定
P4 Critic 验收       → 1080 旧档回归 + 1440/4K 能力分支
P5 真机 1440/1080    → 采用/回退（2026-10-24 已采用 1440@24）
```

## 5. 验收标准

- `run.bat test full` 23/23；
- **默认 2560x1440@24**：GUI/`_common`/实时/录制/doctor 一致；
- 旧 1080 会话、旧 1080 标定、显式 1080 命令仍可用（旧档不被删除）；
- 代码里不再出现多份 `2560/1920/1080/720/960` 作为“事实来源”（测试/文档默认值除外）；
- 标定/录制/离线分辨率不一致时**明确报错**（1080 标定 + 1440 录制 return 2）；
- 1440p/4K 只有在 `doctor` 两路成功时可选；失败明确回退；
- 实时入口不再固定 720p/60fps；
- Critic 独立签字，不由 Executor 自评。

## 6. 明确不做

- 不在没有 `doctor` 数据时把默认改成 4K；
- 不为了“高清”牺牲稳定性：1440@30 已实测丢帧，默认取 24，不静默承诺 30；
- 不删除旧分辨率/旧会话（1920x1080 / 1280x720 保留）；
- 不把 4K 直接塞进 HFYU 默认录制；
- 不让 Executor 自己写“通过”。
