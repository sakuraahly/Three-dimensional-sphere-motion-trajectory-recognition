## 1. 要解决什么

一句话：**让"录一次数据"变成一个有目录、有元数据、可校验、可回放的会话，而不是两段散落的 mkv。**

现在缺的不是算法，是**数据层**：

| 现状 | 问题 |
| ---- | ---- |
| 没有 `data/` | 录制数据只能塞 `outputs/`（语义是"删了能再生"）或 `assets/videos/`（语义是"入库静态素材"）——**两个都不对** |
| 没有 `session.json` | 一周后只有两段视频，不知道分辨率 / 基线 / 同步偏移 / 用的哪份标定 |
| 没有录制/离线入口 | `run_realtime --record` 只录单路标注画面；`StereoReconstructor` 只被测试调用 |
| 没有数据校验 | 录坏了（掉帧、分辨率不一致、标定对不上）要等到处理时才发现 |

## 2. 目标结构

```
data/                         ← 新增：真机录制会话（不入库，单独备份）
  README.md
  sessions/<YYYYMMDD-HHMMSS>/
    session.json              ← 唯一权威元数据
    left.mkv / right.mkv      ← 无损原始视频（FFV1）
    calib/                    ← 本次使用的标定快照（npz + json）
    derived/                  ← CSV / 图 / 标注视频（可再生产物）
    notes.md                  ← 现场备注（可选）
  raw/                        ← 外部拷贝进来的原始素材（可选）

stereo/sessions.py            ← 新增：会话 schema / 读写 / 校验
apps/tools/check_dataset.py   ← 新增：会话校验 CLI
apps/record_stereo.py         ← P1：双路无损录制（需相机）
apps/run_stereo_video.py      ← P2：离线双目轨迹（无相机可测）
```

### 为什么 `data/` 不是 `outputs/`

| 目录 | 语义 | 删了会怎样 |
| ---- | ---- | ---------- |
| `outputs/` | **可再生产物**（标注视频、CSV、调试图） | 重跑一次就回来 |
| `assets/` | **入库的静态素材**（标定板 PDF、示例图） | 从 git 恢复 |
| **`data/`（新）** | **不可再生的真机录制** | **没了就没了**，必须单独备份 |

这条区别要写进 `AGENTS.md` 的放置规则；否则下一个人一定会把录像放进 `outputs/`。

## 4. `session.json` 的字段

| 组 | 字段 | 为什么必须有 |
| -- | ---- | ------------ |
| 身份 | `schema/version/id/created/label/notes` | 版本可迁移；`id` 是目录名 |
| 相机 | 左右 `role/identity/name/port/backend/width/height/fps_requested/fps_measured/frame_count/video` | 知道"哪台、什么模式、录了多少帧" |
| 视频 | `codec/container/lossless` | 无损是硬要求；有损要显式标记 |
| 标定 | `path/sha256/image_size/baseline_mm/baseline_measured_mm/created/verdict` | 没有 sha256，就无法证明"这批数据用的是哪份标定" |
| 同步 | `method/offset/confidence/note` | 闪光/拍手的偏移，正负号最容易搞反 |
| 环境 | `git_commit/python/opencv/platform` | 复现问题时先看版本 |

**基线策略（按用户决定）**：

- `baseline_mm` = **标定算法结果**，作为几何参数使用；
- `baseline_measured_mm` = 物理测量值，**只作交叉核对**，不覆盖算法结果；
- 两者偏差：>10% 警告，>20% **判会话不可用**（多半是方格尺寸、L/R、板规格错了）；
- 标定结果本身仍按 `calib/` 的四级判定，不因为物理测量而改判。

| ---- | ---- |
| `data/` 被误提交 | `.gitignore` 只忽略 `data/sessions/*` 与 `data/raw/*`；README 仍入库 |
