# 单目主线与 GUI 分窗重做（2026-10-27 · 第八轮）

> **一句话**：把界面从"一个 3055 行、199 个控件、3.5 屏的长滚动页"改成
> "**门厅 + 按模式分窗**"，同时把"单目标定"从库里的一个内部函数变成
> **用户能点、链路真用得上**的第一条正式路径。
>
> **为什么现在做**：90° 双目受几何限制（对称 90° 需要 B≈2·D，现有 B=124 mm
> 只能对应 D≈62 mm）当前做不出真机证据；而单目标定的**算法早就写好了**
> （`calib/stereo_calib.py:641 calibrateCameraExtended`），缺的只是
> **一个入口 + 一个消费方**。这条线是当下唯一不依赖硬件改造就能推进的主线。
>
> 依据：`docs/主线.md` §0、`docs/人工参与清单.md` §一.1、`docs/待办清单.md` B-08。

### 0.4 单目链路的真实状态（`mono_calib_gap.md`）

| 事实 | 证据 |
| ---- | ---- |
| 单目内参标定**算法已存在** | `calib/stereo_calib.py:641 calibrate_mono_points` → `cv2.calibrateCameraExtended`（`:659`） |
| 但它**不在对外契约里** | 未进 `calib/__init__.py` 的 `__all__`；全项目只有 `apps/calibrate_stereo.py:64` 一处 import |
| 没有任何**单目入口** | 无 `apps/calibrate_mono.py` |
| 没有任何**消费方** | `CameraModel`（`sphere_tracker/geometry.py:356-377`）**连畸变数组都不收**；`grep undistort sphere_tracker/` → **0 次调用** |
| 所谓的"单目标定"其实是**单点焦距估计** | `apps/tools/calibrate_focal.py:105` 用 `f = r·Z/(D/2)` 反算一个数，主点直接等于图像中心，不产生畸变系数 |
| 没有标定也照样跑，**且不提示** | `apps/run_realtime.py` 无任何标定依赖；无 `fx` 时用 `hfov_deg=60°` 猜（`geometry.py:370-373`） |
| 单目误差**没有任何量化口径** | 唯一数字是开题报告里的"0.31%"，口径是 22 cm 球 / 3.7–4.4 m **合成真值**，不能外推到 40 mm 球 |

**敏感度（解析传播，`Z = f·D/(2r)`，`dZ/Z = df/f + dD/D − dr/r`）**：

| 扰动 | Z=300 mm | Z=600 mm | Z=1000 mm |
| ---- | -------- | -------- | --------- |
| `dr = 0.2 px` | 0.54 mm | 2.16 mm | 6.01 mm |
| `dD = 0.2 mm`（0.5%） | 1.50 mm | 3.00 mm | 5.00 mm |
| **`df/f = 1%`** | 3.00 mm | **6.00 mm** | 10.00 mm |
| RSS 合成 | 3.44 mm | **7.05 mm** | 12.69 mm |

**读法（这条决定了本轮的优先级）**：在 600 mm 处，**焦距误差是最大项**（6.0 mm / 1%），
半径项只有 2.16 mm。所以"把 `f` 标对"比"把圆检测精修到 0.1 px"值钱约 5 倍。
`calibrate_focal.py` 还会让球径误差**计入两次**（先反算 f，再用 f 正算 Z），
这是改用棋盘内参标定的第一个量化理由。

### 0.5 顺带发现的三个**现存缺陷**（与本轮重构无关，但必须同时修）

不是"界面不好看"，是**行为错了**。都已由人类视角走查 + 源码核对双向确认。

| # | 缺陷 | 证据 | 为什么必须现在修 |
| - | ---- | ---- | ---------------- |
| D1 | **打开界面 200 ms 后自动真开相机**（"相机探测"），无任何提示 | `apps/gui_main.py:479 self.after(200, self._refresh_cameras)` → `_run([PY, cameras.py probe])`；走查日志：DSHOW 真出图 2 台、耗时 23.9 s，界面无提示 | 只"看一眼界面"也会亮摄像头灯 + 白等 24 s。**这是隐私观感问题，也是每次启动的固定成本** |
| D2 | **界面印着未渲染的 Markdown 星号**，至少 5 处 | 截图可见：`**内角点**数`、`**卡住时用它中断**`、`**真出图 2 台**`、`**最多 2 台**`、`**显式指定**` | 说明文案是"给开发者看的注释"直接漏到了用户脸上；`_hint()` 不做 Markdown 渲染 |
| D3 | **「宽松预设」有 2 项被面板值顶回，界面与日志却都说"6 条"** | 预设先写 `stationary_max_px=10 / min_sharpness=400`（`apps/calibrate_stereo.py:1182-1190`），GUI 面板的显式值（`3`/`800`，`apps/gui_main.py:1036/1039`）**后写覆盖**（`:1196-1199`）；`:1191` 仍打印"都放松了"；勾选框文案写"一次放松 **6** 条门限"（`apps/gui_main.py:1046`） | 用户以为放宽了收图门限，实际最影响收图成功率的两项没动，**并在日志里说了反话** |
| D4 | **点工作台②/③会把第 2 步的检测方法改成 `specular`**，不确认 | `apps/gui_main.py:1801-1802`（②点选球心）、`:1810-1811`（③跑离线双目）直接 `self.method.set("specular")`；只有一行日志 | 用户回到第 2 步会发现"检测方法"自己变了。有日志 ≠ 有交代 —— **改的是用户填过的输入框** |
| D5 | **界面上「清晰度下限 800」是一个永不触发的闸门** | `calib/capture.py:101-104` 的注释自己写着："它在任何被检出的帧上都远低于实际值（SB 检出下限远高于此），**所以不构成有效闸门**"；真正生效的是 `min_focus_ratio` | 界面暴露了一个**看起来能调、调了没用**的参数。这比"参数太多"更糟：它会让人误以为问题已经解决 |

> D3 的口径必须**按环节**说，两个数字不可合并、也不可互相否定（两位审计者互相更正过一轮）：
>
> | 环节 | 失效项 | 证据 |
> | ---- | ------ | ---- |
> | **收图**（`capture_board.py`，手持拍的那一刻） | **2 / 6**：停稳 `10→3`、清晰度 `400→800` 都被面板值顶回 | `capture_board.py:493` 对 live 相机**无条件**把 `stationary_px` 交给 `judge_capture`（`:110-111`），**该文件里没有 `require_stationary` 开关** |
> | **标定**（`calibrate_stereo.py --left-dir/--right-dir`） | **1 / 6**，且只有清晰度有实际后果 | `calibrate_stereo.py:1178-1180 require_stationary=(src.kind != "dir")`，消费点 `calib/capture.py:428` —— 目录源下"板静止"根本不参与判定 |
>
> 所以：谁拿"目录源只有 1 项"去说"停稳其实无所谓"，就是把两个环节混了。
> 另 4 项（`min_area_ratio` / `min_margin_px` / `min_brightness` / `max_brightness`）**确实生效**。
>
> **修法（分两步，先止血）**：
> 1. **现在**：只改 **2 处字符串** —— `apps/calibrate_stereo.py:1191` 的日志、`apps/gui_main.py:1045` 的勾选框文案。
>    条数**由代码算、不写死**，且只列真正被改到的项。零行为风险。
> 2. **参数面板重写时**：勾上"放宽"就把那两格置灰。**不单独在旧面板里做** ——
>    那会留下"预填 / 清空 / 置灰"三套规则并存。
>
> `apps/calibrate_mono.py` **不做 `--relaxed`**：`--dir` 天生是目录源语境，
> 即使将来加宽松也只剩 `min_sharpness` 一项有意义；单目这边"宽松"不该做成模式，
> 最多是一个清晰度下限参数。

### 0.6 四个"控件数"口径不同，**不许互引**

本轮两位审计者给出的静态构造点数量**互相不一致**（158 vs 111），
原因是"数什么"不同（是否含 Label、是否含容器、是否含 Radio）。
**本计划不引用这两个数字**，只用两个运行时实测值，且都写明怎么量的：

| 数字 | 口径 | 怎么复现 |
| ---- | ---- | -------- |
| **199** | 实例化后递归 `winfo_children()` 的全部 widget（含容器） | `outputs/agent_gui_audit/measure_page.py` |
| **22** | **首屏能点**的东西：11 按钮 / 3 下拉 / 5 输入 / 3 单选 | 截图点数（`page01_first_screen.png`） |

本计划的所有阈值（首屏输入 ≤8、按钮 ≤5）按**第二种口径**定义 —— 因为那才是用户面对的。
以后任何人报控件数，必须同时报"口径 + 复现方式"，否则不许进文档
（理由见 `AGENTS.md` §6 那条"同一件事写两遍状态必然矛盾"，这次轮到计数）。

### 0.7 诊断信息的位置错了

走查记录里有一条值得单独钉住：**日志是唯一的诊断入口，但第一次用的人读不懂** ——
里面是 `--backend dshow|msmf`、`argv`、`exit code` 这种开发者语法。

→ 契约：**底部状态条说人话 + 给下一步**（"相机探测失败：DSHOW 下 2 台里 1 台没出图；
试试拔插 USB 或点『相机设备管理』"），**原始日志归 `ConsoleWindow`**。
这是全局 §四"反馈引导行动"的直接落地，不是锦上添花。

## 2. 设计契约（先定职能，再写代码 · 全局 §10）

### 2.1 三个模式 = 三条链路，不是三套皮肤

| | `mono` 单目 | `parallel` 平行双目 | `angled` 大角度双目 |
| - | ----------- | ------------------- | ------------------- |
| 深度来源 | 球径先验 `Z=f·D/(2r)` | 视差（校正后 y 差/水平差） | 视差（原始像素 + 三角测量） |
| 标定产物 | `config/mono_calibration.json`（K,D） | `config/stereo_calibration.{json,npz}` | 同左，`stereo_mode=angled` |
| 标定方法 | `calibrateCamera`（单路） | `stereoCalibrate` + `stereoRectify`（FOV 裁剪） | `stereoCalibrate`（跳过 FOV）/**chain**（无共视） |
| 去畸变口径 | `undistortPoints(..., P=K)` | 整帧 `initUndistortRectifyMap` + `remap` | `undistortPoints`（`angled_geometry` 内部已做） |
| 精度量级 @0.6 m | ±7 mm（RSS） | ±0.35 mm（仅半径项） | 同 parallel 量级 |
| 适用条件 | 一台相机；球径已知且准 | 光轴近平行（B ≪ D） | B 能拉到 40–60° 及以上 |

> ⚠️ **不许把三种模式实现成"同一个 `stereoCalibrate` 加个 if"**。
> 这正是 2026-10-24 那次被判 FAIL 的形状（`AGENTS.md` §11.7 起因段）。
> 每个模式的第 2 步**必须调用它自己的方法**，且窗口上写明该方法的**前提**。

### 2.2 窗口拓扑（5 类窗口，两类关系）

```
apps/gui_main.py  (≤150 行，只做引导)
  └ App(Tk root，不显示内容，只持有 AppState + TaskRunner)
      ├ HubWindow          门厅：三张模式卡 + 工具条            ← 唯一入口
      │
      ├ MonoWindow         mono：① 内参 ② 球与量程 ③ 开始
      ├ StereoWindow(parallel)  ① 装置检查 ② 标定 ③ 采集 ④ 分析
      ├ StereoWindow(angled)    ① 装置检查 ② 标定 ③ 采集 ④ 分析
      │
      ├ BenchWindow        会话工作台（多会话列表 + ①–⑤）      ← 单例，两处可进
      └ ConsoleWindow      日志与任务（任务表 + 日志）          ← 单例，随时可开
```

**只有两种窗口关系**：

1. **门厅 → 模式窗**（唯一入口；模式窗标题带模式名，关闭即回门厅）；
2. **任意窗 → 控制台**（底部状态条的"查看日志"按钮）。

**禁止**：模式窗之间互相跳；任何窗口里出现"模式"下拉框；任何一步需要用户
"自己记住一个路径再去另一个窗口粘贴"。

### 3.2 `calib/mono_calib.py`（新，库）

```python
@dataclass(frozen=True)
class MonoCalib:
    fx, fy, cx, cy: float
    k1, k2, p1, p2, k3: float
    rms_px: float
    image_size: tuple[int, int]
```

**质量判定（必须有，否则又是一次"RMS 好看就通过"）**：

| 判定 | 阈值 | 为什么 |
| ---- | ---- | ------ |
| `rms_px` | ≤ 0.5 px | 内参标定正常水平；>1 px 说明图糊或角点错 |
| 有效视角数 | ≥ 8 | 少于 8 个姿态时 `fy`/畸变不可辨（**报错，不降级**） |
| 姿态覆盖 | 板的中心必须落在 5 个区域里的 ≥4 个 | 全挤在画面中央会让畸变系数失真 |
| 板占比 | 每张 `area_ratio` ≥ 3%（复用 `detect_board` 已有指标） | 太小 = 角点定位不准 |
| `focus` | 每张 ≥ 组中位数（复用相对判据） | 已在 `calib/board.py` 实现，不重写 |

**不做的**：不写 `npz`（单目没有矩阵需要二进制，JSON 足够）；

### 3.4 接线（让标定真的被用上，否则只是又一个孤岛）

| 文件 | 改什么 | 为什么必须 |
| ---- | ------ | ---------- |
| `sphere_tracker/geometry.py` `CameraModel` | 加可选 `dist: tuple` 与 `undistort_points()`；`calibrated` 区分"有 fx"与"有畸变" | 现在**连畸变数组都不收**，标定无处可去 |
| `sphere_tracker/config.py` `CameraConfig` | 加 `k1,k2,p1,p2,k3`（默认 0 = 不去畸变，保持现有行为）+ `calibration_path` | 参数同源，不再第二份清单 |
| `sphere_tracker/pipeline.py` `_ensure_camera` | 把 `dist` 传进 `CameraModel`；检测后对**球心与圆的 4 个极值点**去畸变，用去畸变后的平均半径 | 只对球心去畸变会留下半径的尺度误差（广角边缘可达数 %） |
| `apps/run_realtime.py` | 启动打印内参**三态**：`已标定 fx=…` / `未标定（hfov 估算，±x%）` / `手动 --focal`；默认读 `config/mono_calibration.json` | 消灭"没有标定也照样跑、且不提示"这个静默失效点 |
| `apps/gui_main.py` 里那行文案 | `焦距fx(留空自动)` → `焦距 fx（手动覆盖，留空用标定值）` | "留空自动"会让用户以为标定过；实际是 hfov 猜的 |
| `apps/tools/calibrate_focal.py` | docstring 与输出加一句"这是**单点焦距估计**，不是内参标定；球径误差会并入 fx 再乘一次" | 防止它继续被当成"标定"用 |
| `run.bat` | 加 `mono` 参数（**不加第四个根脚本**，§3 规则 5） | 唯一入口原则 |

**去畸变口径的裁决（Leader 决定，写进契约）**：用**点去畸变**
`cv2.undistortPoints(..., P=K)`，与 `calib/params.py:188`、`stereo/angled_geometry`
已经建立的约定一致；**不做整帧 `remap`**（会改图像尺寸语义，牵连
`viz` 叠加、`annotated.mp4`、所有像素坐标）。

**半径怎么取（这里有个坑，已定退路）**：`sphere_tracker/types.py:28-40` 的 `Detection`
只有 `x/y/radius/score/method` + 可选 `contour/mask`，**没有"圆上 4 个极值点"这个字段**。
所以按检测器分三档，**不许静默降级**：

| 情形 | 取法 | 标注 |
| ---- | ---- | ---- |
| `contour` 存在（`color` 检测器） | 从轮廓取 `argmin/argmax` 得到**真极值点** → 去畸变 → 重算平均半径 | `radius_source="contour"` |
| `contour is None`（`hough` / `specular`） | **在合成圆上采 16 点** → 去畸变 → 拟合圆取平均半径 | `radius_source="synthetic16"`，日志与 HUD 标"半径由合成圆估，边缘可信度下降" |
| `Detection` 缺 `radius` | 不估深度，HUD 显示"无半径，无深度" | 不做静默兜底 |

**为什么选"退化 + 标注"而不是"报错"**：报错会让 `hough`/`specular` 在单目模式下
**直接不可用**，把"精度略降"变成"功能不可用"，代价不对等（`AGENTS.md` §9 那条
"代价不对称，宁可报错让人确认"是针对**静默用错相机**，不是针对精度降级）。
但**必须可观测**：`radius_source` 要进 `Detection`，HUD 与日志都要说，
否则就是又一个"静默失效"。

**可信区（与 §1 P6 配套）**：|u−cx| > 0.5·(w/2) 时，球的投影已是椭圆，
`Z=f·D/(2r)` 的近似误差上升 —— HUD 标黄，并在报告里注明"该点在可信区外"。
这是**限定条件**，不是把误差藏起来。

**合成点法会引入多少误差（量级说明，供实施时验证）**：4 个合成点在去畸变后不再共圆，
误差与"该处的去畸变位移"同阶；60° FOV、`r=55 px`、画面边缘处位移可达 2–3 px。
→ 所以 `contour` 路径优先，`synthetic16` 只在没有轮廓时用，且必须标出来。

### 3.5 `tests/selftest_mono_calib.py`（新，第 25 个测试）

### 11.2 由此暴露的通则：界面会"盲启"子进程

A1 不是孤例。把新界面里所有 `tasks.start(...)` 过了一遍，**要求必填参数却没传**的有三处：

| 调用点 | 缺少 | 后果 |
| ------ | ---- | ---- |
| 门厅「3D 查看器」 | `view_3d.py` 的 `source` | `exit 2`，静默 |
| 双目第 ④ 步「打开 3D 查看器」 | 同上 | 同上 |
| 单目第 ③ 步「离线视频」 | `run_video.py` 的 `path` | `exit 2`，静默 |

**通则（写进实现契约）**：

1. **任何 `tasks.start()` 之前，必须先校验该 app 的必需参数**；缺参数就**不启动**，
   而是把"还缺什么、去哪儿填"写进状态条。
2. **TaskRunner 增加"早退无输出"检测**：启动后 N 秒内以非 0 退出、且 stdout 一个字都没有时，
   取 stderr 首行报到 `on_log` 与状态条。理由：盲启只是当前这三处，
   但**下一次新增调用点还会犯**；机制层的兜底比逐点修补值钱。
3. 判据可脚本化：`selftest_gui_budget` 增一节，AST 扫描 `_gui_*.py` 里每个
   `tasks.start([...])` 的字面量 argv，与一张"app → 必需参数"表对照，缺一条即红。
