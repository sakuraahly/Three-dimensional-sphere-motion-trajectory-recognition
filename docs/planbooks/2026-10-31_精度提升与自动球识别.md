## 0. 前提清单（范式审计，硬条款）

| #   | 隐含前提                             | 还成立吗       | 处理                                                                                                                                             |
| --- | ------------------------------------ | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| P1  | 「单目只能逐帧用 `Z=f·D/(2r)` 测深」 | ⚠️ 部分         | 逐帧公式没错；但**绝对尺度**与**相对运动**要分开谈。相对运动精度已经不错（实测 CV 2.7%）；绝对尺度取决于 `D` 与 `r` 的**系统偏差**，不是公式问题 |
| P2  | 「半径必须从边缘（梯度）量」         | ❌ 镜面球不成立 | `B-130`：整圈仅 25%~35% 有梯度，被内部反射（r≈28）压过。镜面球的半径只能来自**尺度可信的框**或人工点选。**不要再去扫一圈找最强圆**               |
| P3  | 「高光是左右视图的共同对应点」       | ❌ 不成立       | `B-132`：左右高光落在球面不同位置，直追高光的圆心天然差 ≈6 px（本会话左 r=17.5 / 右 r=24.7）。双目必须用**轮廓圆心**                             |
| P4  | 「标定精度决定三维精度」             | ❌ 本机不成立   | 标定极线 eps 0.584 px 尚可；瓶颈在**对应点口径**与**录制期几何漂移**（`B-131` 实测左右圆心 y 差 11~12 px，是标定自报 0.56 px 的 20 倍）          |
| P5  | 「抖动下降 = 更准」                  | ❌ 不成立       | M4 的教训：常速度 Kalman 把真加速度削平，抖动降 86% 而 RMSE 1781 mm。**任何平滑/滤波类改动都必须带真值对裁**                                     |
| P6  | 「自动检测 = 更准」                  | ❌ 不成立       | 自训 YOLO 圆心误差中位 **4.29 px**，而 color 亚像素半径能到 **0.06 px**。自动化的价值是**免点选 / 能初始化**；精度仍要靠**框内几何细化**         |
| P7  | 「自动检测与精度互不相干」           | ⚠️ 会打架       | 一旦把 yolo 设为默认，它会**替换**当前精度更高的 color 路径。验收必须同时看「能不能自动初始化」**与**「精度没退」                                |
| P8  | 「补数据不必麻烦用户」               | ❌ 不成立       | `B-129` 要 5~10 段**同场景单目**录像、`B-113` 要「已知距离 + 卡尺」的采集 —— 都是物理采集，不可代劳                                              |

## 3. 三条工作线

### 3.1 单目精度（瓶颈 = 半径 r 的**量测**，不是焦距也不是公式）

| 编号 | 做法                                                                                                                          | 对应待办 | 依赖                     |
| ---- | ----------------------------------------------------------------------------------------------------------------------------- | -------- | ------------------------ |
| S1a  | **消掉 specular 半径那 13.6% 系统偏差**：已知距离 + 卡尺采一组，量出 `r_meas/r_true` 随半径/曝光/模糊的变化，做成**实测校正** | `B-113`  | **需用户采集**           |
| S1b  | **会话级自证球径**：`session.json` 记 `ball_diameter_mm` + 检测器口径 + 半径来源，让「这段按什么直径算的」可自证              | `B-114`  | 无                       |
| S1c  | **统一「单目的 Z」的两个定义**：给 `CameraConfig` 加 `refine_radius`，由 pipeline 统一点做细化，删 `run_video` 的重复实现     | `B-126`  | 会动双目路径，需单独验证 |
| S1d  | **跟踪护栏进库 + 收紧门限**：把 `B-120` 的 `seed_r×[0.75,1.35]` + 逐帧 8% 从 app 层提到库层，与 `track.py` 太松的 0.35 统一   | （新）   | 无                       |
| S1e  | **半径也进平滑**：现在只平滑 Z；把 r 先平滑再进 `Z=fD/(2r)`，降抖动（**判据必须对真值**，见 P5）                              | 无       | 无                       |

> **不做的**：再试"扫一圈找最强圆"（`B-130` 已证伪）；把 1.157 当魔数乘进去
> （那会把可复核的实测值变成看不见的魔数）。

### 3.2 双目（平行）精度（瓶颈 = **对应点口径** + **录制期几何漂移**，不是标定算法）

| 编号 | 做法                                                                                                                                                                                       | 对应待办 | 依赖                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- | ---------------------- |
| S2a  | **对应点改轮廓圆心**：双目的 specular 不再追高光，改用轮廓/边缘拟合圆心（或「轮廓级配对再三角化」）。**单项收益最大**                                                                      | `B-132`  | 无                     |
| S2b  | **配对门限自适应**：`max_epipolar_px` 由硬编码 2.5 改为 `k × 标定极线 RMS`；开启 `require_radius_ratio`（**仅在左右同口径时**）；加视差→Z 合理性检查                                       | （新）   | 与 S2a 同批            |
| S2c  | **几何守卫**（原写"录前拍一张球"，**落地改为**"跑满 N 对先判一次"，见 §9）：量校正后左右圆心 y 差；超 `GEOM_SUSPECT_PX=3.0` 就**明确报错 + 指下一步**，把 `B-131` 的「整段跑完才发现」提前 | `B-131`  | 无（**不需要世界系**） |
| S2d  | **同步边界写清**：实时相机不支持帧偏移（`PairSource` 明确拒绝）→ 这是平行双目实时链路的已知边界，文档化，不假装解决                                                                        | 无       | 无                     |
| S2e  | **标准重拍标定**（eps 0.584 → 0.3 px，报告建议）                                                                                                                                           | 无       | 最后；收益低于 S2a–S2c |

> **判断依据**：`B-131` 那段会话，标定自报 0.56 px 而实测 y 差 11~12 px ——
> 说明"标定精度"根本不是当前的限制项；S2a/S2c 才是。

### 3.3 自动球识别（瓶颈 = **数据分布**，不是模型或算法）

分四层，逐层可独立验收：

| 层  | 内容                                                                                                              | 对应待办          | 现状                               |
| --- | ----------------------------------------------------------------------------------------------------------------- | ----------------- | ---------------------------------- |
| L0  | **半自动（今天就能用）**：一次点选 → 自动跟完整段                                                                 | `B-122`           | 已可用（specular+CSRT 86.4%@15px） |
| L1  | **自动初始化**：阈值跟随 sidecar 的推荐值；补 5~10 段同场景单目重训（60 epoch / `imgsz=960`）                     | `B-128` / `B-129` | 需**用户采数据**                   |
| L2  | **免点选闭环**：YOLO 初始化 → 时序门控（连续 N 帧命中才建轨，防 `B-122` 的"锁到白衣服"）→ 轮廓/CSRT 跟 → 丢失回捕 | （新）            | 未做                               |
| L3  | **实时**：`run_realtime.py` 在有自训权重时自动选 yolo                                                             | 无                | 需改默认选择逻辑                   |

> **诚实边界（必须写进验收）**：即便 L2 做成，**镜面球的半径仍受 `B-130` 限制** ——
> 自动链路能给「位置」，给不了「可信半径」。所以镜面球半径要么来自双目，要么保留
> **一次**人工锚点。这不是没做完，是**物理边界**。若用户接受这个边界，L2 的目标
> 就从"零点击"改为"**一次点选后全程自动**"。

## 4. 验收与证伪实验

**通用口径**：任何改动都要在 [selftest_synthetic.py](../../tests/selftest_synthetic.py)
的合成真值上对裁；**不接受只报"抖动下降"**（P5）。

| 指标             | 口径                                        | 真值来源                   |
| ---------------- | ------------------------------------------- | -------------------------- |
| 半径相对误差     | `                                           | r_meas − r_true            | / r_true`                        | 合成真值 / 卡尺实测（S1a） |
| 单目深度相对误差 | `                                           | Z − Z_true                 | / Z_true`（**分绝对/相对两栏**） | 双目 `traj3d.csv` 同帧     |
| 双目极线残差分布 | 校正后左右圆心 y 差的 p50 / p95             | 标定 + 真机会话            |
| 零配对比率       | 每次录制「有检测但 0 配对」的帧占比         | 会话统计                   |
| 三维轨迹 RMSE    | 逐帧 3D 距离 RMSE vs 真值                   | 合成真值                   |
| 自动初始化成功率 | 从第 k 帧起无人工介入即锁定正确球的会话占比 | 真机会话（需人工核对一遍） |

**证伪实验（必须做，否则 PASS 无效）**：

1. **尺度**：把 `D` 或 `r` 故意乘 1.157（即"用魔数凑回去"），若抖动下降但
   `Z` 相对误差不变差 → 说明判据量错了对象；
2. **对应点**：合成"左右高光错位 6 px"的装置，证明「用高光圆心配对」会给
   出**好看但无意义**的三角测量（这是 S2a 存在的理由）；
3. **门限**：构造 y 差 1 / 3 / 5 / 12 px 的合成序列，S2b/S2c 的判定必须随门限**单调分档**。

## 9. 落地记录（S2a / S2c，2026-10-31）

**范围**：只做 S2a + S2c（用户批准的起手两项）。S2b / S1d / S1e 仍未动。

### S2a 双目圆心改「轮廓圆心」

| 落点                                   | 内容                                                                                                                                                                              |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sphere_tracker/geometry.py`           | 新增 `refine_circle_subpixel_checked()`（末位多一个「是否真的细化成功」）；原 `refine_circle_subpixel()` 改为薄包装，**签名与「失败原样返回」约定不变**（`docs/API.md` 引用了它） |
| `sphere_tracker/config.py`             | `SpecularConfig` 新增 `refine_center=True` / `refine_center_search_px=0`（0=自动）/ `refine_center_min_search_px=2.5` / `refine_center_max_search_px=8.0`                         |
| `sphere_tracker/detectors/specular.py` | 新增 `_refine_center()`；seed 与 track 两个出口把圆心换成轮廓圆心，`Detection.extra["center_source"]` 记 `contour`/`box`、`parts["center_shift_px"]` 记位移                       |

**三条口径**（都是有意选择，不是实现细节）：

1. **只取圆心、不取半径** —— `B-130` 已证伪「从边缘量镜面球半径」（整圈只有 25%~35% 有梯度）；
   半径仍取 CSRT 框（尺度可信），避免把「量不准的半径」换成一个看起来更准的值。
2. **门控仍用框中心** —— 跳变/模板/静止门控是「CSRT 有没有跟丢」的判据；混入口径不同的
   轮廓圆心会让门限无法解释。轮廓圆心**只在出口处替换**。
3. **搜索窗自适应** `clip(0.25×radius, 2.5, 8.0)` —— 左右框半径实测差 40%（左 17.5 / 右 24.7），
   写死 ±2.5 px 够不到右侧那 20 px 的真轮廓；上限 8 px 是为了不把球内的小半径强反射吸进来。
   细化失败或位移 > 0.5×半径时**原样退回框中心**（只改善、不劣化）。

### S2c 几何守卫（落地口径与原文不同，理由在此）

原文写「录前拍一张球的图」。**落地改成**：`apps/run_stereo_video.py` 加 `--geometry-guard N`
（默认 30，`0`=关），主循环里跑满 N 对就判一次；判为可疑则打印
`StereoReconstructor.geometry_failure_message()` 并 `return 2`（**拒绝出数**）。

为什么不放在库层默认、也不做「录前拍一张」：`mono_vs_stereo.py` / `profile_stages.py` 会在

### 10.1 它到底解决什么

镜面球的像素半径**不能**从边缘量（`B-130`：整圈只有 25%~35% 有梯度），所以
`MatchConfig.require_radius_ratio` 那种"左右应该一样粗"的门一直默认关着 ——
它假设两路焦距相同，而实测本机原始焦距比是 1.015（另一台装置差更多），
硬按"比值≈1"会把**真对应点也拒掉**。

锚点把"该差多少"**量出来**：`r_L/r_R = f_L/f_R`，**与距离无关**
（`r = f·D/(2Z)`，两路 Z 相同）。于是门变成"每一对相对**自己的期望比**判"，
球飞近飞远都不会误杀。

### 10.3 三条口径（都是有意的）

1. **比比值，不比绝对半径**。绝对半径依赖 Z，球一靠近就会被判"半径不对"而整帧丢掉；
   比值与距离无关，一次锚点管整段。
2. **焦距取原始 `K`，不取校正后 `P`**。检测器给的半径是**原始像素**；而立体校正会把两路
   重投影到同一个虚拟相机，``P1[0,0] == P2[0,0]`` **恒成立**（本机实测 K 比 1.015、P 比 1.000）
   —— 用 P 等于把要量的差异**抹成 1**，门就退化成"左右一样粗"。这一条第一版写反了，
   是量了真实标定才发现的。
3. **锚点自身也要被审**：人工点的是真对应点，它的校正后 y 差就是"这套标定在这一点准不准"
   的直接测量。超过 `GEOM_SUSPECT_PX`（3 px）→ **拒绝启用并退出码 2**，不是警告：
   用错锚点会让后面每一帧的配对都被静默筛一遍。

### 10.4 已验 / 未验

- **已验（合成真值，`test_radius_anchor`）**：Z=1.000（真值 1.0）、两路期望半径 20/28 px
  （焦距差 40%）、期望比值 0.714 = f_L/f_R；
  **并且证明了它真的改变选择** —— 故意让"半径离谱但极线更准"的候选存在时，
  不开门它会被选中（这就是要修的错），开门选中正确的那个。
  反向自证：把门短路后该断言报 `[不达标]`，还原后全绿。
- **已验（真机会话 `20261019-200855`）**：`--anchor-gate on` 读出 `source=gui_click` 的种子、
  锚点 Z=0.325 m、两路期望半径 48.5/48.5 px（该装置焦距几乎相同）、锚点 y 差 2.14 px（< 3，放行）。
  开/关跑 20 对结果一致 —— 因为该会话每帧只有一个候选，**门没有可拒的对象**，
  这正是"它只在多候选时生效"的预期表现，不能拿它当"有效"的证据。
- **未验**：真机多候选场景下的配对率/精度 A/B（需要一段有干扰物的录像）；
  `--anchor-diameter-mm` 用错球径时的影响量级（比值不受影响、只有绝对半径那条线受影响，
  但没量化）。
- **边界**：`--auto-seed` 的种子（`source=auto-yolo`）**被明确拒绝**当锚点 ——
  它半径来自 YOLO 框、不可信；程序会直接说清原因而不是静默降级。
