# 世界系「每次快速确认」设计方案（2026-10-31）

> 状态：**设计阶段，不改代码**。本文件只回答一个问题：
> 世界系拍过一次之后，**每次**怎么快速确认它还对 —— 像双目标定有 `verify_stereo` 那样。
>
> 触发：用户问「如果你要这样做世界系的话,有没有每次都快速确认世界位置的方法,
> 比如像现在一样有专门的标定流程」。用户裁决：**先只写设计方案，不写代码**。

---

## 0. 前提清单（范式审计，`AGENTS.md` §11.7 硬条款）

本方案沿用的每一条隐含前提，逐条回答「在『每次复核』这个新场景下还成立吗」：

| #   | 隐含前提                            | 还成立吗           | 处理                                                                                                                                                                                                                |
| --- | ----------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1  | 世界系 = 棋盘平放所在的那个平面     | ✅                  | 不变                                                                                                                                                                                                                |
| P2  | `T_world_cam` 与"棋盘起点"无关      | ❌ **不成立**       | `from_board` 用 `_left_bottom_order()` 把原点钉在"画面里最左下"的内角点；**板在画面里看起来转 180°，原点就跳一个 180°** —— 直接比 `T_world_cam` 矩阵会**误报**"动了"。判据必须换成**与起点无关的物理量**（见 §3.2） |
| P3  | 单帧 PnP 的 `rmse` 能说明世界系质量 | ❌ 只在窄意义上成立 | `MAX_BOARD_RMSE_PX` 只反映"拟合得好不好"，**不反映板平不平**（`calib/world_frame.py` 文档串已警告）。所以复核只能说"与存档一致"，**不能说"世界系正确"**                                                             |
| P4  | 一张图的位姿精度足够当"确认"        | ⚠️ 待量化           | 板在画面里太远/太斜时，`Δt` 噪声可达厘米级。**门限不能比噪声底还细**，须先实测（§5.3）                                                                                                                              |
| P5  | "复核通过"⇒"输出坐标正确"           | ❌ **不成立**       | 还有 `B-134`（有世界系时 `traj3d.json` 的 `coordinate_system="world"` 但 `samples` 仍是相机系）——**标签对、数据错**。复核管不了它，别把两者混为一谈                                                                 |
| P6  | 复核不必动会话契约                  | ✅（仅 A 方案成立） | A 方案只读一张图 + 存档，不改任何契约；B 方案要改会话契约                                                                                                                                                           |

## 1. 现状（引证，避免凭记忆）

| 支撑       | 位置                                                                 | 事实                                                                                                                                                                  |
| ---------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 数据结构   | [calib/world_frame.py](../../calib/world_frame.py)                   | `WorldFrame`：`T_world_cam` 4x4，`p_world = T_world_cam @ p_cam`；`load()` 严格校验（4x4 / 有限 / 末行 / 正交 / `det>0`），**任何一条不过都抛错，绝不回退成单位矩阵** |
| 一次性设定 | 同上 `from_board()`                                                  | `detect_board` → `solvePnP(K1,D1)` → `T_cam_board` → 取逆。检测不全或 `rmse > MAX_BOARD_RMSE_PX`（=2.0 px）一律抛错，**"不给凑合能用的世界系"**                       |
| 工具入口   | [apps/tools/set_world_frame.py](../../apps/tools/set_world_frame.py) | `--image / --board-cols / --board-rows / --board-square / --rig / --out / --note / --ground-axis {z,-z} / --dry-run`；退出码 0/1/2                                    |
| 消费方     | [apps/run_stereo_video.py](../../apps/run_stereo_video.py)           | `--world-frame`（默认 `config/world_frame.json`）：有且合法时写 `derived/traj3d_world.csv`、把 `traj3d.json` 的 `coordinate_system` 设为 `world`、写 `world_frame` 块 |
| 对称物     | [apps/verify_stereo.py](../../apps/verify_stereo.py)                 | 「复检双目标定：装置有没有被碰动？」判据是**相对比较**（与标定时比），明确"绝对阈值没有刻度"                                                                          |

**缺口（本设计要补的）**：

1. **`config/world_frame.json` 目前不存在**（仓库里没有），世界系从未真正落盘过；
2. **没有任何"复核世界系"的入口** —— `set_world_frame` 只做一次，之后无人确认；
3. **没有溯源** —— 不知道某个会话用的是哪一份世界系（对比：双目标定会快照进会话 `calib/`）。

**后果（为什么值得做）**：相机被碰一下，`config/world_frame.json` **静默失效**，
之后所有标 `coordinate_system="world"` 的输出全是错的，而**画面和日志都看不出来** ——
与 `B-134`、与 `AGENTS.md` §9 那条"不做按名字自动兜底"同型：**静默的错数比明确的失败贵得多**。

## 2. 目标 / 非目标

**目标**：给"世界系还对不对"一个**秒级**的、有退出码的、可被 `启动程序.bat` 调用的确认手段。

**非目标**：不重定义世界系；不改坐标系；不修 `B-134`；不做实时链路内校验。

---

## 3. 方案

### 3.1 三个候选

| 方案                | 做法                                                                           | 代价                      | 收益                         |
| ------------------- | ------------------------------------------------------------------------------ | ------------------------- | ---------------------------- |
| **A. 复核子命令**   | 拍一张左相机棋盘图 → `from_board` → 与存档比 → PASS/FAIL                       | 小：一个新函数 + 一个开关 | 秒级确认"相机相对地面动没动" |
| **B. 会话内世界系** | 世界系从**会话自身**某帧现算；或把 `world_frame.json` **快照进会话** + 记 hash | 中：改数据标准 / 会话契约 | 消除"存档过期"，自带溯源     |
| **C. 两者都做**     | A 先落地，B 随后                                                               | 大                        | 兼得                         |

### 3.2 A 的关键设计点：比"物理量"，不比矩阵（P2 的直接后果）

**不能**直接比 `T_world_cam` 矩阵 —— 板在画面里看起来转 180° 时，原点约定
（`_left_bottom_order`）会跳，矩阵差一个绕 Z 的 180°，**物理上没动却报大 Δ**。

比这三个与起点无关（或已被 `_left_bottom_order` 统一到同一物理角点）的量：

1. **反投影残差**：把本次检测到的角点，用**存档的 T** 投到本次图上，pixel RMS
   —— "存档的世界系能不能解释这张新图"；
2. **板中心在相机系的平移差** `Δt`（mm）：与起点无关；
3. **地面法向在相机系的夹角差** `ΔR`（deg）：与起点无关。

> 这条判据的可证伪性见 §5.2 —— 它是 A 方案能否成立的关键。

### 3.3 落点二选一（计数代价不同）

| 落点                                                         | 说明                        | 代价                                                                                                         |
| ------------------------------------------------------------ | --------------------------- | ------------------------------------------------------------------------------------------------------------ |
| ① 新文件（拟命名 check_world_frame.py，放 `apps/tools/` 下） | 与 `verify_stereo` 形态一致 | **`apps/tools/*.py` 30→31、`AGENTS.md` §3「相机/标定」11→12 必须同步**，否则 `check_standards` 的 B 类直接红 |
| ② 给 `set_world_frame.py` 加 `--verify`                      | "做一次 / 查一次"同一入口   | **零计数代价**；改动集中在一个已登记文件                                                                     |

**建议 ②**（理由：与"目录好看"无关，纯粹是避免为一次检查引入一次文档漂移；
`AGENTS.md` §9 已记过"搬家换 55 处引用"的教训）。

### 3.4 入口

```powershell
启动程序.bat worldset                        # 现有：棋盘平放，拍一张，落盘
启动程序.bat worldcheck --image board.png    # 新增：复核（映射到 --verify）
```

> `AGENTS.md` §3 规则 5：**不给根目录加第四个脚本**，"只做某一步"就给
> `启动程序.bat` 加参数。改完 `.bat` 必须复跑一次（§附：UTF-8 无 BOM + CRLF 两条硬约定）。

## 4. 门限（建议值，**必须由 §5.3 实测校准后才算数**）

| 量                              | 建议门限                 | 备注                                          |
| ------------------------------- | ------------------------ | --------------------------------------------- |
| 反投影 RMS（用存档 T 解释新图） | ≠ 判据主项，仅作交叉检查 | ——                                            |
| 平移 `Δt`                       | ≤ **5 mm**（可调）       | 待噪声底实测；板小/斜时应放宽                 |
| 旋转 `ΔR`                       | ≤ **0.5°**（可调）       | 同上                                          |
| 口径                            | **只做相对比较**         | 同 `verify_stereo` 的理由："绝对阈值没有刻度" |

退出码：`0` 一致 / `1` 不一致（打清差在哪、下一步怎么重拍）/ `2` 参数或输入错。

## 5. 验收与证伪实验（合成可跑，无需相机）

### 5.1 合成一致性

已知 `T_cam_board` → `projectPoints` → 加亚像素噪声 → `from_board` 复算 → `Δ` 应 ≈ 0。

### 5.2 反向自证（**能不能成立的命门**）

- **变异 1**：把板按"看起来转 180°"摆 → 证明"直接比矩阵"的判据会**误报**（Δ 巨大），
  而 §3.2 的物理量判据仍判 PASS；
- **变异 2**：把 `T` 平移 3 / 5 / 10 mm、旋转 0.3° / 0.5° / 1° → Δ 与判定应随门限**单调分档**。

> 与 `selftest_board_corner_order`、`AGENTS.md`「标定守卫该盯物理量而非 RMS」
> 是同一类教训：**判据盯错量，测试全绿也没用**。

### 5.3 门限的唯一依据

同一位置**重拍 5 次** → 看 `Δt / ΔR / 反投影` 的重复性（这是门限的唯一来源，
不是拍脑袋）。此步需真机 + 一块能平放的板。

## 6. 明确不做

- **不做**"自动重算世界系并静默覆盖存档" —— 等价于 §9 那条"不做按名字自动兜底"：
  省几十秒，赌**静默用错的世界系**，代价不对称，**宁可报错让人确认**；
- **不做**用球本身当世界系基准（球会动）；
- **不顺手改** `B-134`（标签 `world` 但 `samples` 是相机系）—— 独立缺陷，见 §0 P5；
- **不重定义** `T_world_cam` 的方向/坐标系（本轮）。
