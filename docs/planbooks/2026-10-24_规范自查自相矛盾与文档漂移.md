# 计划书：规范自查自相矛盾 + 文档/脚本计数漂移

- 日期：2026-10-24
- 角色：Leader（派发/集成/验收） + Executor A（检查器） + Executor B（入口文案） + Critic（独立验收）
- 依据：全局 `AGENTS.md` §八 / §九 / §十三 / §十四 / §十五

## 1. 要解决什么

`run.bat standards` 与 `apps/run_tests.py` 这两条"确定性链路"本身在漂移，
而且**检查器的输出自相矛盾**——它一边报告"23 处失效引用"，一边判定"全部通过"。
换句话说：**守漂移的工具自己漂了**，这比普通文档漂移更严重。

不做会怎样：以后所有"standards 通过"的结论都不可信，质量门形同虚设。

## 2. 已确认的问题（审计证据，只读复核过）

| # | 问题 | 证据 |
| - | ---- | ---- |
| P1 | `check_refs` 算出 `outside`（仓库外引用）却**从不进入 problems**，却计入"扫到 N 处失效引用" | `apps/tools/check_standards.py:247-259`、`:357-359` |
| P2 | `STC/...` 引用只在仓库内解析 → `..\STC\standards\` 里**真实存在**的文件被判失效（假阳性） | `check_standards.py:222-236`（只用 `ROOT/cand`）；`check_sources` 已用 `ROOT.parent` 解析（`:288-295`），两处口径不一致 |
| P3 | 白名单 `KNOWN_MENTIONS` 只增不减，无 vanished 检测 → 死条目永久豁免（`KNOWN_DRIFT` 有检测，`KNOWN_MENTIONS` 没有） | `check_standards.py:270-277` |
| P4 | `run.bat` 计数漂移："跳过两个慢测试"（实为 3 个）、"15 个全跑"（实为 23 个）、"十几秒"（实测 197.3 s） | `run.bat:211`、`:218`、`:221` |
| P5 | `apps/run_tests.py` 文档串与常量矛盾："默认 30 s"（实为 `DEFAULT_SLOW_THRESHOLD = 60.0`）、"全套 15 个 / 其余 13 个" | `apps/run_tests.py:22`、`:13`、`:69` |

**明确不做**（本轮范围外）：
- 不接"双目三角测量进实时主流程"（里程碑级改动，另开计划书）；
- 不改测试数量（23 个），不删测试；
- 不动 `AGENTS.md` 的规则条文（改规则要走 HITL）；
- 不重排目录。

## 3. 修法（方向，不写死实现）

- **P1/P2**：`STC/` 前缀的引用按 `ROOT.parent` 解析。存在 → 归入"仓库外（存在）"，**不计入失效**；不存在 → 计入 problems。这样"扫到的失效引用数"与"判定结果"口径一致。
- **P3**：对 `KNOWN_MENTIONS` 也做 vanished 检测，并**清掉当前所有死条目**（白名单只保留仍然命中的）。
- **P4/P5**：不把会漂的数字抄在两个地方。`AGENTS.md` 是计数的唯一来源（`sync_facts.py` 已守），`.bat` 与 `run_tests.py` 文档串改为不重复具体数字，阈值注释改成与常量一致（60 s）。

## 4. 验收标准（可复现）

1. `python apps/tools/check_standards.py` 退出码 0，且**输出内部一致**：
   凡被计为"失效"的条目必进入 problems；不为 0 时不得打印"全部通过"。
2. 该输出里**不再出现** `STC/...` 假阳性；`KNOWN_MENTIONS` 死条目 = 0。
3. `tests/selftest_doc_facts.py` 新增两条断言：①白名单无死条目；②`STC/` 引用按父目录解析。单跑通过。
4. `run.bat` 中"两个/15 个/十几秒"三处失真消失；`run_tests.py` 的阈值注释 = 60 s。
5. `run.bat test`（fast）全绿，测试数仍 23（不增不减）。
6. `git status` 干净，一个提交只装这一件事。

## 5. 风险与兜底

- `selftest_doc_facts.py` 直接调用 `check_standards`，改输出可能打破它 → **允许**同步调整该测试的断言，但**不允许**放宽断言或删除用例；Critic 专查这一条。
- 白名单批量删除有误删风险 → 删之前先由检查器自己算出"未命中集合"，只删集合内条目。
- 证据缺口：`run.bat` 的 `pause` 在非交互下挂死（审计时被 SIGTERM 打断、bat 层退出码丢失）——本轮**只记录不修**，因为改它会影响双击交互，需要单独评估。
