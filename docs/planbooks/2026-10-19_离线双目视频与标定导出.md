# 2026-10-19 · 离线双目视频轨迹 + 标定参数导出

> **背景**：目前没有外接相机。用户决定先做**离线**路线：
> 用标定好的双目装置**录制**小球运动视频，再离线算出三维轨迹（不做实时）。
> 用户会自己重新标定，所以本计划**不碰标定算法**，只消费 `config/stereo_calibration.*`。
>
> **已确认的需求**：
> - 只拍**一个球**（不做多球跟踪）；
> - 标定由用户自己重做，导出工具要能读**任意**一份标定文件；
> - 参数导出要 **JSON + YAML**，并加 **TOML** 作为备用格式；
> - 录像必须**无损**。

---

## 1. 要解决什么

一句话：**录好的左右两段视频 → 三维轨迹 CSV + 标注视频；同时把标定参数导出成外部工具能读的文件。**

现状（2026-10-19 实测）：

| 能力 | 现状 |
| ---- | ---- |
| 真机录制视频 | **没有**。`assets/videos/` 只有 README；`outputs/videos/` 只有 3 个合成视频 |
| 标定参数保存 | 有：`config/stereo_calibration.npz`（全矩阵）+ `.json`（质量报告） |
| 参数**导出** | 没有：JSON 不含矩阵，没有 YAML/TOML，没有分相机文件 |
| 离线双目轨迹 app | 没有：`StereoReconstructor` 只被 2 个测试调用；`run_video.py` 是单目 |
| 双路录制 | 没有：`run_realtime --record` 只录单路标注画面 |
| 视频同步偏移 CLI | 没有：`find_offset` 与 `PairSource(sync_offset=...)` 都在库里，app 不暴露 |

## 2. 方案（三块，P2 先落地）

### P2（本轮实现，无相机依赖）标定参数导出

- 新增 `calib/export.py`：`build_export(rig)` + `write_export(rig, out_dir, formats)`。
- 新增 `apps/tools/export_calibration.py`（CLI，薄壳）。
- 输出：
  - `left_camera.<ext>` / `right_camera.<ext>`：`K`、`D`、`image_size`、畸变模型；
  - `stereo_rig.<ext>`：`R`、`T`（米）、`E/F`、`R1/R2`、`P1/P2`、`Q`、基线、质量、标定来源；
  - `summary.txt`：人读摘要 + 文件清单。
- 格式：**JSON（stdlib）+ YAML（PyYAML，已装）+ TOML（自带最小序列化器）**。
- 坐标系与单位写进文件：三维点在校正后左相机系、米；`T` 的单位是米。

### P0（下一轮实现，无相机依赖）离线双目视频轨迹

- 新增 `apps/run_stereo_video.py`：
  - `--left-video/--right-video --calib --sync-offset N | --auto-sync`
  - `--method/--preset`（默认颜色预设是白球，拍橙球必须显式给 `orange_ball`）
  - `--csv`、`--out-video`、`--max-frames`
- 做法：`StereoRig.load` → 校验视频分辨率 == `rig.image_size` →
  `PairSource(video=..., sync_offset=...)` → 两路各跑 `SpherePipeline`（关掉单目三维）→
  `StereoReconstructor.update()` → CSV + 并排标注视频 + 汇总。
- `--auto-sync`：先用 `brightness_series` + `find_offset` 从两段视频求偏移，再重开 `PairSource`。
- 时间轴：`t = 帧号 / fps`（fps 从视频读，读不到就报错要求 `--fps`）。

### P1（等相机，暂不实现）双路无损录制

- 新增 `apps/record_stereo.py`：两路原始视频 + `session.json`（角色/身份、请求 vs 实际分辨率、
  实测 fps、帧数、标定路径 + SHA256、同步偏移）。
- **无损格式：FFV1 + MKV**（实测见 §4）。开录前做一次"写两帧→读回→逐位比较"的自检，
  不通过就**拒绝开录**，绝不静默退到有损编码。
- 等相机接上再实现，因为录制链路无法在沙箱验证。

## 4. 技术验证（本轮实测）

**无损编码**（640×480、6 帧随机噪声，逐位比较）：

| 编码 | 容器 | 6 帧大小 | 读回逐位一致 |
| ---- | ---- | -------- | ------------ |
| `FFV1` | `.avi` | 5 979 KB | ✅ |
| `FFV1` | `.mkv` | 5 974 KB | ✅ |
| `HFYU` | `.avi` | 8 502 KB | ✅ |
| `RAW ` | `.avi` | — | ❌ OpenCV 不支持该组合 |

→ **选 FFV1 + MKV**（无 AVI 2 GB 限制）；`HFYU` 作备选；`RAW` 不可用。

**TOML**：Python 3.14 的 `tomllib` **只读**，无 `tomli-w`；本项目自带一个最小序列化器，
支持标量/字符串/数字数组/嵌套表，已用 `tomllib.loads` 往返验证。

## 5. 明确不做

- 不做实时双目（P0/P2 都是离线）。
- 不做多球跟踪。
- 不改标定算法、不重标（用户自己做）。
- 不做三维平滑/预测（M4/M5 后续）。
- 不做世界坐标转换（先输出校正后左相机系）。
- 不新增第 24 个回归测试（导出用例并入 `selftest_calib_facts.py`）。

## 6. 风险

| 风险 | 对策 |
| ---- | ---- |
| 导出值与 NPZ 不一致 | 导出直接读同一个 `StereoRig`，测试逐项 `allclose` |
| TOML 不支持 `null` | 缺省字段**省略**，不写 `null`；数值数组保持同构 |
| PyYAML 未装 | 只在请求 YAML 时 import；缺了报错并给 `--formats json,toml` |
| 录制掉帧导致索引漂移 | P1 的 `session.json` 记录帧数与 fps；P0 检测到帧数差就 warning |
| 视频分辨率与标定不符 | P0 启动即校验，不等跑到一半才报错 |
