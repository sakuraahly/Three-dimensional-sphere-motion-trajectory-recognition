### 1.2 🔴 阻塞项 A：MSMF 下两台 aoni 不能同时出图

`cameras.py probe --backends msmf`：**真正出图 2 台 = #1 aoni + #2 内置**；
`#0 aoni` 报 `-2147483638`（设备被置为无效），30.7 s 一帧都没有。

`cameras.py probe --backends dshow`：**#0 / #1 两台 aoni 都出图**（1920×1080），
内置 #2 全黑。

`check_stereo_setup --left 0 --right 1 --backend dshow --no-show`：
**两路能同时打开**（5.3 s），都是 1920×1080；没举棋盘，0/51 帧看到板（预期）。

**结论**：

- **MSMF 双目不可用**（#0 坏）；**DSHOW 双目可用**（#0/#1）。
- 但项目规则是：**角色名/auto 解析出的索引锁死 MSMF**；
  `--backend dshow` 与角色名**不能一起用**。所以 DSHOW 只能走
  **显式数字编号**（`--left 0 --right 1 --backend dshow`），并且必须**目视确认**哪个编号是哪台。
- `-2147483638` 的唯一恢复手段是**物理拔插**（交接文档 §10.15）；
  先拔插 #0，再跑 `probe --backends msmf`，目标是 **#0 ✅ / #1 ✅**。
  只拔插不重启、或换到集线器，都可能无效。

### 1.3 🔴 阻塞项 B：角色名与设备名是**反的**

`config/cameras.json` 里：

```
left  -> 身份 4489382...，名字 "aoni ... right"，索引 1
right -> 身份 31324e2c...，名字 "aoni ... left"，索引 0
```

也就是说：**角色 left 绑的是名字叫 right 的那台**，角色 right 绑的是名字叫 left 的那台。
这可能是你按**物理方位**命名的结果，也可能是历史遗留。`cameras.py check` 只验
"身份与配置一致"，**不验物理左右**，所以它绿不代表左右没反。

**开始标定/录制之前必须目视确认**：遮住一台镜头，看哪一路变黑；
或者在两路画面里各放一个可区分的标记。确认后再决定：
- 若物理左右与角色一致 → 保持现状，但把"名字与角色相反"写进 session notes；
- 若不一致 → `cameras.py identify` + `pin`（**只在 MSMF 可用时**，否则用显式编号 + 目视记录）。

## 2. 规划（按依赖顺序）

### P0 修复/确认双目后端（阻塞项，先做）

1. **拔插 #0（aoni left）**，最好插机身直连 USB 口，不经过集线器/扩展坞；
   等 10 s，跑：
   ```powershell
   & $PY apps\tools\cameras.py probe --backends msmf --max-index 3
   ```
   目标：**#0 ✅ / #1 ✅**。
2. 若 MSMF 恢复 → 用角色名 + 默认 MSMF 走后续流程（这是项目设计路径，
   身份/端口绑定、`check`、`identify` 都成立）。
3. 若 MSMF 仍坏 → **DSHOW 显式编号回退**：
   - `--left 0 --right 1 --backend dshow`（或目视确认后交换）；
   - **不要**用角色名 + dshow（代码会拒绝，且绑定会错）；
   - 标定、复检、录制**全部使用同一组显式编号 + 同一后端**；
   - `session.json` 里写 `backend=dshow`、`index`、`视觉确认=是`。
4. **目视确认物理左右**（见 §1.3），确认结果写进笔记。

**验收**：`probe` 同一后端两台 aoni 都 ✅；`check_stereo_setup` 能看到同一块棋盘
（两路同时 ≥ 90% 帧）；左右确认有文字记录。

### P1 标定：先复检，再决定是否重标

当前 `config/stereo_calibration.*` 是 **2026-10-18 11:25** 的（68 mm 基线、
极线 0.908 px，勉强可用）。相机被拔插/搬动过，**不能默认它还成立**。

1. 用 P0 确定的打开方式跑 `verify_stereo.py`：
   ```powershell
   # MSMF 路径
   & $PY apps\verify_stereo.py --calib config/stereo_calibration --left left --right right
   # DSHOW 回退
   & $PY apps\verify_stereo.py --calib config/stereo_calibration --left 0 --right 1 --backend dshow
   ```
2. 判据：极线 ≤0.6 px 且相对标定时增量 ≤0.15 px → 可继续用；
   否则**重标**。
3. 重标要点（用户自己执行）：
   - 物理量基线尺子值，传给 `--baseline-mm`；算法值为主，物理值只做 10%/20% 核对；
   - 板占画面 **10%–30%**（上次真机只有 1.2%，这是精度偏低的机制原因）；
   - 25 对、姿态覆盖画面四角、板停稳；
   - `--save-pairs` 留证据；`--report-png` 留验证图；
   - 标定后 `export_calibration.py` 导出 JSON/YAML/TOML，并备份 `config/`。
4. **先不要拍球**：标定没通过时录的数据，三维结果不可信。

### P2 双路无损录制器（已完成，2026-10-19 18:34）

`apps/record_stereo.py` 已落地；真机 3 秒 MSMF 冒烟：**30.1 fps / 92+92 帧 / 校验无错误无警告**。

- 两路 **HFYU + MKV**（默认；无损，实测两路并发约 34.5 fps/路）；
  `--codec ffv1` 可选，但本机 2×1080p 只有约 8.3 fps/路，录 30 fps 会掉帧；
- 开录前做"写两帧→读回→逐位比较"自检；
- **1920×1080**、请求 30 fps；实测 fps 写 `session.json`；
- 每路一个采集线程，**每帧都写、不丢帧**（不用 `PairSource` 相机模式）；
- `left_times.csv` / `right_times.csv`：每帧 `perf_counter` + `unix_time`；
- 起手闪光/拍手，录完 `find_offset` 写回；置信度不足时 method=none，不硬编；
- `session.json`：角色/身份或显式编号、后端、请求 vs 实际分辨率、实测 fps、
  帧数、标定路径 + sha256、物理基线、同步偏移、备注；
- 目录 `data/sessions/<YYYYMMDD-HHMMSS>/`，录完直接 `validate_session`；
- `--self-check-only` 不开相机也能验编码器。

**验收**：真实会话两文件同分辨率、帧数差 ≤1、`check_dataset` 通过（已满足）；
同一场景第二次录制可复现。

## 4. 风险

| 风险 | 对策 |
| ---- | ---- |
| #0 MSMF 拔插后仍坏 | DSHOW 显式编号 + 目视确认；session 记录 backend/index |
| DSHOW 编号与 PnP 错位 | 绝不用角色名 + dshow；用显式编号，遮镜头确认 |

| 录制丢帧 | 独立采集线程、每帧写；`check_dataset` 帧数差 ≤1 |
| 无硬件同步 | 闪光/拍手 + `find_offset`；实时场景暂不做 |
| 数据丢失 | `data/` 单独备份；每个会话带 `session.json` |
