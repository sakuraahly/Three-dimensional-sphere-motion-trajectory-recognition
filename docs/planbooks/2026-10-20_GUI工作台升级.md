# 2026-10-20 · GUI 双目工作台升级（计划）

> 目标：把现在散在终端/多个按钮里的操作，收成**一个会话工作台**：
> 录制 → 校验 → 点选 seed → 跑双目 → 看 3D → 导出标准数据。
> **本阶段不做预测、不做实时双目、不做自动 seed**（点选是刻意保留的人工确认）。

---

## 1. 现在的问题

| 现状 | 用户要记/要做的事 |
| --- | --- |
| 录制、离线双目、点选 seed 是三个独立按钮 | 先录、再找目录、再点选、再回来跑 |
| `check_dataset` 只在终端 | 录完不知道同步/黑帧/帧数是否合格 |
| 3D 查看器只能命令行 | 跑完还要切终端 `python apps/view_3d.py ...` |
| 标准 JSON 已自动生成，但 GUI 不展示 | 不知道 `traj3d.json` / `visualization.json` 在哪、是否成功 |
| 任务日志/状态分散 | 失败后要自己判断下一步 |

**不是功能缺失，是操作路径没闭环。**

---

## 2. 目标界面（第 3 步“双目工作台”）

```text
┌ 双目工作台 ─────────────────────────────────────────────┐
│ 最近会话  [下拉/列表：20261020-095331  flash ✓ seed ✓]   │
│                                                         │
│ ① 录制 10 秒   [录制双目]                                │
│ ② 数据校验     [校验]   帧数 302/303  sync flash +1 ✓    │
│ ③ 点选球心     [点选 seed]  左(894,732,58) 右(561,747,58)│
│ ④ 跑双目       [离线双目]  匹配 97.7%  残差 1.95 px     │
│ ⑤ 看三维       [打开 3D 查看器] / [内嵌预览]             │
│ ⑥ 标准数据     [导出 JSON] traj3d.json / visualization.json│
│                                                         │
│ 状态：20261020-095331 已通过；B 095403 帧数不一致，需重录 │
└─────────────────────────────────────────────────────────┘
```

关键原则：

- **每一步只显示“当前能不能做 + 做完结果 + 下一步”**，不让用户猜；
- 录制完成后自动选中新会话；
- 校验失败直接给原因与“重录”，不进入点选；
- seed 仍由人点（金属球/高光靠猜不可靠）；
- 3D 先做“打开独立查看器”，稳定后再考虑内嵌 matplotlib 画布；
- 所有操作走现有脚本 + 任务管理器，不把算法搬进 GUI。

## 3. 分阶段实施

### P0 会话摘要层（无 UI）

新增 `apps/_workbench.py`（私有辅助库，只被 GUI import，不顶层执行）：

```python
@dataclass
class SessionSummary:
    path, id, created, frames_left, frames_right, fps
    sync_method, sync_offset, sync_confidence
    has_seeds, has_traj, has_visualization, has_annotated
    n_matched, n_samples, z_min, z_max, residual_median
    status: "empty" | "recorded" | "seeded" | "traj" | "bad"
    problems: list[str]

def scan_sessions(root) -> list[SessionSummary]
def summarize_session(path) -> SessionSummary
```

- 只读文件，不跑检测；
- 状态判定规则写死并有测试：帧数差 >1 / sync none / 黑视频 / 缺 JSON；
- 这是 GUI 和控制台共用的“会话事实”，避免 GUI 自己解析 CSV/JSON。

**验收**：对 `20261020-095331`（通过）与 `20261020-095403`（帧数 302/304）
返回不同 `problems`；不启动 Tk。

### P1 工作台卡片

- 第 3 步加“会话工作台”卡片；
- 最近会话列表（默认最近 10 条）；
- 选中后显示：
  - 帧数、sync、seed 状态、traj 状态；
  - `校验 / 点选 seed / 离线双目 / 打开 3D / 导出 JSON` 按钮；
- 按钮禁用逻辑：没有视频不能校验；没有 seed 不能跑 specular；没有 traj 不能看 3D；
- 录制完成后自动刷新并选中新会话。

**验收**：不碰终端，能从列表选中 A 会话，看到 97.7% 与 JSON 状态。

### P2 一键“录制后收尾”

录制按钮完成后：

1. 自动 `check_dataset --strict`（走任务管理器，不阻塞 UI）；
2. 结果写入状态卡；
3. 通过则提示“点选球心”，失败则提示“重录”，并给原因；
4. 点选保存后自动启用“离线双目”；
5. 离线完成自动刷新摘要，启用“打开 3D”。

**不做**：自动点 seed、自动改 offset、自动重录。

### P3 3D 查看器入口

- 第一版：`[打开 3D 查看器]` 调用
  `python apps/view_3d.py <session>`，用任务管理器管理进程；
- 第二版（可选）：在 GUI 内嵌 matplotlib `FigureCanvasTkAgg` 的 3D 画布；
- 第一版优先，避免把 GUI 变成第二个 matplotlib 应用。

### P4 数据/文件面板

- 显示 `derived/seeds.json`、`traj3d.json`、`visualization.json`、
  `annotated.mp4`、`traj3d.png` 是否存在；
- `[打开目录]`、`[复制路径]`、`[重新导出 JSON]`；
- 显示 `n_matched / n_samples`、Z 范围、残差中位；只读，不改数据。

### P5 测试与文档

- 扩展 `tests/selftest_launcher_params.py`（**不新增测试数量**）：
  - `_workbench.summarize_session` 对通过/坏会话的状态；
  - 工作台按钮的 enable/disable 规则；
  - 3D 查看器入口命令包含 `view_3d.py` 和会话路径。
- 更新 `docs/用户手册.md` §12.6、`docs/交接文档.md`、`docs/文件结构.md`。
- 跑 `启动程序.bat test` + `standards`。

## 4. 验收标准

| 场景 | 通过标准 |
| --- | --- |
| 录制完成 | 自动校验；0 warning 才亮“点选” |
| 坏会话 B（302/304） | 状态卡明确“帧数不一致，重录”，不劝进三维 |
| 点选 seed | 保存后 `seeds.json` 状态变为 ✓ |
| 跑双目 | 完成后显示匹配率/残差/Z 范围，不需看终端 |
| 看 3D | 按钮能打开 `view_3d.py`，进程可被任务管理器收掉 |
| 导出 | `traj3d.json` / `visualization.json` 存在且可打开 |
| 无终端 | 从录制到看 3D 全在 GUI 完成（seed 点选除外） |
| 回归 | fast 20/20；23 个测试数不变 |

## 5. 明确不做

- 不做预测/Kalman 开关（用户明确先不做）；
- 不做实时双目（`run_realtime.py` 仍单目）；
- 不做自动 seed/自动 Hough 初始化（金属球不可靠）；
- 不把 `check_dataset`/`run_stereo_video` 的逻辑复制进 GUI；
- 不改测试数量；不新增根目录启动脚本。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| `启动程序.py` 继续变大 | 事实/状态放 `apps/_workbench.py`，GUI 只做展示与命令 |
| 校验/离线是长任务，卡 UI | 全部走现有任务管理器，按钮按任务状态禁用 |
| 用户不知道“为什么不能点” | 每个禁用按钮旁显示 `problems[0]` |
| 3D 内嵌复杂 | 第一版只打开独立查看器 |
| 状态过期 | 每次操作后重扫会话目录，不缓存 |
