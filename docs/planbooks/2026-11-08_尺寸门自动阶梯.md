# 尺寸门自动阶梯（半径门自适应）· 计划书

> 2026-11-08 15:20 起。触发：梨子实验（`data/stereo/parallel/20261108-150233`）
> 暴露的两个问题，用户口径：「尺寸门也是要变成自动阶梯跳变的参数吧，就像打开相机一样」。

## 1. 问题

`min_radius = 8 / max_radius = 200` 是**针对某个拍摄距离写死的先验**。
梨子凑近到 25 cm，半径 **205–212 px**，刚好越过 200 → 检测器 0 检出，
而它给出的理由是「**球可能太小**」—— 方向完全相反。

同一个坑已经出现过一次：`train_ball_detector.py` 里为了训数据集，把
`max_radius` 直接写到 5000（等于关掉这道门）。写上 5000 不是解法，是绕过。

## 2. 参照物：相机分辨率协商（已落地，可复用其形式）

`stereo/pair_source.py` 的 `AUTO_*`：从保守档出发 → 每档按可量化判据测 →
命中就锁 → 逐档留证据 → 走完还没命中就说清"走完了"。
本计划把这套形式搬到"半径门"上，**不是**新发明一套。

## 3. 判据（先写死，再实现）

| 项 | 取值 | 依据 |
| -- | ---- | ---- |
| 档位 | `r_max = k·H`，k ∈ (0.18, 0.30, 0.45, 0.65) | 用**画面高度比例**，1080p 与 720p 同义；0.18·1080=194 ≈ 现有 200 |
| 命中 | 探针窗口内「有检出」帧占比 ≥ **0.6** | 与 `AUTO_MIN_PAIR_FPS = DEFAULT_FPS*0.6` 同一个"六成"口径 |
| 贴边 | 候选半径 p90 ≤ **0.90·r_max** | 贴着上限说明**还在被切**，要再上一档 |
| 锁死 | 命中后整段不变 | 中途改门限 = 同一段轨迹物理口径前后不一致，比一开始选错更难查 |
| 放弃 | 走完 4 档仍未命中 | 输出"走完了 + 每档的命中率"，不静默 |

**只解一种病**：候选**存在但被尺寸门砍掉**。
若探针窗口内**根本没候选**（掩膜落在墙上），阶梯**立即放弃**并说明
"与尺寸门无关" —— 否则会一路放大到 0.65·H 把墙当球。

## 4. 落地清单

1. `sphere_tracker/detectors/size_ladder.py`（新，纯逻辑、无 cv2）：
   `SizeLadder` 状态机 + `SIZE_LADDER_K` + `observe()/window/describe()`。
2. `sphere_tracker/detectors/color.py`：
   - 在尺寸门前记录**最大候选半径**（`_diag["r_max_seen"]`），供阶梯读；
   - `_diagnose` 把"0 候选"拆成 **尺寸门 / 形状门 / 掩膜不在附近** 三类，
     并报出实测半径，不再一律说"球可能太小"。
3. `apps/run_stereo_video.py`：`--radius-auto`（默认开）/`--no-radius-auto`，
   探针在正式循环前若干对里跑，锁定后打印一行 `[半径门] 锁在第 N 档 …`。
4. 测试：`tests/selftest_plugins.py` 增一节（不新增测试文件，避免改 27 处计数）。

## 5. 明确不做

- 不改 `min_radius`（去噪用，与距离无关，放宽只会放大误检）。
- 不做"每帧跳档"（那是抖动，不是自适应）。
- 不动 `hough_max_radius`（hough 的搜索窗另有语义，见 `config.py:275` 的注释）。
- 不用 `max_radius=5000` 这种"关掉门"的做法（`train_ball_detector` 是训练场景的特例）。

## 6. 验收

- 梨子那段录像：`--radius-auto` 下能锁到 0.30·H 档并检出（半径 ≈205 px 应落在窗口内）；
- 原有用例不回归：`run.bat test fast` 全绿；
- 反向自证：把阶梯关掉，同一段应复现"0 检出 + 说清是尺寸门"。

## 7. 实施结果（2026-11-08 15:25）

已落地：

| 文件 | 改动 |
| ---- | ---- |
| `sphere_tracker/detectors/size_ladder.py`（新） | `SizeLadder` 状态机；档位 `0.18/0.30/0.45/0.65·H`；命中判据 0.6；**升档的唯一理由**是"门外有被尺寸门单独挡住的更大候选"；命中即锁死 |
| `sphere_tracker/detectors/color.py` | 记 `_diag`：`r_seen / r_pass / r_blocked / image_h / gates / biggest`；`_zero_candidate_note()` 把 0 候选拆成 **背景 / 尺寸门 / 形状门 / 分数门 / 面积门** 五类，并带实测数值 |
| `apps/run_stereo_video.py` | `--min-radius/--max-radius` 默认改 `None`（**手工优先**）；新增 `--no-radius-auto`；自动时每帧写入窗口、逐档打印证据 |

实测（`data/stereo/parallel/20261108-150233`，`--method color`）：

```
[半径门] 走自动阶梯：4 档 (k=0.18, 0.30, 0.45, 0.65 × 画面高 1080px)，每档看 12 帧
[半径门] 第 1 档 r_max=194px（k=0.18）：11/12 帧有检出（92%），门外最大候选 378px → hit
[半径门] 锁在第 1/4 档：8–194px（画面高 1080px）
```

`_zero_candidate_note` 实测（同帧、`max_radius=200`）：

> 掩膜落在背景上了：掩膜占画面 19%，最大连通域半径 367px（≈ 0.34×画面高）——
> 这不是尺寸门的问题，拿远相机只会让背景更完整。先换 `--preset` / 缩取色区间，
> 或改用点选球心（seed）

回归：`run.bat test fast` **24/24 通过**（15:25）。

## 8. 还没做

1. **正式判据测试**：`tests/` 里补一节「阶梯三态」（hit / step / no_candidate）+ 反向自证。
   现在是靠真跑那段录像 + 全量回归验的，**缺一条会自动变红的闸**。
2. **GUI 暴露**：`--radius-auto` 目前只有命令行；GUI 的「离线三维重建」应给一个
   「尺寸门：自动/手工」的选择（`apps/_actions.py` 已有 `min_radius/max_radius` 透传）。
3. **标定那件事没修**（正交问题）：梨子会话的 20px 极线残差来自标定（板面 4.7% < 8%），
   与尺寸门无关，仍需重标。
