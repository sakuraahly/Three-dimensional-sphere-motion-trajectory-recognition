## 0. 先说方法：为什么"看代码猜"不算验收

新 GUI 是 **Tkinter**，因此可以在**同一个进程里真的 `invoke()` 点按钮**，
不必"读代码想象用户点了会怎样"。本次做的是一个**真开窗口、真点按钮、逐步截图**的
走查工具 [`gui_walkthrough.py`](../../apps/tools/gui_walkthrough.py)，
外加一路**静态接线审计**、一路**相机归因**。

> 这一节是范式审计的前置：**判据的可信度**本身要被审。

## 2. 范式审计（§11.7 硬条款 — Leader 亲自做）

逐条列出"用 GUI 走查证明 GUI 没问题"这套做法沿用的隐含前提，判它在新条件下是否成立：

| #   | 隐含前提                            | 成立？           | 依据 / 换成什么                                                                                                                                                        |
| --- | ----------------------------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1  | 「窗口能开、不崩 = 没缺陷」         | ❌ **不成立**     | 走查第一版报「缺陷 0 条」，依据**只有截图**。而缺陷 #1 的窗口在截图里长得完全正常（窗口在、按钮在、状态条有字）—— 它**根本开不出来**，是空窗                           |
| P2  | 「截图就是判据」                    | ❌ **不成立**     | 改为每点一个按钮必须留**三样证据**：状态条原文前后对比、任务日志尾+退出码、产物是否真的出现。拿不出三样的只能记「未验证」，**不许写"正常"**                            |
| P3  | 「没点就没风险」                    | ⚠️ **部分成立**   | 录制/标定/拍图/点选/清理会动数据或需要硬件，**按用户要求不点**；但必须显式标 `未验证`，不算绿（`report.json` 的 `unverified` 就是这份清单）                            |
| P4  | 「界面显示'相机可用' = 相机能出图」 | ❌ **不成立**     | 单目① 那行是**静态匹配**（角色/端口对上就写），**不开相机**。这正是本轮**唯一没修**的一条                                                                              |
| P5  | 「按钮存在 = 按钮接上了」           | ❌ **不成立**     | Tk 的 `command=` 指向不存在的回调会**静默吞掉**；「检查装置」曾经就是"没有回调 → 状态条永远停在正在检查"                                                               |
| P6  | 「界面按 mm 收，命令行也按 mm」     | ❌ **不成立**     | 界面按 **mm** 收（默认 21.6），`--ball-diameter` 与 `AppConfig.ball_diameter_m` 要**米**。断链的直接后果不是"Z 差 1000 倍"，而是**一个三维点都不出**（被范围判据拦掉） |
| P7  | 「失败时状态条会写失败」            | ❌ **不成立**     | 实测：平行②「开始标定」失败后状态条刷成「**就绪**」；工作台①「校验数据」成功后永远停在「正在校验…」                                                                    |
| P8  | 「折叠区能省空间」                  | ❌ **被实测否掉** | 折叠区**头按钮自身**要 28 px，只省回 19 px，而两个窗口还差 42 / 110 px                                                                                                 |

**结论**：P1/P2/P5/P6/P7 是**必须修**的范式失效；P3 是**有意边界**（要标注，不是要绕过）；
P4 是**本轮剩下的那条**（登记 `B-149` 的同类）；P8 换成"**把两行按钮并成一行 + 按内容定高**"。
**无「spec 与原理冲突」待升仲裁的项。**

**关于被推翻的两条旧判断**（写在这里，免得留在别人脑子里）：

- ❌ 旧判断「「检查装置」是死按钮，不传参数必然 exit 2」→ **不成立**。
  [`check_stereo_setup.py`](../../apps/tools/check_stereo_setup.py) 用
  [`add_stereo_source_args`](../../apps/_common.py) 加参数，**一个 `required=True` 都没有**；
  不传参数它不会退 2，而是自动挑相机、真开 8 秒取景。当初看到的 exit 2 是
  **左右相机撞车**造成的。真实缺陷只有一半：**没有回调，状态条永远停在「正在检查」**。
- ❌ 旧判断「子进程会无限期卡在 `input()`」→ **对新 GUI 不成立**。
  `pair_source` 现在传 `interactive=False`，且唯一用默认值的 `run_realtime.py`
  **新 GUI 从不启动**。该风险降级为「`run_realtime` 那条路」。
  （`_task_runner` 仍然补了 `stdin=DEVNULL`：**它不是为这个 bug 修的，是兜底**。）
