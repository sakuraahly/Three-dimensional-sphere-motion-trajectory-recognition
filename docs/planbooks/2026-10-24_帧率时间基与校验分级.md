# 计划书：容器时间基写错 + 校验器把"标称不准"当硬失败

- 日期：2026-10-24（第二轮）
- 触发：用户录完 10 秒双目片段，`check_dataset --strict` 报"不通过（错误 0，警告 2）"，
  工作台显示"校验失败（码 1）"
- 角色：Leader（定边界/裁决/验收） + Specialist（根因调研） + Executor ×2（写入器 / 校验器） + Critic（独立验收）

## 1. 要解决什么

一句化：**视频文件的时间基是错的，而校验器把"标称值不准"和"真的丢帧"混成一件事。**

不做会怎样：所有按容器 fps 换算时间的下游（播放器、`sources.py` 的 `FileSource`）系统性偏 25%；
同时真正危险的场景（容器头错一倍、sidecar 残缺）反而没人拦。

## 2. 根因链（每层带证据）

| 层 | 结论 | 证据 |
| --- | ---- | ---- |
| 表象 | `--strict` exit 1，警告 2 条 | 用户日志 `20261024-173514` / `173619` |
| 直接原因 | 容器 fps=24.0，实测 29.92，差 20% > 阈值 10% | `sessions.py:329-334`（旧） |
| 机制原因 | 写入器 fps 直接取 `args.fps`（argparse 默认 24），与相机无关 | `record_stereo.py:574-575` → `_make_writer` |
| 根因 | **一个参数背两种语义**（"请求相机帧率" vs "容器标称帧率"），容器时间基没有任何"以事实为准"的来源 | `--fps` help 原文；`sources.py:588` 自承 `CAP_PROP_FPS` 常回显请求值 |
| 附带过期结论 | "1440p 主循环只有 24.07fps" 的前提是写盘 3.68MP；FOV 对齐后写盘 1.67MP，实测 30fps 稳定 | 301 帧 / 10.002s；`record_stereo.py:391/415-421`（旧注释） |

**影响面（不夸大）**：只有 `sources.py:874,880-884`（FileSource 用容器 fps 换算 t）受影响；
`timestamp_pair.py` / `pair_source.py` / `run_stereo_video.py` 走 sidecar 或 `fps_measured`，未受影响。

## 3. 改法

1. **写入器**：容器帧率取两路**相机协商值**（`cap.get(CAP_PROP_FPS)`，取 min），退化链 `_container_fps(info, requested)`；
   写盘前打印取值来源。修正 1440p 历史注释与警告条件（改成按**写盘像素**判断）。
2. **校验器分级**：`errors`（硬失败）/ `warnings`（`--strict` 下失败）/ `notes`（永不失败）。
3. **fps 拆两条**，不再混：
   - sidecar 完整 + 真实帧率可得：`ratio ≤10%` 静默；`10–25%` → 提示（标称偏差）；`>25%` → 警告（时间基错误）；
   - sidecar 缺失 → 只能用容器，`ratio>10%` 仍为警告；
   - sidecar **有但坏**（行数≠帧数 / 不单调）→ **独立**警告，不依赖 `fps_measured` 是否存在。
4. **清晰度只做提示**：复用 `camera_quality.frames_quality` 的指标（Laplacian 方差中位数，中心 25–75%），
   报左右数值与比值；`≥1.8` 也只给提示 + 指向 `camera_quality.py`。

## 4. 裁决记录（Leader）

- **签字**：容器 vs 实测 fps 在 sidecar 完整时降为提示 —— 数据的时间基在 sidecar 里，容器只影响播放观感。
- **驳回**：清晰度 `≥1.8` 判 warning。理由：`check_dataset` 是**数据有效性**闸门，清晰度差不等于数据无效；
  且会把 7 个旧会话追溯判死。权威判据留在 `camera_quality.py`。
- **不做**：两路各写各自协商帧率（现取 min）。两路差 ~2% 只影响播放器观感，代价不值。

## 5. 验收标准

1. `check_dataset --strict` 对 `20261024-173619`、`20261024-173514` → **exit 0**，fps 为 `[提示]`。
2. sidecar 改名 / 截断 → **exit 1**（不是一律放行）；`fps_measured` 缺失时也不许静默。
3. 全库 `--root --strict`：本轮新规则导致**翻红 0**；不通过数仍 15（全部是既有问题）。
4. 原有 19 条检查一条不少、不放宽。
5. `run_tests.py full` 全绿；测试数仍 23。

## 6. 明确不做 / 已知限制

- **真机未复测**：容器头是否真为 30.0 没有实拍验证（无相机）。验证条件：一次 10s 实拍 + 打印
  `cap.get(CAP_PROP_FPS)` 与 `[容器] 标称帧率` 行 + 对成片读容器 fps。
- 清晰度是**场景相关**指标（同一批录像不同会话 23~97 波动），只用于同场次左右对比，不能跨会话比较。
- 旧会话若**既无 sidecar 又无 `fps_measured`**，时间基无从校验，仍是静默（无证据可比）。
