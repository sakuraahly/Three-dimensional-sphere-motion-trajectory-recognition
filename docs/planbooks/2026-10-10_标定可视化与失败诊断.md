# 标定可视化与失败诊断（2026-10-10）

> **要解决什么**：标定两次跑不通，而且**人不知道自己已经收过哪些姿态** ——
> 只能举着板瞎猜，重复被"与已收位姿太接近"拒掉。
>
> **一句话**：先把"我收到哪儿了"变成看得见，再把"为什么解不出来"变成量得出来。

---

## 1. 现象与证据

### 1.0 用户的原话（这是本计划的第一驱动）

> "我看不到所谓的已经标定的姿态和位置，**只能瞎猜**。"
>
> "我在标定的时候**反馈很不好**。"

**这不是"锦上添花"，是当前最直接的痛。** 标定要求"把板挪到没覆盖过的姿态"，
而程序**不告诉人已经覆盖了哪儿** —— 于是一个人举着板，被
"与已收位姿太接近"反复拒绝，却不知道为什么、该往哪挪。

### 1.0.1 已修：覆盖率面板画到了画布外面（**2026-10-10 本轮修**）

**这是我自己在"P0-3 面板自适应"那轮改出来的 bug。**

```python
# 调用（错的）
cov_cache = collector.coverage_image(size=(190, img_h), scale=1.0)
```

`coverage_image` 里 `size` 的语义是**源图尺寸**，而内容按 `scale` 缩放：

```python
canvas = np.zeros((int(h*scale), int(w*scale), 3))          # -> 190 × img_h
quad   = perspectiveTransform(unit, p.homography_left) * scale   # -> 仍是全图坐标 600~900
```

**画布只有 190 px 宽，姿态却画在全图坐标处 —— 全部落在画布外。**
面板看起来是空的（用户截图右上角那条贴边的线，就是被裁掉的一个四边形）。

**修复**：把参数语义拆成"**输出画布**"与"源缩放"两种，由函数自己算缩放并居中：

```python
def coverage_image(self, out_size=None, scale=0.5):
    if out_size is not None:          # 输出画布，等比缩放 + 居中
        s = min(ow / src_w, oh / src_h)
```

**同时补上"还缺哪儿"**：每个宫格内直接写 `已收/上限`（如 `1/5`），
满格显绿、未满显黄 —— 用户要的是"知道下一步往哪挪"，
让他自己数四边形属于"需要思考"。

**验证**：构造 3 个已知位置的假姿态渲染 → 非背景像素 2.96%（修前几乎为 0），
目视确认 3 个四边形 + 3 个 `1/5` + `3/25` 全部正确落在画布内。

### 1.0.2 仍然不够好的地方（**待做，本计划的 V0**）

| # | 现状 | 该怎样 |
| - | ---- | ------ |
| a | 只有位置覆盖，**没有倾角覆盖** | 8 对可能全是正面照（内参病态）；要显示"倾角偏正面" |
| b | 收下一对的反馈只有角上计数 +1 | 新收的四边形**闪一下**，让人确认"这一下算数了" |
| c | 没有一句直接的"下一步" | 条带里写 `覆盖：缺 左上/右下` |
| d | 面板在窄窗口下会被压缩 | 设下限宽度，宁可压缩图像 |

### 1.1 真机 8 对的标定结果（`outputs/logs/calibrate_*.log`）

```
标定板        : 棋盘格 8x5 内角点，方格 25 mm
图像尺寸      : 1920x1080
使用/输入图像 : 8/8
整体重投影 RMS: 46.4040 px
左目重投影 RMS: 1.3784 px      ← 单目正常
右目重投影 RMS: 0.9386 px      ← 单目正常
极线误差 RMS  : 15978.5150 px  ← 比图像对角线(2203px)大 7 倍
基线长度      : 199.67 mm
判定          : 不可用
```

**关键签名：单目各自 ~1 px（好），双目 46 px、极线 15978 px（垃圾）。**

这个组合**不是"图不清楚"**：图不清楚会让单目也变差。它说明**左右两路的对应关系或相对位姿解算出了问题**。

### 1.2 已经排除的原因：8 对太少

用项目自带的合成装置做对照（`tests/selftest_stereo_calib.py` 的 `make_poses` / `render_view`）：

| 合成场景 | 整体 RMS | 极线 RMS | 基线误差 | 判定 |
| -------- | -------- | -------- | -------- | ---- |
| **A. 8 个覆盖良好的姿态** | **0.4154 px** | 0.3209 px | 1.5% | 可用 |
| **B. 8 个姿态挤在一起** | **0.1334 px** | 0.2738 px | 12.3% | 可用 |

**结论（已证）**：8 对本身**完全够用**，A 组 0.42 px 甚至优于 `ok_rms=0.80` 门槛。
姿态退化只让**基线偏 12%**，RMS 依然正常。

**所以真机那 46 px / 15978 px 另有原因，而且不是"数量不够"或"姿态不散"。**

## 2. 待确认的根因（**证据缺口，不写死结论**）

**当前最高嫌疑：左右两路的角点顺序不一致。**

理由：这是唯一能同时解释"单目各自正常、双目爆炸"的机制 ——
每个相机内部的角点顺序自洽（所以单目标定正常），
而左右数组**同名下标对应的不是同一个物理角点**时，
`stereoCalibrate` 拿到的是错配点对 → R/T 是垃圾 → `stereoRectify` 的 P1/P2 是垃圾
→ `undistortPoints` 把点映射到图像外 → 极线误差 15978 px。

**机制上说得通，但还没在真机数据上验证过。** 采集时用的是
`detect_board_in_roi` → 内部 `detect_board`（`findChessboardCornersSB` 优先、
经典版兜底），**左右两路若分别落到不同检测器，或板在两路里的表观旋转不同，
返回顺序就可能不同。**

### 验证方案（一次运行即可）

```powershell
python apps\calibrate_stereo.py --left left --right right --save-pairs outputs\pairs_try
```

拿到 `outputs/pairs_try/left/*.png` 与 `right/*.png` 后，逐对：

1. 各自跑 `detect_board`，取角点数组；
2. 比对**两路角点数组的几何一致性** —— 用两路的单应 `H_left`、`H_right`，
   算隐含的相对旋转 `R_rel = R(H_right⁻¹ · H_left)`；
   真实双目（基线 200 mm、板在 ~0.6 m）**相对旋转应当只有几度**；
   若算出接近 180° 或行列互换的形态 → 顺序不一致，**根因确认**。

## 3. 做到什么算完成

| 项 | 验收标准 |
| -- | -------- |
| **V1 看得见** | 标定窗口里能一眼看出**已收的 8 个（或 25 个）姿态分别落在画面哪个区域、什么倾角**，不需要任何解释 |
| **V2 知道下一步** | 每收一对后，界面明确提示**下一步该往哪挪**（哪个宫格还空着、哪个倾角还没覆盖） |
| **V3 失败可诊断** | 标定失败时，除了 RMS，还给一句"**最可能是哪一类问题**"（对应关系 / 姿态覆盖 / 图像质量），并说明验证方法 |
| **V4 对应关系有守卫** | 左右角点顺序不一致时**当场报警**，而不是解出 46 px 才发现 |

## 4. 最小完善清单

### P0 —— 让已收姿态看得见（用户当前最痛的一条）

| # | 做什么 | 为什么 | 代价 |
| - | ------ | ------ | ---- |
| **V0-1** | **覆盖率面板放大并加语义**：现在的图只有 200 px 高、挤在最右侧，形状与网格没有图例。改成：<br>· 尺寸随窗口自适应（至少 1/4 面板宽）<br>· 画出**每个已收姿态的棋盘四边形**（已有）+ **中心点**（已有）+ **倾向**<br>· 宫格上直接写"已有 n/5" | 用户现在看到的是几个绿框和 `3/8`，**看不出"还缺哪里"** | `calib/capture.py: coverage_image()` ~60 行 |
| **V0-2** | **"还缺什么"用文字说出来**：条带里加一行 `覆盖：缺 左上/右下；倾角偏正面 6/8` | 图形要解读，文字不用。符合"不要让用户思考" | ~40 行，靠已有 `_region_count` 与位姿中心 |
| **V0-3** | **收下一对后短暂高亮**：新收的四边形闪一下（约 0.5 s），让人确认"这一下算数了" | 现在只有左下角的计数 +1，不显眼 | ~15 行 |

### P1 —— 让失败可诊断

| # | 做什么 | 为什么 |
| - | ------ | ------ |
| **V1-1** | 按 §2 的验证方案跑一次 `--save-pairs`，**确认或推翻**根因 | 现在只有嫌疑，没有结论 |
| **V1-2** | **加左右对应关系守卫**：采集时逐对检查 `R_rel` 的隐含旋转角，超过阈值（建议 25°）就拒绝并报警，附"两路角点顺序可能不一致" | 把 §2 那条从"事后分析"变成"当场发现" |
| **V1-3** | 标定失败时输出**归因段落**：按 `per_pair` 分布判断是"个别坏帧"还是"整体错配"，并给出对应的下一步 | 现在只有"重拍"两个字 |
| **V1-4** | 标定失败时**自动保留图像对**到 `outputs/pairs_failed_<时间戳>/` | 失败现场不保留，就只能重拍一次去复现 |

### P2 —— 姿态覆盖引导

| # | 做什么 |
| - | ------ |
| **V2-1** | `diversity_min` 与 `max_per_region` 的取值**用数据定**：先跑几次看 V0-2 的覆盖统计，再决定要不要调（**不凭猜调参**） |
| **V2-2** | 覆盖率不足时，把"建议的下一个姿态"画在覆盖率面板上（半透明示意） |

## 5. 明确不做

| 不做 | 理由 |
| ---- | ---- |
| 不因为这次失败就**调高 `stationary_max_px` 或降 `min_sharpness`** | 已证 RMS 与图像质量无关（单目 1 px）；调门限只会收进更差的帧 |
| 不把 `min_pairs` 再往上调 | 已证 8 对够用；问题不在数量 |
| 不做三维实时可视化 | 与本次目标无关，属于 `../计划书.md` 的里程碑 |
| 不换标定板（ChArUco）**在这次诊断之前** | 换板会掩盖根因；先确认是不是对应关系问题 |

## 6. 执行顺序

```
V0-1/V0-2/V0-3 看得见 ──> 用户再跑一次标定 ──┐
                                            ├─> 若仍失败 ──> V1-1 抓 --save-pairs 定根因
V1-4 失败自动留图 ─────────────────────────┘                      │
                                                                  ↓
                                                    确认是顺序问题 → V1-2 加守卫
                                                    确认是别的   → 另开计划
```

**先做 V0**：它独立于根因，且是用户当前最直接的不便。
**V1-1 必须在 V1-2 之前** —— 守卫的阈值要靠真实数据定。

## 7. 风险

| 风险 | 对策 |
| ---- | ---- |
| 加大覆盖率面板后，1080p 屏幕上更挤 | 面板已经自适应（P0-3 那轮做的），文字条带优先保空间 |
| `R_rel` 阈值定得太松/太紧 | 用 V1-1 的真实数据定；先只报警不拒绝 |
| 加了守卫后正常帧被误拒 | 守卫只对"明显不一致"（>25°）生效，且报警时**同时打印实测角度**，便于回看 |
