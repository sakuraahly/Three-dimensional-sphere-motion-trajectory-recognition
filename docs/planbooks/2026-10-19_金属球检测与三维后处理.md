## 3. 规划

### P0 镜面球检测器（阻塞项）

新增 `sphere_tracker/detectors/specular.py`，接口与现有 detector 一致：

```python
class SpecularBallDetector:
    def detect(self, frame, ctx) -> list[Detection]
```

推荐组合（按复杂度递增）：

1. **Hough 只做中心提议，不直接信半径**：子 agent 在 `193809` 上实测球的
   半径约 **30–65 px**（frame 97 ~35–40、134 ~33、245 ~64），随摆锤远近变化近 2×；
   之前用 6–15 px 的固定先验**根本没扫到真球**，检出的“圆”是内部反射弧/背景。
   要用半径扫描/一维径向边缘谱，不能固定一个半径；
2. **时序门控**：球速约 **80 px/帧**（233→245 移动约 970 px），±60 px ROI 不够；
   用 `2.5r + 1.5|v|dt`（上限约 360 px），丢失时全图搜索；
3. **镜面特征**：饱和度不具区分度（球 S≈30，背景白袋 S≈26）；改用
   内部高光锐度/动态范围 + 暗环 + 圆周梯度一致性，不要用单一颜色阈值；
4. **手动种子兜底**：左右各一个 `--seed` / `--seed-right`（单 seed 覆盖不了
   ~85 px 视差）；研究阶段允许人工初始化，但必须记录在 session notes，
   不能假装全自动；
5. **标签先行**：现有 25 帧只有 PNG、没有真值；先按
   `side,frame,x,y,r,visible,hard,notes` 标 20–30 帧，否则只能做合成测试，
   无法证明真机命中率。

**验收**：在 `20261019-193809` 上抽 20 帧，检测圈必须套在球上 ≥18 帧；
三维轨迹的 X/Y/Z 变化范围与摆锤可见运动一致（不是 1 cm 的死点）。
另外记录 `--detect-width` 的已知坑：`SpherePipeline` 把原分辨率 `ctx.gray`
传给缩小后的 detector，新检测器必须做 shape-guard，pipeline 侧另行修。

### P0 新证据：`200855` 不是一条完整轨迹

逐帧看原始左图：球在 frame 0/60 还可见，**frame 150 已经不在画面里**
（见 `outputs/tmp_frames3/left_marks_150.jpg`；红/绿十字标在 920/960，附近没有球）。
左路 CSRT 从 frame ~80 起只是在跟踪静止背景；现在检测器加了两道“静止/缺失”守卫：

- 局部运动与中心位移连续 20 帧都接近 0 -> 判丢；
- 最近 25 帧中心跨度 <5 px -> 判丢。

`200855` 现在会明确报 `lost`，不再把背景死点送进三维。**这条会话不能用于 3D 验收**；
需要重录：球在**左右两路都全程可见**、10 秒、开始/结束各闪一次。

### P1 同步（阻塞项，和 P0 并行）

**实测根因（2026-10-19）**：`20261019-192530` / `193809` 的逐帧亮度最大跳变只有
1.44 / 0.98，明显事件 0 个；而 19:06 那次闪光测试是 5.2 / 4.9、事件 67/64 个。
**不是 `find_offset` 坏了，是这两段视频里根本没有闪光**（闪早了/闪晚了/没闪）。

已加的诊断：

- 录制器在 `开始！现在闪光！` 时蜂鸣提示；
- 录完打印 `[同步诊断] 最大亮度跳变 左/右` 和事件数；
- 画 `derived/sync_brightness.png`（两路亮度曲线 + 事件位置）；
- `validate_session` 对 `sync.method=none` 给警告，`check_dataset` 会显示；
- `find_offset` 的 `peak_count` 改为左右取较大者（闪光可能只在一路明显）。

操作要求：**看到/听到“开始！现在闪光！”后立刻闪**，不要在倒计时里闪；
结束前再闪一次。最大跳变 **<2.0**（`SyncConfig.flash_min_jump`）就重录，
不要拿 `offset=0` 当对齐。

**自动兜底**：没有闪光时，录制器用逐帧 `perf_counter` 时间戳估计 offset，
`method=timestamp`；中位差超过半帧就拒绝。它只是主机读帧时间的近似，
慢速场景可用，快速球仍应闪光。

### P2 三维后处理接主流程

`run_stereo_video.py` 增加：

- `--kalman`：对匹配点跑 `Kalman3D`，输出 `traj3d_filtered.csv`；
- `--predict 0.2`：用 Kalman 外推，输出预测点与误差（留出未来帧评估）；
- 默认不开启；只在 P0/P1 验收通过后打开。

### P3 深度融合

- 左路检测半径 → `mono_depth(radius, fx, D)`；
- 双目三角测量 → `stereo_depth(disparity, fx, B)` + σ；
- `fuse_depth` 输出 `Z_fused`、`σ`；在 CSV 里加 `z_mono/z_stereo/z_fused`；
- 球径 `D` 必须已知（卡尺量），不能猜。

### P4 世界坐标与 3D 可视化

- 棋盘 PnP 求 `world←camera`，写 `world_frame.json`；
- 三维点转到 X 右 / Y 前 / Z 上；
- `traj3d.png` 之外，增加实时/离线 3D 面板（先 matplotlib，后 GUI）。

## 4. 明确不做

- **不在检测错误的数据上跑 Kalman/预测**：那只会得到"平滑的错误"。
- **不为了自动而自动**：P0 允许 `--seed` 人工初始化，先把数据跑通，再谈全自动。
- **不换哑光球**（用户已决定）；但 P0 验收必须真的套住球，不能拿"匹配率高"当成功。
- 不做深度学习检测器（没有标注数据；先把几何方法做到极限）。

## 5. 风险

| 风险 | 对策 |
| --- | --- |
| 镜面高光随视角变化 | 用圆周梯度/内外环对比，不用颜色阈值 |
| 背景有圆形物体 | 半径先验 + 时序 ROI + 速度门控 |
| 摆锤周期运动导致误配 | 闪光同步 + 左右半径比校验 |
| 检测丢失 | 上一帧预测 + 扩大 ROI；仍失败则标记 `matched=0`，不硬补 |
| 标定精度不足（极线 1.18 px） | 先接受；P4 前用更大板/更近重标 |
