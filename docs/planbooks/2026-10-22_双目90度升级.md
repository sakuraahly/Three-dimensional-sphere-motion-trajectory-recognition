## 1. 先说结论：90° 不是“把相机转 90°”这么简单

现有装置的基线是 **64.6 mm**，球在 **0.25–0.35 m**。如果两个相机光轴夹角
真的是 **90°**，并且对称地向内看同一个点：

```text
交会距离 D = 基线 B / 2
B = 64.6 mm  →  D ≈ 32 mm
```

也就是说，当前基线配 90°，两路只能在 **3 cm 左右**交会；球在 25–35 cm 时，
两路视野基本不重叠。反过来：

| 想要的交会距离 D | 90° 对称双目需要的基线 B |
| --- | --- |
| 0.3 m | 0.6 m |
| 0.5 m | 1.0 m |
| 1.0 m | 2.0 m |

**所以 90° 升级首先是一个机械/标定问题，不是软件开关。**
如果保留 64.6 mm 基线，球在 0.3 m 处对应的光轴夹角只有约 **12°**，不是 90°。

计划里必须先加一个“几何可行性”门禁：输入工作距离和基线，程序算出真实夹角；
不满足就明确拒绝，而不是让用户拍完才发现两路没有重叠。

## 3. 需要先确认的物理参数

实现前需要用户给出/实测：

1. **90° 的定义**：
   - 两个光轴夹角 90°（推荐对称：各与场景中线成 45°）；
   - 还是一台正对、另一台侧向 90°（非对称，重叠区更偏）；
2. **基线 B**：两相机光心距离；
3. **工作距离 D**：球轨迹中心到相机的距离；
4. **重叠区**：球全程是否都在两路画面内；
5. 相机是否刚性固定、是否能同时看到同一块标定板；
6. 标定板尺寸/可打印尺寸（当前 8×5、25 mm 方格，板占画面 3.7%，偏小）。

> 没有 2/3/4 的数据，软件只能做“支持 90° 的通用实现”，不能保证这套机械
> 装置能出可用的三维。

```json
{
  "stereo_mode": "parallel" | "angled",
  "rig": {
    "angle_deg": 90.0,
    "baseline_mm": 600.0,
    "working_distance_m": 0.30,
    "calibration": "calib/stereo_calibration_90.json"
  }
}
```

- 旧 session 没有 `stereo_mode` → `parallel`；
- 不改变 `schema/version` 的旧语义；新增字段可选；
- 数据管理导出 manifest 增加 `stereo_mode` / `angle_deg`，旧包仍可读。

### 4.2 坐标输出

- **平行模式**：保持 `coordinate_system = rectified_left_camera`，输出不变；
- **90° 模式**：`coordinate_system = left_camera`，原点仍是左相机光心，
  X 右 / Y 下 / Z 前；不做立体校正后再输出；
- 3D 查看器按 `coordinate_system` 显示轴标签，并在标题/状态显示
  `parallel` / `angled 90°`。

### 4.3 标定文件

`stereo_calibration.json` 增加：

```json
{
  "stereo_mode": "angled",
  "angle_deg": 90.0,
  "rectified": false,
  "R": [...], "T": [...],
  "K1": [...], "D1": [...], "K2": [...], "D2": [...],
  "quality": {
    "rms": 0.4,
    "epipolar_line_rms": 0.8,
    "n_pairs": 30,
    "median_triangulation_angle_deg": 88.0
  }
}
```

- 旧 JSON 没有 `stereo_mode` → `parallel`；
- `P1/P2/R1/R2/Q` 继续保留（平行模式需要），90° 模式不依赖它们；
- `baseline_side()` 的“左右装反”警告只对平行/水平基线有意义，
  90° 模式改用 `angle_deg` + 基线向量检查。

## 5. 标定方案（90° 的关键）

### 5.1 物理标定

- 标定板必须**同时完整出现在两路画面**；
- 推荐用比现在更大的板（或更近），让板占画面 ≥ 8–10%；
- 采集 30+ 对，覆盖：
  - 板在重叠区左/中/右；
  - 不同倾角（不要只正对一台相机）；
  - 不同距离（工作距离附近）；
- `stereoCalibrate` 本身支持任意 R/T，90° 不是算法限制；
  限制在**两路是否同时看得到板**和**板占画面大小**。

### 5.2 标定质量指标

平行模式看“校正后 epipolar y 误差”；90° 模式不能只看这个：

| 指标 | 90° 目标 |
| --- | --- |
| 重投影 RMS | ≤ 0.5 px |
| 极线（F 矩阵）线距离 RMS | ≤ 1.0 px |
| 有效标定对 | ≥ 25 |
| 中位交会角 | 60°–100° |
| 已知距离/已知板角的三角测量误差 | ≤ 10 mm @ 1 m（折算） |
| 重叠区覆盖率 | 球轨迹全程可见 |

### 5.3 标定 UI

在现有标定页增加：

```text
双目模式：[平行（现有）] [90°（新）]
夹角：90°（自动从 R 计算，不允许手填覆盖）
基线：600 mm
工作距离：300 mm
几何检查：✅ 重叠区足够 / ❌ 基线/距离不匹配
```

实时预览显示：

- 两路是否都检测到棋盘；
- 板占画面比例；
- 当前有效对/目标对；
- 90° 模式下显示“两路光轴夹角”和“预计交会距离”。

现有平行标定流程、按钮、参数**不删除**；只是多一个模式分页。

## 6. 重建方案

### 6.1 为什么不能直接复用现有 `match_epipolar`

现有 `StereoReconstructor`：

```text
左检测 -> 校正到 P1 -> 右候选校正到 P2 -> 比较 y 差
```

这套逻辑默认“校正后极线水平”。90° 相机仍可 `stereoRectify`，但校正图像
会严重旋转/拉伸，重叠区可能很小，检测框也会变形。

**计划采用两条路径：**

1. **parallel**：现有 `StereoReconstructor` 原样保留；
2. **angled**：新增 `AngledReconstructor`，不校正图像：
   - 用原始 `K1,D1,K2,D2` 把像素变成归一化射线；
   - 用 `R,T` 把右射线变到左相机系；
   - 用 `F = K2^-T [t]_x R K1^-1` 计算左点在右图的极线；
   - 右候选按“到极线的距离”匹配，不再比较 y；
   - 两条射线做最近点交会，输出左相机系 `(X,Y,Z)`；
   - 记录 `epipolar_px`（到极线距离）、`triangulation_angle_deg`、交会残差；
   - 交会角 < 10° 或残差过大 → 拒绝/降置信度。

### 6.2 新增/改动文件

```text
stereo/angled.py         新：F 矩阵匹配 + 射线三角测量
stereo/pair_source.py    保留；仅时间配对，不关心几何
calib/params.py          增加 mode/angle_deg/未校正三角测量方法
calib/stereo_calib.py    增加 90° 质量指标（极线线距离/交会角）
apps/run_stereo_video.py 增加 --stereo-mode angled 分支
apps/calibrate_stereo.py 增加 --stereo-mode angled
```

**不改**：`stereo/triangulate.py` 的平行模式实现；新增类并存。

### 6.3 单路丢失

90° 模式下两路视野差异更大，单路丢失更常见：

- 先用极线约束在另一路搜索；
- 失败则保留 2D 轨迹，3D 点标记 missing；
- 不把“单路可见”硬凑成 3D。

### 7.2 预览

- 左右预览并排，叠加：
  - 当前模式/夹角/基线；
  - “两路都看到球/棋盘”的指示；
  - 90° 模式下的重叠区提示（先做简化版：中心和边缘的安全框，不做像素级 mask）；

```text
输入：基线 B、工作距离 D
```

这个计算器比任何口头说明都更能防止“转完发现没重叠”。

- 会话列表状态列旁增加 `平行`/`90°` 徽标；

- 查看器标题显示 `90°`，轴标签按 `coordinate_system`；
- 旧会话显示 `平行`，打开行为不变。

## 9. 验收标准

### 兼容性

- 现有 23 个测试全部通过；
- 平行模式 A 会话结果不变（同 seed/同 pairing）；
- 旧 calibration/session/数据包无需改动即可打开；
- 不删除任何现有按钮/CLI/数据字段。

### 合成 90°

- 标定：重投影 RMS ≤ 0.5 px，极线线距离 ≤ 1.0 px；
- 配对率 ≥ 95%（重叠区内）；
- 三维 RMSE ≤ 10 mm @ 1 m（折算）；
- 交会角中位数 60°–100°。

### 真机 90°

- 标定报告明确“可用/勉强/不可用”；
- 静止已知距离球：重复性 ≤ 5 mm，深度误差 ≤ 2%；
- 球轨迹全程在重叠区，3D 无系统性跳变；
- 不达标时保留 parallel，不把 90° 结果当成功。

## 10. 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 基线/工作距离不满足 90° 几何 | 两路无重叠，标定都做不了 | P0 计算器 + 先量 B/D；不满足就改机械或改角度 |
| 标定板不能同时进两路 | 90° 标定无法进行 | 大板/近距/调整交会点；预览显示两路板检测 |
| 校正图像严重变形 | 旧 pipeline 不可用 | 90° 不走 rectified；用 F 矩阵 + 射线三角测量 |
| 单路丢失更频繁 | 3D 点稀疏 | 极线搜索 + 明示 missing，不硬凑 |
| 旧功能被改坏 | 回归 | 平行路径默认、独立 `AngledReconstructor`、旧 schema 默认值 |
| 相机不同步/掉帧 | 90° 对时间更敏感 | 时间戳配对默认（已转正）+ 丢帧门禁 |

## 11. 需要你确认的 4 个数

在开始写代码前，最好先给：

1. 两个光轴的夹角：**真的 90°**，还是“相机摆放大致成直角”？
2. 基线 B（两光心距离）大概多少 cm？
3. 球轨迹中心到相机的距离 D 大概多少 m？
4. 两路画面重叠区里，球是否**全程**都可见？

如果 B 仍是 6.5 cm、D 仍是 0.3 m，那 90° 在物理上不成立；
程序可以“支持 90°”，但这套机械装置产不出可用三维。这是这份计划最先要
说清的事。

## 12. 建议的落地顺序

```text
先量 B/D + 确认重叠
  ↓
P1 兼容层（旧 parallel 不变）
  ↓
P2 90° 标定（先合成，再真机）
  ↓
P3 90° 重建（F 匹配 + 射线交会）
  ↓
P4 UI 模式/几何提示
  ↓
P5 查看器/导出
  ↓
P6 真机验收；不达标回退 parallel
```

**在 P2 真机标定通过之前，不投入实时双目和大量 UI 美化** ——
否则很可能把一套物理上不成立的装置做得“界面很完整、数据不可用”。
