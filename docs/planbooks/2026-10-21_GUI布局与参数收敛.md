# GUI 布局与参数收敛计划（2026-10-21）

> 目标：解决“显示不全”，把「基本设置 / 高级设置」做成可展开收起，
> 并把第 2 步每个参数**到底影响哪个程序**说清楚；不删除任何旧功能。
>
> 先做 UI 结构与可读性，不改检测/标定算法。

---

## 1. 现状事实（980×780 实测）

- 主窗口固定 `980x780`，`minsize(880,560)`；没有按屏幕尺寸/位置自适应；
- 内容页实际高度约 **2131 px**，必须滚动才能看到工作台/日志；滚动条只有
  内容超出时才出现，用户容易以为“下面没了”；
- 第 1 步卡片高约 **900 px**，参数区是 `ttk.Notebook` 两个页签：
  「基本设置」「高级设置」——只能二选一，不能同时展开/收起；
- 第 2 步是 3 行平铺参数，**混用了单目/双目/实时/离线**的项；
- 头部原来用 `place` 固定右侧按钮和模式框；窗口本身大于屏幕/工作区时，
  右侧控件会随窗口一起出屏（实测旧版 980×780 外框 996×819，本机工作区
  底边 952，窗口底边 1000 被任务栏盖 48 px）；不是 `place` 本身导致出屏。

## 2. 第 2 步参数真实用途（审计结论）

| 控件 | 变量 | 谁在用 | 对双目会话 |
| --- | --- | --- | --- |
| 检测方法 | `self.method` | `run_realtime.py` / `run_video.py` / `run_stereo_video.py` / 工作台 | **用** |
| 颜色预设 | `self.preset` | 单目 `--preset` + 双目 `--preset` | **用**（仅 color 系） |
| 摄像头编号 | `self.camera` | 只传给 `run_realtime.py --camera` | 不用 |
| 球直径 | `self.diameter` | 只进 `_common_args()`（单目实时/离线） | 不用（双目用标定） |
| 预测视野 | `self.horizon` | 只进 `_common_args()`（单目） | 不用（双目预测关闭） |
| 焦距 fx | `self.focal` | 只进 `_common_args()`（单目） | 不用 |
| 启用三维估计 | `self.show_3d` | 只进 `_common_args()`（单目） | 不用（双目始终有 3D） |

**结论**：第 2 步不是“没用”，但它把**单目实时/离线**的参数和**双目**的参数
混在一起，且没有标注作用域。改法不是删除，而是：

> 审计补充：`_common_args()` 过去还无条件把 `--display-width`/`--no-3d`
> 传给 `run_video.py`，而该脚本不认这两个参数 → 离线视频会 argparse 失败。
> 本轮拆成 `_common_args(for_video=True)` 修复；`calib_fps`/`calib_backend`
> 也开始传给 `record_stereo.py`，不再“界面能设、录制不读”。

1. 常用区只放 `检测方法`、`颜色预设`（全流程都相关）；
2. 单目专用参数收进「高级（仅单目实时/离线）」折叠区；
3. 每个参数旁加作用域标签，例如 `仅实时`、`仅单目 3D`、`双目使用标定`；
4. 第 2 步标题改为「检测与测距参数（单目 / 双目共用）」并加一句
   “双目会话不使用球直径/预测视野/焦距，深度来自标定”。

## 3. 设计

### 3.1 屏幕自适应窗口

- 不再固定 `980x780`：按 **Windows 工作区**（`SPI_GETWORKAREA`，扣任务栏）
  计算：
  - 目标 `min(1180, work_w - 80) × min(820, work_h - 100)`；
  - 最小 `900×600`（若工作区更小则取可用尺寸）；
  - 居中显示，保证不越过工作区边界；
- 这样 1366×768 / 1920×1080 / 1024×768 都不会把右侧切出屏幕；
- 纯计算放 `apps/_gui_geometry.py`，可单测。

### 3.2 可展开/收起的设置区

新增可复用控件 `apps/_collapsible.py`：

```text
▾ 基本设置（常用）
   ...
▸ 高级设置（精度/排障）
   ...默认收起...
```

- 标题行是一个 `ttk.Button`，带 `▾/▸`；
- 展开后的内容有**可见边框**（用户能明确看出哪些参数属于这个折叠区）；
- `expand()/collapse()/toggle()`；
- 默认：基本展开、高级收起；
- 展开/收起不重建控件，状态不丢；
- 键盘：Tab 到标题，Enter/Space 切换；
- 不依赖 Launcher，可独立实例化。

### 3.3 第 1 步：替换 Notebook

- 删除（UI 层）`ttk.Notebook` 两个页签；
- 用两个 `CollapsibleSection`：
  - **基本设置（常用）**：目标/最少对数、板参数、分辨率/帧率；
  - **高级设置（精度/排障）**：停稳、清晰度、放宽、后端、基线、存图像对、验证图；
- 「运行标定 / 复检」和相机管理按钮仍在两个折叠区**之后**，不随折叠移动；
- 所有控件变量名保持不变，测试仍能访问；
- 默认基本展开、高级收起，页面高度立刻下降。

### 3.4 第 2 步：按作用域分组

```text
第 2 步 · 检测与测距参数（单目 / 双目共用）
  检测方法 [color]   颜色预设 [不使用]       ← 常用
  ▸ 高级（仅单目实时/离线视频）
      摄像头编号 / 球直径 / 预测视野 / 焦距 / 启用三维估计
```

- 常用区两项始终可见；
- 单目专用项默认收起，并标注作用域；
- 加一个「这些参数用在哪？」按钮，弹表格式说明（与本文 §2 一致）；
- 不改命令行参数、不删除控件。

### 3.5 显示/滚动

- 屏幕自适应窗口 + 页宽 reflow；
- 页顶加一行“当前模式 + 页面较长，可滚动”的提示（轻量）；
- 滚动条在内容超出时始终显示（不要只靠鼠标滚轮）；
- 卡片宽度按视口 reflow，避免右侧截断；
- 保留日志区内部滚动，不把整页无限撑高。

### 3.6 头部

- 不再用 `place` 固定右侧按钮；
- 改为 `brand`（左） + `actions`（右）两栏 `pack`；
- actions 放两行：
  - 第一行：双目模式下拉 + `基线夹角估算`；
  - 第二行：`数据管理`；
- 右上角按钮文字用完整「基线夹角估算」，不使用含糊的 `几何…` 省略号；
- 窄窗口时 actions 不会盖住标题/副标题，也不会被推到屏幕外。

## 4. 实施步骤与子 agent

| 步 | 内容 | 负责 | 验收 |
| --- | --- | --- | --- |
| P0 | 只读布局/参数审计 | 子 agent（只读） | 给出 file:line、屏幕尺寸证据、参数作用域表 |
| P1 | `apps/_collapsible.py` 可复用折叠控件 | 子 agent（单文件） | 自测：展开/收起/状态保持/键盘 |
| P2 | `apps/_gui_geometry.py` 窗口尺寸纯计算 | 子 agent（单文件） | 自测：1024/1366/1920、边界 |
| P3 | 头部改 pack 两栏 | 主 agent | 980/1024 宽不重叠 |
| P4 | 第 1 步换折叠区 | 主 agent | 基本开/高级关；变量/按钮不变 |
| P5 | 第 2 步分组 + 作用域说明 | 主 agent | 常用参数可见；单目参数收起 |
| P6 | 滚动/窗口自适应 + 回归 | 主 agent | 截图 + 20/23 测试 |

子 agent 只写自己的新文件；主 agent 负责 `启动程序.py`、测试、文档和提交。

---

## 5. 验收标准

- 1024×768、1366×768、1920×1080 下窗口完整落在**工作区**内（1366/1024
  的结论是 `fit_window` 纯函数 + 工作区算术；物理屏若不同需以实测为准）；
- 头部模式/数据管理按钮不重叠标题，不被切出屏幕；
- 第 1 步高级默认收起；展开后所有原控件都在，值不丢；
  注意：原 Notebook 高度本来按最大页计算，折叠主要改善“默认可见内容/可读性”，
  不会把整页从 2100 px 砍半（实测只降约 85 px）；
- 第 2 步明确标注每个参数作用域；单目专用参数默认收起；
- 旧功能/CLI/变量名不变；`启动程序.bat test full` 23/23 通过；
- 有截图/几何测量证据，不只“看起来好了”。

## 6. 明确不做

- 不改检测/标定算法；
- 不删除任何参数或按钮；
- 不重写整个 GUI 框架；
- 不做主题/皮肤大改；
- 不把日志/任务管理器搬出滚动页。
