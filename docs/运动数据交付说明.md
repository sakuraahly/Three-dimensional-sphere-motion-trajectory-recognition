# 运动数据交付说明（motion.csv / motion_meta.json）

给要用这份数据做**卡尔曼滤波 / Savitzky-Golay 滤波 / 轨迹识别**的人。

一句话：这份 CSV 里是**位置 + 速度 + 加速度**，以及「哪些点能一起算、哪些不能」的
显式标记。它不替你做滤波，但把滤波前必须知道的坑都写在列里了。

---

## 1. 怎么生成

```bash
python apps/tools/export_motion.py \
    --traj outputs/rec/20261103-093820-gui/traj3d.csv \
    --out  outputs/rec/20261103-093820-gui/motion.csv
```

产物是**两个文件**（同一目录）：

| 文件 | 内容 |
| ---- | ---- |
| `outputs/<会话目录>/motion.csv` | 逐点运动量，列序固定（见 §2） |
| `outputs/<会话目录>/motion_meta.json` | 源文件 / 点数 / 段列表 / 平滑参数 / 单位 / 坐标系 / 生成时间 / **已知局限** |

参数：

| 参数 | 默认 | 含义 |
| ---- | ---- | ---- |
| `--window-s` | `0.20` | Savitzky-Golay 窗口（**按秒**，不是按点数）。默认值是实测扫出来的拐点，见 `stereo/motion.py` 模块文档里的表 |
| `--poly` | `2` | 多项式阶数。2 阶能精确保留恒定加速度，3 阶开始把噪声也拟合进去 |
| `--max-gap-s` | `0.10` | 相邻点时间差超过它就断开成新段（30 fps 下 ≈ 3 帧） |
| `--no-smooth` | 关 | 不平滑，直接对原始位置差分。**只用于对照**，此时加速度基本是噪声 |

输入也接受 `traj3d.json`（读 `samples` 里的 `frame / t / xyz / matched`）。

退出码：`0` = 出了文件；`1` = 读不了（文件不存在 / 没有匹配点），原因打在 stderr。

## 2. 列含义与单位

| 列 | 单位 | 含义 |
| -- | ---- | ---- |
| `frame` | — | 源视频帧号（**不连续**：丢帧/未匹配的帧不在表里） |
| `t` | s | 时间戳（来自源 CSV，不是 `frame/fps` 算的） |
| `x` `y` `z` | m | 平滑后的位置（`--no-smooth` 时就是原始三角测量值） |
| `vx` `vy` `vz` | m/s | 速度分量 |
| `speed` | m/s | 速度模长（非负，等于 `sqrt(vx²+vy²+vz²)`） |
| `ax` `ay` `az` | m/s² | 加速度分量 |
| `accel` | m/s² | 加速度模长（非负，等于 `sqrt(ax²+ay²+az²)`） |
| `segment` | — | 所属连续段号，从 0 开始；`-1` = 单点段（凑不出差分） |
| `smoothed` | — | `true` = 该点参与了平滑；`false` = 段太短没处理（见 §4） |

**缺值写空串**（不是 `0`，不是字符串 `"nan"`）。会出现空串的场合：
单点段的速度/加速度、2 点段的加速度（二阶差分要 3 个点）。

> 读的时候请把空串当**缺失**，不要 `fillna(0)`。`0` 的意思是"真的静止在那里"，
> 那是另一件事实。

### 坐标系

**左相机系**（`traj3d.csv` 的口径）：相机在原点，

- `X` 向右（与图像 `u` 增大同向）
- `Y` **向下**（与图像 `v` 增大同向）
- `Z` 向前（沿光轴背离相机）

所以"球在下落"表现为 `y` 增大、`vy > 0`。做重力相关建模时 `g` 应作用在 **+Y**。
输入是 `traj3d.json` 时，坐标系以它自己的 `coordinate_system` 字段为准（已抄进
motion_meta.json 的 `frame.coordinate_system`）。

---

## 3. `segment` 怎么用（**最容易错的一条**）

实测这段数据：252 个匹配点、**10 段**、最长一段 84 点。段是这样切出来的：
相邻点时间差 > `--max-gap-s`（默认 0.10 s）就断开。

规则只有一条：**不同 `segment` 的点之间没有任何时间连续性假设。**

- 不许跨段做差分：跨着缺口算 `(p[i+1]-p[i])/dt` 会把"瞬移"当成"高速"，
  一次就能把 `|a|` 抬到几十 m/s²（本项目已经因此返工过）；
- 不许跨段连续滤波：卡尔曼的状态（`x` / `P`）在段边界必须**重置**，
  否则滤波器会拿缺口前的速度去解释缺口后的位置；
- S-G 也不许跨段：窗口跨过缺口，等于用"不存在的中间点"拟合。

本工具已经按段算好了 `v` / `a`（段内中心差分、段首尾单边差分），
你自己再做滤波时请**按 `segment` 分组**，别把整列当成一条序列。

---

## 4. `smoothed` 的含义

- `true`：该点所在段够长（≥ `poly+2` 个点，且能凑出窗口），参与了 S-G 平滑。
- `false`：段太短，**没被处理**。此时 `x/y/z` 是原始测量值，`v`/`a` 也来自原始值。

`smoothed=false` 的点不是"平滑过但看起来一样"，是"根本没处理" ——
要严格一致的精度，把这类点（连同它们所在的那一小段）单独处理或直接丢掉，
不要假装它们和别的点同质。

实测这段数据：`smoothed=true` 占 **97.6%**（246/252），其余是短段。

---

## 5. 加速度为什么不可信（除非你先滤波）

加速度是位置的**二阶**差分，噪声在每一步都被放大。这段数据的实测对照
（`20261103-093820`，0.75 m，30 fps，252 点）：

| 量 | 原始（`--no-smooth`） | 0.20 s 平滑后 |
| -- | --------------------- | ------------- |
| 速度中位 | 0.179 m/s | 0.172 m/s |
| 速度 p95 | 0.691 m/s | 0.534 m/s |
| 加速度中位 | 2.448 m/s² | 2.008 m/s² |
| 加速度 **p95** | **15.475 m/s²** | **7.874 m/s²** |

这段是一个约 **0.18 m/s** 的慢摆。一个慢摆的加速度 p95 是 15.5 m/s²，
比 1.5 个 g 还大 —— 那不是物理，是检测噪声。平滑后压到 7.9 仍偏高，
说明**剩余部分依然以噪声为主**。

结论：

- 原始 `ax/ay/az/accel` 只能当"尖锐程度"的指标，**不能当运动学量**；
- 平滑后的加速度可以看趋势，但**不要**拿它的瞬时值去标定物理模型；
- 如果要用到加速度，先自己再做一层滤波（S-G 或卡尔曼），并在报告里写明窗口。

---

## 6. 时间戳不是严格等间隔（滤波前先重采样）

实测相邻匹配点的时间差：中位 **33.2 ms**、p95 **66.4 ms**、最大 **464.9 ms**
（最后这个就是段边界）。30 fps 的理论间隔是 33.3 ms —— 也就是说 p95 处在
"每隔几帧就丢一帧"的状态。

Savitzky-Golay 的系数表**假定等间隔**。不等间隔直接套，窗口在时间上忽长忽短，
转折处会过冲。所以：

> **先按段用 `stereo.motion.resample_uniform(t, P, dt)` 重采样到固定 `dt`
> （取该段的中位间隔），再滤。**

卡尔曼对不等间隔是天然支持的（`dt` 进状态转移矩阵），只要你别把 `dt` 写死成 1/30。

---

## 7. 不要做的事

1. **不要跨段插值把缺口填平。** 缺口里填一条直线 = 造出一段"不存在的匀速运动"，
   卡尔曼会把它当真观测吃进去，之后的速度估计会被带偏很久。
   缺口就是缺口：要么按段各滤各的，要么显式建模"这段时间没有观测"。
2. **不要把空串读成 0。** 见 §2。
3. **不要跨 `segment` 连续跑一个滤波器。** 见 §3。
4. **不要拿未平滑的 `accel` 下结论。** 见 §5。
5. **不要用 `frame/fps` 重算时间。** 帧号是源视频的，丢帧后它与 `t` 不再成比例
   （`t` 才是真的时间）。

## 8. 最小可用示例（读 CSV → 按段 → 重采样 → S-G → 速度）

```python
import csv
import numpy as np
from scipy.signal import savgol_filter
from stereo.motion import resample_uniform        # 项目自带，别自己再写一份

def load_by_segment(path):
    """按 segment 分组；空串字段不读（本示例只用位置）。"""
    groups = {}
    with open(path, encoding="utf-8", newline="") as f:
        for row in csv.DictReader(f):
            seg = int(row["segment"])
            if seg < 0:                 # 单点段：凑不出差分，丢掉
                continue
            groups.setdefault(seg, []).append(
                (int(row["frame"]), float(row["t"]),
                 float(row["x"]), float(row["y"]), float(row["z"])))
    return groups

WINDOW_S, POLY = 0.20, 2            # 与 export_motion 默认一致

for seg_id, rows in sorted(load_by_segment("motion.csv").items()):
    if len(rows) < POLY + 2:
        continue                    # 段太短，S-G 凑不出窗口：明确跳过，不硬凑
    t = np.array([r[1] for r in rows])
    P = np.array([r[2:] for r in rows])          # (N,3) 米

    dt = float(np.median(np.diff(t)))            # 这一段自己的采样间隔
    tu, Pu = resample_uniform(t, P, dt)          # ① 先等间隔（S-G 假定等间隔）

    win = int(round(WINDOW_S / dt)) | 1          # ② 窗口按秒换算成点数，取奇数
    win = max(POLY + 2, min(win, len(tu) if len(tu) % 2 else len(tu) - 1))
    Ps = np.column_stack([savgol_filter(Pu[:, k], win, POLY, mode="interp")
                          for k in range(3)])

    V = np.gradient(Ps, tu, axis=0)              # ③ 段内求导（边界是单边差分）
    speed = np.linalg.norm(V, axis=1)
    print(f"段 {seg_id}: {len(rows)} 点，|v| 中位 {np.median(speed):.3f} m/s")
    # 卡尔曼在这里初始化/重置：一个 segment 一个滤波器实例
```

要点就三个：**按段分组**、**先重采样再滤**、**每段重置滤波器**。

## 9. 已知局限（motion_meta.json 的 `known_limitations` 里也有一份）

1. 只含 `matched=1` 的点，未匹配帧直接缺席，不补齐。
2. 段首尾是单边差分，精度比段内低一档。
3. 加速度噪声占主导（§5 有数）。
4. 时间戳非严格等间隔（§6 有数）。
5. `smoothed=false` 的点没被处理过。
6. 三角测量本身的深度误差（标定给出 σ ≈ 3.85 mm @ 0.6 m）不在本文件的统计里 ——
   这份 CSV 只描述"点列的差分"，不描述"点本身有多准"。

口径的唯一来源是 `stereo/motion.py`（平滑/求导只有这一处实现）与
`apps/tools/export_motion.py`（列序与空串口径）。两者改了，本文档必须跟着改。
