## 1. 总览：从光子到三维轨迹

```
   左相机 ─┐                                        ┌─ 二维检测 ─ 亚像素圆心 ─ 卡尔曼跟踪 ─┐
           ├─ 时间戳同步 ─ 左右配对 ─ 去畸变 ──────┤                                       ├─ 三角测量
   右相机 ─┘                                        └─ 二维检测 ─ 亚像素圆心 ─ 卡尔曼跟踪 ─┘
                                                                                          │
                                         单目球径先验深度 ── 逆方差加权融合 ───────────────┤
                                                                                          ▼
                                                    逐帧 (t, X, Y, Z) → 等间隔重采样 → S-G 平滑
                                                                                          │
                                                                    ┌─────────────────────┴───┐
                                                                    ▼                         ▼
                                                             速度 / 加速度导出        自适应窗口预测
                                                                                          │
                                                                                          ▼
                                                                     traj3d.json / visualization.json
```

**两条独立的深度来源**：双目视差（主）、单目球径先验（辅）。其余环节（检测、跟踪、平滑、预测）在两条链路上共用。

关键设计取舍：

- **检测与几何解耦**：`sphere_tracker/` 只管"在单张图里找到球"，不知道有几台相机；`stereo/` 只管"把两路观测合成为三维点"。这样单目链路可以单独跑，双目链路也能换检测器。
- **坐标契约单一**：内部一律用左相机系，只在导出那一刻可选地转世界系，避免多处各自发明坐标。
- **参数可插拔**：检测器通过注册表选择（`plugins.py`），标定方法通过 `CalibConfig.method` 选择，装置参数通过 `stereo/profiles.py` 的档案切换。

## 3. 坐标系与坐标契约

全项目唯一约定：**X 向右、Y 向下、Z 向前（相机光轴）**，单位米，原点在左相机光心。

```
        Y ↓
          │
          │      Z →（画面深处）
          │    ╱
          │  ╱
          O ─────────→ X
      (左相机光心)
```

| 装置模式 | 原点 | 是否立体校正 | 深度求法 |
| --- | --- | --- | --- |
| `parallel` | **校正后**的左相机光心 | 是 | `Z = f·B/d` |
| `angled` | **原始**左相机光心 | 否 | 去畸变射线最近点交会 |

硬约束（写进 `docs/主线.md` 的坐标契约）：

1. 内部计算一律 `left_camera`；只在**导出那一刻**转 `world`。
2. `rectified_left_camera` 是 `parallel` 的历史产物，只对当前那份 parallel 标定有效，不要再新增消费者。
3. 没有 `world_frame.json` 时，导出必须写 `coordinate_system="left_camera"` 并注明"未设置世界系"，**不许静默当世界系**。
4. `parallel` 与 `angled` 的 `xyz` 不得混进同一条轨迹。

世界系是可选的：用一张左相机拍到的棋盘图做 PnP，求 `T_world_cam`，落盘 `world_frame.json`（`calib/world_frame.py` + `apps/tools/set_world_frame.py`），导出时把坐标转过去并标记 `world`。

图示见 [`坐标系统图.png`](坐标系统图.png)。

## 4. 相机模型：针孔投影与去畸变

针孔模型（`sphere_tracker/geometry.py::CameraModel`）：

$$
u = f_x \frac{X}{Z} + u_0, \qquad v = f_y \frac{Y}{Z} + v_0
$$

反投影（已知深度求三维点）：

$$
X = \frac{(u-u_0)Z}{f_x}, \qquad Y = \frac{(v-v_0)Z}{f_y}
$$

`CameraModel.backproject(u, v, z)` 就是它。注意几个实现细节：

- `fₓ ≤ 0` 时用水平视场角 `hfov_deg` 估焦距；`fᵧ ≤ 0` 时**直接令 `fᵧ = fₓ`**（不按图像纵横比另算）；主点为负时取图像中心。
- `calibrated` 标志只看 `fₓ`。
- 径向/切向畸变由标定的 `D` 描述，三角测量前必须先对像素做去畸变，否则射线方向系统性偏移。
- 两路相机的像素尺度必须一致：不同分辨率或不同 FOV 直接拿来做极线配对会污染视差（`stereo/fov_align.py` 专门处理这件事）。

单目深度先验也挂在这个类上：

$$
Z = \frac{f \cdot D_{ball}}{2r}, \qquad f = \frac{f_x + f_y}{2}
$$

`depth_from_radius()` 用它。它对球径和像素半径都敏感（`Z ∝ 1/r`），所以只作为弱观测参与融合。

## 5. 双目几何：两条路

### 5.1 平行双目（`parallel`）

立体校正后，左右同名点落在同一条水平扫描线上。设基线 `B`、焦距 `f`、视差 `d = u_L − u_R`：

$$
Z = \frac{fB}{d}, \qquad X = \frac{(u_L-u_0)Z}{f}, \qquad Y = \frac{(v_L-v_0)Z}{f}
$$

实现：`stereo/triangulate.py`、`stereo/depth_fusion.py::stereo_depth()`（视差取绝对值，`d=0` 返回 `inf`）。

**误差随深度平方放大**：对 `d` 求微分

$$
\left| \delta Z \right| \approx \frac{Z^2}{fB}\,\delta d
$$

所以远处 1 px 的视差误差，代价远大于近处。这也是为什么基线不能太小、分辨率不能太低、远处结果要谨慎解读。

### 5.2 大角度双目（`angled`，近似 90°）

两路光轴接近垂直、几乎没有共视区域，常规 `stereoCalibrate` 拿不到可靠外参，也不能做有意义的 `stereoRectify`。项目改用**射线交会**：

1. 用各自的 `K, D` 把 `(u, v)` 去畸变，再反投影成归一化方向；
2. 左射线 `P_L(s) = O_L + s·d_L`，右射线 `P_R(t) = O_R + t·d_R`，其中 `O_R, d_R` 由外参 `R, T` 变换到右相机再转回左系；
3. 求两异面直线的**最近点对**，取中点为三维点；
4. 用最近点距离作为交会质量：距离过大说明配对或外参有问题。

实现：`stereo/angled_geometry.py::triangulate_pixels()`、`stereo/angled.py`。

这里**不再**使用"校正后 y 差"或单一 `Z=fB/d`。输出必须标 `stereo_mode=angled`、`coordinate_system=left_camera`。

### 5.3 极线约束能约束什么、不能约束什么

`stereo/joint_refine.py` 里有一条重要观察：极线约束只约束 `v`（竖直方向），**`u`（视差方向）没有任何跨视图约束**。而球的圆弧在视差方向上的切线若沿 `u`，1 px 的圆心横向误差就是 1 px 的视差误差，深度会偏掉几个百分点。所以该模块只允许在有证据的地方调整 `u`。

## 6. 标定：内参、外参与两条分支

标定模块在 `calib/`，入口 `apps/calibrate_stereo.py`。棋盘内参用 OpenCV 的 `calibrateCameraExtended`（张正友平面标定法），外参用 `stereoCalibrate`。

### 6.1 `joint` 分支（共视充足时默认）

每轮迭代（`R = 1..4`）做：

1. **各自单目标定** `_calibrate_one()` → `K₁,D₁ / K₂,D₂` + 逐图重投影 + 内参标准差；
2. **定外参** `stereoCalibrate(flags=CALIB_FIX_INTRINSIC)` → 只优化 `R,T`，各帧板位姿自由；
3. **整体精化** `stereoCalibrate(flags=CALIB_USE_INTRINSIC_GUESS)` → `K,D,R,T` 与板位姿一起最小化，**仅当 RMS 下降才采用**；
4. **立体校正** `stereoRectify(CALIB_ZERO_DISPARITY, alpha)`；
5. **极线误差** 校正后同名点的 `v` 之差，逐对统计；
6. **离群剔除** `per_pair = max(左右重投影误差, 极线误差)`，阈值 `max(median + 3×1.4826×MAD, 0.5px)`，剔除后重算；剩余少于 8 对则停；
7. 取 RMS 最小的那一轮作为结果。

**保护**：`angled` 且共视对少于 8 时直接抛错拒收，不输出似是而非的参数。

质量判定是四级（优秀 / 可用 / 勉强可用 / 不可用），并有硬条件：棋盘占画面比例小于 8% 不许判"优秀"。落盘 `quality{rms, fx_sigma_px, depth_sigma_mm_at_0_6m, ...}`。

### 6.2 `chain` 分支（大角度 / 零共视时的唯一合法路）

90° 装置没有共视对，`joint` 求不出 `R,T`。链式标定用**一块板在不同姿态下分别约束两台相机**，把"相机 A ↔ 板 ↔ 相机 B"的变换串起来，再单独拍一组**参考段**（板不能动）来锁定相对位姿：

```
左内参段  →  板的位姿链  →  右内参段  →  参考段（板不动）  →  R, T
```

拍图时的覆盖要求（五个角、姿态分化等）和 `check_chain_inputs.py` 的自检，见 [`真机标定操作清单.md`](真机标定操作清单.md) 与 [`标定算法对比.md`](标定算法对比.md)。

### 6.3 世界系（可选）

`calib/world_frame.py` 用 PnP 从一张左相机棋盘图求 `T_world_cam`，落盘 `config/world_frame.json`。导出时若存在就把 `left_camera` 转成 `world`，否则保持并显式标记。

> 标定结果属于"这台相机 + 这个机位"的参数，`config/` 整个目录不入库。换机器、挪相机、重插导致外参变化，都要重标。

## 7. 图像同步与左右配对

`stereo/sync.py`、`stereo/timestamp_pair.py`、`stereo/pair_source.py` 负责把两路帧按时间对齐。

- 每帧带时间戳；配对时找时间差最小的左右帧，超过容差就丢弃而不是硬凑。
- **帧率必须一致**：帧率不同会让配对在时间上系统漂移；采集档（分辨率 + 帧率）由装置档案锁定，标定图与录制必须用同一档。
- 单张图片做不了双目（一帧没有视差），`pair_source.py` 会给出明确提示而不是笼统的"不是文件夹"。
- 录制后 `session.json` 记录帧数与采集档，数据管理界面据此判定会话状态（已录制 → 已点选 → 有三维）。

## 8. 二维球检测

`sphere_tracker/detectors/` 通过注册表（`plugins.py`）提供多种实现，可单独用，也可投票融合：

| 后端 | 依据 | 适用 |
| --- | --- | --- |
| `color` | HSV 颜色阈值 + 连通域 + 圆度筛选 | 默认，纯色哑光球、光照稳定 |
| 梯度 / 几何 | 圆边缘径向梯度一致性、Hough | 颜色不可靠但有清晰轮廓 |
| 背景差分 | 帧间变化区域 | 静止相机、背景稳定 |
| 融合 | 每个成员交 top-K 候选，按中心聚类后按"不同成员数"投票 | 复杂场景 |

`color` 的取色有三种入口：固定预设（`--preset red_ball`）、自动估主色
（`--preset auto`，不需要点选）、人工种子（点选球心后从点击环取色并锚定半径）。
同色多候选时按"上一帧位置 + 速度"裁决 top-1；训练/调参边界见
[`纯色球检测方案.md`](纯色球检测方案.md) §9。

检测结果统一为 `Detection`（圆心、半径、置信度等，字段见 `API.md` 第 4 节）。

调参与各后端的实测边界见 [`纯色球检测方案.md`](纯色球检测方案.md)：颜色阈值可先用预设 /
`--preset auto` / 点选球心取色，再用 `calibrate_color.py` 看掩膜微调；强高光、透明球、
同色背景是主要失效模式（同色背景现在会由 `last_error` 明确说出来，不再静默 0 检出）。

## 9. 亚像素细化与圆拟合

`geometry.py` 提供：

- `fit_circle_taubin()`：Taubin 代数圆拟合，少于 3 点抛错；
- `fit_circle_robust()`：迭代修剪离群点（`trim_sigma=2.0`），点数少于 5 时退回 Taubin；
- `refine_circle_subpixel()`：从粗圆心沿 `n_rays=72` 条径向射线，在 `±search` 范围内以 `step=0.25 px` 找梯度峰值，再重新拟合圆；
- `refine_circle_subpixel_checked()`：同上，但多返回一个"是否真的细化成功"的布尔。

**重要陷阱**：`refine_circle_subpixel()` 失败时**不抛异常，而是原样返回输入**（半径太小、采样越界、有效射线不足时）。要判断成功与否必须用 `checked` 版本的布尔，不要去比浮点相等。

半径的亚像素精度直接决定单目深度（`Z ∝ 1/r`），也影响圆心的横向定位，进而影响视差。实测半径误差可从 0.4–0.5 px 降到约 0.06 px。

## 10. 二维跟踪：卡尔曼与关联

`sphere_tracker/track.py`：

- `KalmanFilter(order=2)`：状态含位置、速度、加速度（6 维；`order=1` 为 4 维），过程噪声 `q`、量测噪声可自适应；
- `innovation()` / `mahalanobis()`：新息与马氏距离，用于卡方门控；
- `adapt_noise()`：机动时抬高 `q`；`reinitialize()`：反弹或突变后带着速度重初始化；
- `Track`：`predict_to(t)` / `update()` / `coast()`，`misses > max_coast_frames` 判死；
- 关联分两轮：**紧关联**（半径一致 + 卡方门控）→ **抢救关联**（距离门限内命中则把 `q` 顶到上限）；两轮都没配上的检测立刻新建轨迹。

实现细节（会影响结果解释）：

- `update()` 第一步对所有轨迹 `predict_to(t)`，因此 **时间必须单调不减**，否则速度/加速度失真。
- 半径门控与卡方门控只在 `hits >= init_hits` 后生效。
- `TrackState` **不填 `z/vz`**；三维量在 `stereo/` 侧产生。
- `q_max = q_base × 64` 与半径 EMA 的 `alpha=0.5` 是硬编码；半径滞后会直接变成单目测深误差。

## 11. 深度融合：双目视差与单目球径

`stereo/depth_fusion.py` 把两路独立深度按**逆方差加权**合成：

$$
\hat Z = \frac{Z_s/\sigma_s^2 + Z_m/\sigma_m^2}{1/\sigma_s^2 + 1/\sigma_m^2}
$$

其中 `Z_s = fB/|d|` 是双目视差深度，`Z_m = f·D_ball/(2r)` 是单目球径深度。双目权重通常远大于单目，单目主要在视差不可靠时提供弱约束。

单目链路的实测（合成真值）深度误差约 0.31%、3D RMSE 约 15 mm；双目链路不依赖球径，是主用路径。两者适用的物理量不同，不要把单目精度数字套到双目结论上。

## 12. 轨迹平滑

`stereo/motion.py` 提供 Savitzky–Golay 平滑（导出为 `savgol_trajectory`）。

**关键前提**：S-G 的卷积系数表**假定采样等间隔**。真实录制的时间戳往往不均匀，直接套用会让窗口在时间上忽长忽短，平滑出的速度与加速度失真。所以流程是：

```
不等间隔 (t, xyz)  →  等间隔重采样  →  S-G 平滑  →  速度 / 加速度
```

这也是 `export_motion.py` 导出运动量时要把时间段切开、缺值写空串的原因；口径见 [`运动数据交付说明.md`](运动数据交付说明.md)。平滑只影响显示与导数，**原始采样点始终保留**，3D 查看器里可以同时看到平滑曲线与真实采样点，用来判断平滑抹掉了哪些抖动。

## 13. 轨迹预测

`sphere_tracker/predict.py` 提供两类：

- **`predict_quadratic()`**：在轨迹尾部做自适应窗口二次拟合。核心是"最长有效后缀搜索"——逐段丢掉最老的点，取第一个拟合残差合格的窗口，从而自动跳过机动/反弹之前的数据。已知重力时二次项固定为 `g/2`，未知数从 3 降到 2，最少点数可降到 2。
- **`predict_kalman()`**：直接用 `TrackState` 做匀加速外推，忽略轨迹历史。

要点：

- 返回数组的**第一个点是当前时刻 `t+0`**，不是"未来第一个采样"。
- 至少 3 个点才出结果（已知重力时可放宽）；时间轴以 `t_now` 为基准，传 `state.t` 才是从当前帧出发。
- `dims=3` 时 **Z 轴强制线性**——给深度做二次外推会算出负深度。
- `residual_tol` 在 2D 是像素、在 3D 是米，pipeline 按 `tol_px × Z / f` 换算，手调时容易搞错量纲。
- 2D 预测里若高分点数 ≥ 4，只用这些"真观测"拟合，丢掉 coast 出来的点。

三维侧的预测在 `stereo/predict3d.py`。

---

## 14. 相机自运动补偿

`sphere_tracker/camera_motion.py` 处理手持 / 云台 / 平移拍摄：用背景特征估计帧间相机运动，把球心校正到稳定的参考系，再做跟踪与半径判据。

实测（项目自测）：平移拍摄下半径误差从 1.58 px 降到 0.23 px。固定三脚架时可以不开，但相机被碰动会直接破坏标定外参——那是另一类问题，只能重标。

## 15. 误差传播：精度从哪里来、又丢在哪里

按影响从大到小：

| 来源 | 机理 | 缓解 |
| --- | --- | --- |
| 标定外参 / 棋盘尺寸 | `R,T` 或方格边长错 → 深度整体缩放或系统性偏差 | 打印后用尺核对方格；录制前 `verify` 复检 |
| 视差量化 | `δZ ≈ Z²/(fB)·δd`，远处放大 | 增大基线、提高分辨率、缩短工作距离 |
| 圆心定位 | 1 px 横向误差 = 1 px 视差误差 | 亚像素细化、多帧融合 |
| 两路像素尺度不一致 | FOV / 分辨率不同污染视差 | 同型号相机、同一采集档，`fov_align` 校正 |
| 同步误差 | 球在两帧之间移动 → 配对到不同位置 | 锁帧率、丢帧即弃、不硬凑 |
| 球径先验（单目） | `Z ∝ 1/r`，半径与球径误差直接放大 | 只作弱观测参与融合 |
| 平滑 / 预测外推 | 不等间隔、窗口跨机动点 | 等间隔重采样、自适应后缀搜索 |

**结论**：三维精度主要由"标定质量 + 视差精度"决定，检测器再准也救不回错误的外参。所有精度数字都应连同标定质量、工作距离、分辨率一起报告。

## 16. 数据格式与坐标标记

`derived/traj3d.json` 是标准轨迹产物，`derived/visualization.json` 是 3D 查看器直接读的数据。每个点带 `frame / t / xyz`，文件级带：

```jsonc
{
  "stereo_mode": "parallel | angled",
  "coordinate_system": "left_camera | world",
  // 未设置世界系时必须显式说明，不许静默当 world
  "capture_size": [1920, 1080],
  "fps": 30
}
```

`visualization.json` 里的 `trajectory` 每个点就是一次 matched 的真实采样帧位置（不是插值点），3D 查看器据此画采样点并支持点击查看该帧的 `(X, Y, Z)`。字段的精确定义见 [`数据标准.md`](数据标准.md)。

## 17. 已知局限与不适用场合

- **不是通用三维重建**：只针对球形目标，依赖"球在两路画面里都可见且圆心可测"。
- **不是世界系**：默认输出是左相机系；跨会话比较前必须确认坐标系标记一致。
- **强高光 / 透明 / 同色背景**：默认颜色后端会失效，需要换梯度后端或改善光照与背景。
- **远距离小基线**：误差随 `Z²` 增长，超出工作距离后数字不可信。
- **大角度装置零共视**：必须用 `chain` 标定，拍图流程比 `joint` 严格；参考段板不能动。
- **时间戳不均匀**：直接做 S-G 平滑会失真，必须等间隔重采样。
- **预测不跨越机动**：自适应窗口只拟合"最近一段有效运动"，碰撞/反弹之后的长期预测需要物理模型，不在当前范围内。
- **世界系的入口在「工具 · 标定与训练…」第 ③ 张卡**（命令行 `apps/tools/set_world_frame.py`，
  消费端是 `run_stereo_video.py --world-frame`）。符号（`z` / `-z`）必须人确认，
  `-z` 会把 Y 一起反向；`parallel` 的校正系不支持变换，会拒绝并说明原因。
