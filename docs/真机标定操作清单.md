## 0. 先确认：你现在到底有几台**独立**相机

这一步没做，后面全是白费。上次的教训是"以为在标两台，其实条件根本不成立"。

```powershell
启动程序.bat check          :: 看设备列表与角色漂移
启动程序.bat setup          :: 逐个画面确认「左 / 右 / 无关」
```

⚠️ **这台笔记本自带两个"相机"**（`Integrated Camera` 与 `Integrated IR Camera`），
但**只有一个能出彩色画面**（实测 IR 那台打不开）。所以：

- **只有内置摄像头 = 无法做双目标定**（需要两台**同时看到同一片区域**的独立相机）。
- 两台 USB 相机必须能**刚性地固定在同一根支架上**，且视野重叠。
- 内置摄像头曾被标为「无关」。若你想用它凑一台：
  `启动程序.bat setup` 或 `python apps/tools/cameras.py unignore --all`。

**基线（两镜头中心距）决定了深度精度**：`Z ≈ f·B/d`。同样的视差误差下，
基线越小、深度误差越大。所以：
- 内置摄像头旁挂一个外接 = 基线只有几厘米 → 深度精度很差；
- 建议两台同型号外接，基线 **60~200 mm**，**量准它**（下一步要用）。

## 1. 标定板与"够不够大"

命令里三个参数必须和**手上那张纸**完全一致：

```powershell
--cols 8 --rows 5 --square 25
```

- `8 × 5` 是**内角点数**，对应 **9 × 6 个方格**。**数错一个，角点全找不到**。
- `--square 25` 是**方格实际边长（毫米）**。自己打印的话必须**用尺子量**，
  不能信"设置里写的是 25mm" —— 打印机缩放会让它变成 24.6 或 25.4，直接进标定结果。

**距离不是瓶颈**（实测门限 `min_area_ratio = 1.2%`）：

| 物距 | 棋盘在画面里的占比（1280×720，9×6 方格 × 25mm） |
| ---- | ---------------------------------------------- |
| 400 mm | 22.9% ✅ |
| 600 mm | 10.2% ✅ |
| **900 mm** | **4.5% ✅ 仍然远超门限** |

也就是说：**收不到帧时，几乎不是"板太小/太远"，而是下面第 3 条。**
一张 A4 大小（9×6 × 25mm ≈ 225×150mm）的板在 60~90cm 都能用；
想要更高的角点定位精度可以让它占画面 10~30%（约 40~60cm）。

## 2. 最容易被忽略的一条：**必须给 `--baseline-mm`**

```powershell
--baseline-mm 65      :: 换成你实际量到的毫米数
```

**不给它，基线核对就是关着的。** `CalibConfig.expected_baseline_mm` 默认 `None`
（`calib/stereo_calib.py:47`），所以那段核对代码（`:272-276`）**一次都不会执行**。

上次真机就是这样：算出基线 **199.67 mm**、实际间距 **65 mm**（**3.07 倍**），
而日志里**只有 2 条警告、没有基线那条** —— 护栏一直在，只是从没被启用。

量法：**两镜头中心**的距离（不是外壳边缘、不是支架孔距）。

## 3. 收帧时你会看到的拒收提示，以及每一条怎么办

门限（`calib/capture.py`，全部是默认值）：

| 提示（现场文案） | 门限 | 怎么办 |
| ---------------- | ---- | ------ |
| **`棋盘还在移动，请停稳再收`** | 帧间位移 < **3 像素** | **上一轮 58.3% 的拒收是这条。** 见下面 👇 |
| `图模糊(清晰度 NN)` | Laplacian 方差 ≥ **55** | 增加光照、别抖、对焦；别用长曝光 |
| `图棋盘太小(N.N%)` | 占画面 ≥ **1.2%** | 靠近一点（900mm 都还够，所以一般不是这条） |
| `图棋盘贴边(NNpx)` | 角点离边 ≥ **10 px** | 把板往画面中间挪 |
| `图曝光不合适(NN)` | 灰度均值在 **35~230** | 太暗加光；过曝避开直射灯/窗户 |
| `与已收位姿太接近` | 位姿差 ≥ 0.055 | 换个角度/位置，别只平移一点点 |
| `该区域已收够，请换个位置` | 3×3 宫格，**每格最多 5 对** | 要覆盖画面九个区域，不是堆在一处 |
| `两路角点出身不同（左 X / 右 Y）` | 硬门禁 | 见第 5 条 |

### 「棋盘还在移动」是**物理问题，不是软件问题**

3 像素在 1920×1080 上是**画宽的 0.16%**，时间窗是**两帧之间（约 33 ms）**。
**33 毫秒内手持一块板位移不超过 0.16% 画宽，人做不到** —— 这跟"手稳不稳"无关。

**正确做法**：

1. **板要靠在硬支撑上**（墙、书挡、三脚架、桌面支架），不要悬空手持。
2. 板**移到位 → 停住**，而不是"慢慢移动着让它收"。
   这条门限的**目的**是"两路在同一时刻拍到同一个位姿"（两台相机没有硬件同步，
   静态目标是唯一替代手段）—— 所以**必须真的静止**，不是"动得慢"。
3. 实在够不着（例如板只能手持）：用 `--stationary-px 8`，
   **但别超过 ~12** —— 这条门限同时替代了左右同步，
   放太松会让两路拍到不同位姿，**解出的 R/T 会系统性偏**，
   而且偏得很隐蔽（标定照样"成功"）。
4. `--relaxed` 是最后手段：它一次放松 6 条门限（停稳 10px、清晰度 28、更小的板…），
   **是拿精度换成功率**。用完必须复检极线误差，不达标就退回默认重标。

### 要收多少对

```powershell
--target 25 --min-pairs 10     :: 正式标定
```

- 默认是**试标定档** `--target 8 --min-pairs 8`（够验证通路，**不够出正式三维结果**）。
- 还有一道隐藏门限：`min_pairs_after_reject = 8`
  —— 标定会先剔掉外点，**剔完不足 8 对就直接拒绝**。所以 `--min-pairs 10`
  给剔除留了余量，**别再往下调**。

## 4. 全程一定要加 `--save-pairs`

```powershell
--save-pairs outputs/calib_pairs
```

**上次最大的遗憾就是这个**：数据出问题时，图像没存，只剩日志，
于是无法回答"到底是哪一对错了"。存下来之后：

- 可以**离线重标**（把两个文件夹喂进去），不用再举一次板；
- 可以逐对看图找问题（哪一对明显不同步 / 模糊 / 板歪）；
- 万一以后要做 ChArUco 对比实验，**这批图就是基线数据**。

顺带把验证图也存了：

```powershell
--report-png outputs/calib_report.png
```

## 5. 检测器混用：已在代码里挡住，但你要知道它存在

`findChessboardCornersSB` 与经典 `findChessboardCorners` 返回的角点顺序
**恰好整体反序**（= 8×5 点阵的 `rot180`）。

- **单目标定对它免疫**（反序也是一组自洽对应）→ **每一路各自看起来都正常**；
- **双目标定不免疫**：一路 SB、一路经典 → 同名下标不是同一物理角点
  → 合成的 R/T 是垃圾，**而它不会报错**。

现在 `calib/capture.py` 有**两道守卫**（`:224` 粗检后、`:302` 精确复核后），
发现两路出身不同会**当场拒收**并说明。所以这件事你不会再静默吃亏。

**但请留意日志里的"回退"字样**：回退（SB 找不到 → 退经典）是**显式允许**的，
只是不允许**一对之内混用**。若你看到大量回退，说明画面质量有问题
（SB 对模糊更敏感），值得回头查光照/对焦。

## 6. 出结果后看什么（顺序很重要）

标定完会打印判定。按这个顺序看：

1. **基线核对** —— 与实际量到的间距比。**偏差 > 20% 会直接告警**（前提是给了 `--baseline-mm`）。
   **这一条最能说明"对应关系对不对"**：对应错配会把基线吹到真值的 8~15 倍。
2. **极线误差（epipolar RMS）** —— 目标 **< 0.3 px**。
   `good_epipolar = 0.25` / `ok_epipolar = 0.60`：超过 0.60 直接判不可用。
3. **整体 RMS** —— ⚠️ **它抓不到角点顺序错**（实测：整份反序时 RMS 只有 2e-6 px 的变化）。
   **别只看 RMS 就放心。**
4. 每个宫格的覆盖情况（板有没有只在一个角落收满）。

**不可用就不保存**（`apps/calibrate_stereo.py:397`）—— 这是有意的，别绕过它。

标定成功后：

```powershell
启动程序.bat verify         :: 复检：装置有没有被碰动
```

⚠️ **复检要在"同一对物理相机"上做**。落盘时写的是**请求的**相机编号
（`apps/calibrate_stereo.py:405-406`），不是实际打开的那两台 ——
所以**自己记下这次用的是哪两台**（换过相机/用过 `--auto-cameras` 时尤其重要），
否则复检结果无法解释。

## 7. 已知的工具缺口（不是你的操作问题）

| 缺口 | 影响 | 你要做的 |
| ---- | ---- | -------- |
| `calibrate_stereo` **不报"采集停住"** | 相机中途掉线时，它会**静默重试**（`apps/calibrate_stereo.py:237-240`），画面冻住但程序不报错、不退出 | 盯着状态条带的帧数/耗时；长时间不动就 Ctrl+C 重来 |
| 采集与实时用的是**不同的取帧路径** | 上轮给实时加的 `stalled()` / `camera_availability()` 对标定**不起作用** | 别指望标定界面会告诉你相机掉了 |
| 落盘 meta 写的是**请求值** | 见第 6 条 | 手动记下实际用的两台 |
| **`--relaxed` 会一次放松 6 条门限** | 过检风险，精度下降可能不明显 | 只在够不着时用，且用完必须复检 |

## 8. 三条命令，按顺序走

```powershell
:: ① 前置检查：两路是否都看到棋盘、视野是否重叠（先跑这个！）
启动程序.bat precheck
::   或手动指定：python apps\tools\check_stereo_setup.py --left 0 --right 2

:: ② 试标定档先跑通（8 对，验证通路；顺手存图）
python apps\calibrate_stereo.py --left left --right right ^
    --cols 8 --rows 5 --square 25 ^
    --baseline-mm <你量到的毫米数> ^
    --save-pairs outputs/calib_pairs --report-png outputs/calib_report.png

:: ③ 通路确认无误后，正式标定（25 对）
python apps\calibrate_stereo.py --left left --right right ^
    --cols 8 --rows 5 --square 25 ^
    --target 25 --min-pairs 10 ^
    --baseline-mm <你量到的毫米数> ^
    --save-pairs outputs/calib_pairs --report-png outputs/calib_report.png
```

> `--left left --right right` 用的是**角色名**（查 `config/cameras.json`），
> 比索引稳 —— 索引会随 USB 口/插拔顺序漂移。先跑 `启动程序.bat check` 确认角色没漂。
> 也可以 `--auto-cameras`（会**优先外接、避开内置/红外**）。

## 9. 出问题时第一件事：**别改代码**

沙箱/换机器时 `cv2.VideoCapture` 打不开是**环境限制**，不是代码 bug（实测：本机 7 个索引
全试过、单次试开最长 4.4 s）。先跑 `启动程序.bat check` 与 `启动程序.bat diag`
拿到**事实**，再判断。

本项目最贵的教训正是"合成/逻辑上漂亮 ⇒ 以为真机可用"。
所以：**任何真机结论都必须有产物**（日志、`--save-pairs` 的图像、`--report-png` 的验证图）。
