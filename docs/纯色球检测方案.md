# 纯色哑光塑料球检测方案

> **⚠️ 本文只讲"纯色球"这一条路径，它不再是项目的唯一目标（2026-11-06 起）。**
> 用户已明确要求走向**通用球类运动识别**（近乎圆形的水果等任意球体）。新增的
> `--method generic`（纯几何：边缘 + 圆度 + 径向一致性 + 梯度符号一致性）不复用
> 本文的 HSV 参数表，见 `交接文档.md` §75。`color` 仍是**出厂默认**，本文的结论
> 对纯色球依然有效——读本文时不要把它当成"检测能力的上限"。
>
> 课题从"金属球（镜面）"切换到"纯色塑料球（哑光、单色）"后的选型、参数、采集与实测边界。
>
> **本文的所有实验都是合成图**，仓库里没有纯色塑料球的真实录像。合成图能证明什么、不能证明什么，
> 见 §1 —— 请先读那一节，再看数字。
>
> 实验脚本与图都在 `outputs/algo_survey/`（`synth_lab.py` / `run_sweeps.py` / `run_probes.py` /
> `run_probes2.py` / `sweep_results.csv` / `fig_*.png`）。本文写于 2026-11-03。

## 0. 一句话结论

**首选 `--method color --preset <球的颜色>`**（`ColorBlobDetector`）：在"球色饱和度足够、背景与球的
色相或饱和度可分、球直径 ≥ 20 px、出画 < 25% 球径、运动模糊 < 0.5×球径"的画面里，它在合成图上
从 20 px 到 200 px 全部稳定命中，单帧 7~10 ms（1080p）。**但它的失败是静默的**：预设不匹配时
返回 0 个检测、同色背景时返回 0 个检测、同色干扰物时**得分完全相同、谁排第一由扫描顺序决定**。
因此备选不是"更好的检测器"，而是**采集时把这三个条件做对**；做不到就降级到 `fusion`（约 10 fps，
本项目实测 8.3 fps）。

## 1. 证据边界（先说清楚，避免把合成结论当真实结论）

**合成图能证明的：**

- 阈值卡在哪个**数值**上（例如背景亮度 V 一到 70 就整幅被吃进掩膜，因为预设的 `V_min=70`）；
- **失败形态**：是"丢检"（`n=0`）还是"检到了但半径偏"（更危险，下游会算错深度）；
- 同一颜色出现两个候选时，`score` 能不能把它们分开（→ 不能，见 §4.3c）；
- 单帧耗时的量级（合成图是**下限**，真实场景纹理多、边缘多，只会更慢）。

**合成图不能证明的：**

- 真实相机的动态范围、自动曝光/白平衡漂移、JPEG/H.264 压缩块、卷帘效应下的 HSV 分布；
- 真实哑光塑料的表面（不是纯色平涂，有细微纹理、污渍、印刷标记）；
- 真实 fps（本文的 ms/帧 不含采集、解码、跟踪、绘制）；
- **任何"换成真实相机也能过"的推断**。凡本文写"未验证"的地方，都是这一类。

**本文的"命中"判据（我自己定的，不是项目里的定义）：**
top-1 检测与真值圆心距离 ≤ max(3 px, 10%×真半径)，且半径相对误差 ≤ 12%。
"BAD"= 检到了但超出这个范围（静默错），"NONE"= 一个都没返回。

## 2. 各检测器对"纯色哑光球"的适用性

方法清单只来自 `sphere_tracker/detectors/registry.py:25-50`（项目规则 R7）。

| 方法 | 原理 | 需要的先验 | 在纯色哑光球上成立吗 | 单帧耗时 |
|---|---|---|---|---|
| **color** | BGR→HSV 硬阈值 → 开/闭运算 → `findContours` → 圆度/填充率/径向一致性筛选 → 亚像素射线细化 | **球色已知且与背景可分** | **成立（首选）**。球是均匀单色，正是这套方法最理想的输入 | 7.3~9.5 ms @1080p（本项目实测 18.3 ms，见 `config.py:157`） |
| hough | 灰度 Canny + `HOUGH_GRADIENT` + 圆上梯度方向/符号一致性校验 | **无颜色先验**，只要能形成圆弧边缘 | **能出结果但不是首选**。纯色球只有一条"球/背景"边界，边缘信息很少；圆内没有任何纹理，霍夫的累加器只能靠这一圈。合成图上可用，但代价是 **65~80 ms**（约 color 的 8 倍），而精度不如 color（color 直接给轮廓+亚像素） | 65~80 ms @1080p（本项目实测 ≈80 ms） |
| motion | MOG2 背景建模（相机在动时切到"对齐后差分"），差分区域只当**提议**，形状回到当前帧量 | **背景静止或可对齐**；球**必须动** | **只作为补充/兜底**。成立条件：球在动、背景静止。失效条件：球停住（顶点/静止摆）、相机在动、背景有同类运动物（窗帘、风扇、人影）。它不看颜色，所以是"球与背景同色"时唯一的线索 | 未单独实测（fusion 1080p 共 98.5 ms） |
| fusion | color + hough + motion 依次全跑，**两两投票**（中心距 < max(6px, 0.45r) 算同意），每票 +0.12，孤证且总分 < `min_score` 则丢弃 | 三个成员的先验都要满足一部分 | **有同色干扰/同色背景时的正解**。代价：8~10 fps。注意它只取每个成员**最好的一个**候选投票，所以"两个同色物"它分不出来 | 98.5 ms @1080p（本项目实测 120.6 ms） |
| yolo | ultralytics YOLO；COCO 权重有 `sports ball`(32) 类；或自训 `models/ball_yolo.pt`（单类 0） | **模型 + ultralytics**；COCO 的 sports ball 先验是"运动球类"，对**小而纯色的塑料球**不一定有这一类的语义 | **未验证**。零样本 COCO 权重对 4 cm 小球的召回率本文没有测（仓库里有 `outputs/train_ball` 与 `models/` 目录，但那是金属球阶段的数据）。风险：训练集分布不一致时召回会很低，且**默认 `yolo_conf=0.25` 会把低分框全滤掉**（`neural.py` 的注释记录过这个坑） | 未测（依赖 GPU；CPU 上不可用） |
| yolo_sam | YOLO 出框 → SAM2 用框当 prompt 出掩膜 → 掩膜轮廓拟合圆 | 模型 + 更大的算力 | **未验证**。理论上掩膜边界最接近真实轮廓，对"边缘有高光/阴影"最稳；但**它仍然要先有一个框**，框错了一切都错。对纯色球它带来的精度增益（相对 color 的亚像素射线）在合成图上没有证据 | 未测（最贵） |
| specular | 人工 seed + CSRT 跟踪 + 高光/运动门控 | **依赖高光斑** | **不适用**。它靠镜面高光斑定位（`specular.py` 模块 docstring：镜面球整圈只有 25%~35% 有梯度、靠人工 seed），纯色哑光球上没有这个特征 | 20.5 ms @1080p（模块注释） |

**为什么不用 hough 当主力（一句话）**：纯色球给的几何线索只有一圈边界，而 HSV 阈值直接就能把这一圈
以像素级精度切出来；hough 要在同样稀薄的信息上多花 8 倍时间做累加器投票，还得靠"梯度符号一致性"去
压乱检（`hough.py:52-53`）—— 它存在的意义是**颜色不可靠时的第二票**，不是精度来源。

## 3. `ColorBlobDetector` 全部可调参数

代码：`sphere_tracker/detectors/color.py`（检测流程）+ `config.py` 的 `ColorConfig`（取色/种子）
和 `DetectorConfig`（形状/尺寸门限）。

### 3.1 颜色（`ColorConfig`，走 `--preset` 或改 JSON）

| 字段 | 默认（= `white_ball`） | 物理含义 | 调大 | 调小 |
|---|---|---|---|---|
| `hsv_lower` | `[0, 0, 175]` | HSV 下界 (H,S,V)，OpenCV 的 H∈[0,179] | 下界抬高 → 掩膜变小 → **漏检** | 下界放低 → 掩膜变大 → **多检/把背景吃进来** |
| `hsv_upper` | `[179, 80, 255]` | HSV 上界 | 上界抬高 → 多检 | 上界压低 → 漏检 |
| `use_second_range` | `False` | 是否启用第二段色相区间（红色跨 0° 必须用） | — | 红球设 `False` 会**丢掉 H>170 的那半边红**（偏紫的红被切掉一半） |
| `hsv_lower2` / `hsv_upper2` | `[170,80,80]` / `[179,255,255]` | 第二段区间 | 同上 | 同上 |
| `open_ksize` | `5` | 开运算核（先去小噪点） | 大 → 小目标被吃掉 → **小球的漏检**（本次实测 d=16 px 加模糊就开始不稳） | 小（<3 等于关闭）→ 噪点/孤立像素变成候选 → 多检 |
| `close_ksize` | `7` | 闭运算核（补孔洞/接断边） | 大 → **把球和旁边的同色物连成一块**（实测 5 px 的缝就被 7×7 闭运算桥接，见 §4.4） | 小 → 球内暗侧被切断时补不回来 → 圆度下降 |

### 3.2 形状 / 尺寸门限（`DetectorConfig`）

| 字段 | 默认 | 物理含义 | 调大 | 调小 |
|---|---|---|---|---|
| `min_radius` | `8.0` | 允许的最小球半径（px）。同时决定最小面积门限 `min_area = π·min_radius²·0.5` | **直接砍掉小目标**（本项目金属球阶段实测真球半径 35~40 px，8 太松） | 放到 0 附近 → 噪点也当球 → 多检 |
| `max_radius` | `200.0` | 允许的最大球半径（px）。**球离镜头近的时候很容易撞上它** | 能容许更大的近景球；但同色大色块（桌布、衣服）也会被当成候选 → 多检 | 一超就 `score=0` → 漏检（本次实测"球贴同色桌布"就是靠这条被挡下 → 变成 n=0 而不是假检出） |
| `min_circularity` | `0.55` | `4πA/P²`，完美圆=1 | 阈值高 → 掩膜有缺口/高光斑切边时 **漏检**（实测大高光斑会把圆度打到 0.44~0.71） | 低 → 方块（0.785）也能过，靠 `min_fill_ratio` 兜底 |
| `min_fill_ratio` | `0.72` | 轮廓面积 / 最小外接圆面积；方块只有 ~0.61 | 高 → 缺口/高光切边时漏检 | 低 → 方块、月牙形状能过 → 多检 |
| `min_radial_consistency` | `0.90` | 轮廓点到拟合圆心距离的一致性 `1 - std(d)/r`。**判别力最强的一项**（方块 ~0.85，圆 ~0.98） | 高 → 掩膜有缺口/锯齿时开始漏检（合成图干净圆能到 0.99，真实掩膜达不到，本项目的真机数据是圆度 0.61~0.63 那一档） | 低 → 胶囊、粘连的两球、圆弧（出画）能过 → 多检 |
| `subpixel_refine` | `True` | 用 72 条径向射线的梯度峰值重新拟合圆（只对 top-3 做，`color.py:95`） | — | 关掉省 ~0.5~2 ms，代价见 §4.3（模糊下半径误差 1.5 px → 0.44 px） |
| `subpixel_rays` | `72` | 细化用的射线数 | 多 → 更稳但更慢（线性） | 少 → 小球的边缘点不够，拟合抖 |

### 3.3 `min_score` 对 `color` 也生效了（2026-11-06 修）

旧版 `DetectorConfig.min_score` **只被 `fusion.py` 读**（`color.py` 里只有 `if score <= 0: continue`），
改它对 `--method color` 没有任何效果（B-178）。现在 `ColorBlobDetector._rank()` 也过这道分数门：

- 先过形状门（`min_circularity` / `min_fill_ratio` / `min_radial_consistency`），再过 `min_score`；
- 实测同一条红球：`min_score=0.10` 与 `0.55` 都检出，`0.99` 为 0；
- 默认 0.55 不改变既有精度（`selftest_synthetic` 的 color/fusion 数字与改前一致）。

压 `color` 误检仍可先动 `min_circularity` / `min_fill_ratio` / `min_radial_consistency` /
`min_radius` / `max_radius` / HSV 区间。`min_score` 现在是一个真正可用的旋钮，
但它只回答"总分够不够"，不回答"形状像不像球"。

### 3.4 `--preset` 的取值（唯一来源：`config.py` 的 `COLOR_PRESETS`）

| 预设 | hsv_lower | hsv_upper | S_min | V_min | 备注 |
|---|---|---|---|---|---|
| `white_ball`（**默认**） | `[0,0,175]` | `[179,80,255]` | 0（上界 80） | 175 | 亮度高、饱和度低。**不传 `--preset` 就等于它** |
| `orange_ball` | `[5,110,110]` | `[22,255,255]` | 110 | 110 | |
| `green_ball` | `[40,70,60]` | `[85,255,255]` | 70 | 60 | S_min 只要 70，**比红/蓝松**，更容易把背景吃进来 |
| `blue_ball` | `[95,90,60]` | `[130,255,255]` | 90 | 60 | |
| `red_ball` | `[0,110,70]` + `[170,110,70]`~`[179,255,255]` | `[10,255,255]` | 110 | 70 | 双区间（红跨 0°），已配好 |
| `yellow_ball` | `[20,100,100]` | `[35,255,255]` | 100 | 100 | |
| `auto`（**不是颜色**） | 运行时估计 | — | — | — | 从画面主色估区间（`ColorConfig.preset_choices()` 的第一项）。球色不在下表六个预设里、或不想先知道球色时用它 |

**采集时只记两列就够**：背景饱和度要低于该色的 `S_min`，球的暗侧亮度要高于该色的 `V_min`。

**GUI 与 CLI 都有入口**：

- GUI：`apps/_gui_widgets.BallSettings` 的「颜色预设」下拉，候选直接来自
  `ColorConfig.preset_choices()`（`auto` 显示为「自动取色」）。三个窗口
  （单目第②步 / 双目第④步 / 工作台第③步）共用同一块控件。
- CLI：`--preset {auto,white_ball,orange_ball,green_ball,blue_ball,red_ball,yellow_ball}`。
- 「不使用」= 用配置里的 `white_ball`。红球此时仍会 0 检出，但 2026-11-06 起
  `pipeline` 会把原因打到控制台（"颜色掩膜是空的：球色与预设不匹配…"），
  不再是一个字都不说的静默失败。
- **新开的纯色球窗口默认选「自动取色」**（`BallSettings` 在 `kind=plastic` 且
  没有保存过偏好时设成 `auto`）。用户显式选过「不使用」的偏好不会被覆盖。

本次实测：`white_ball` 预设对红色球 `n=0`；`orange_ball` 对红色球也是 `n=0`
（见 `fig_presets.png`）；`auto` 对同一颗红球命中（`auto_range=red_ball`），
对不在六预设里的紫色球也命中（`auto_range=auto:dominant`）。

## 4. 合成实验：它的边界在哪里

### 4.1 设置

- 640×480，背景纯灰 `(128,128,128)`（S=0 → 天然不在任何预设的掩膜里），球画成抗锯齿圆，
  默认红球 `BGR=(0,0,200)`（H=0,S=255,V=200），半径 40 px（直径 80 px，约等于 1080p 下 240 px 的球）。
- 只用 `ColorBlobDetector`（`--method color`），预设 `red_ball`，其余全默认。
- 脚本：`outputs/algo_survey/run_sweeps.py`（主扫描）、`run_probes.py`（小目标/亚像素/耗时）、
  `run_probes2.py`（运动模糊/出画/高光/干扰排序）。原始数字：`sweep_results.csv`。

### 4.2 主表：每条轴的失效位置

| 轴 | 仍可用（HIT） | 开始"检到但偏"（BAD） | 完全失败（NONE） | 失效的**机制**（不是巧合） |
|---|---|---|---|---|
| **球直径** | 16 → 200 px 命中（d=16 只有不模糊时稳） | d=16 + σ=4 时偏 | 直径 ≤ 14 px（由 `min_radius=8` 的硬门推出，**推断，未逐点测**） | 尺寸门限是硬门：`min_radius` 直接决定下限 |
| **球内光照梯度**（暗侧增益 g，球 V=200） | g ≥ 0.30 | — | g ≤ 0.15（暗侧 V=30） | 暗侧 V 掉到 `V_min=70` 以下的部分不再进掩膜；只剩一小条时轮廓仍够圆，所以是"先偏、后丢" |
| **同上，但球本身更暗** | V=120 时只能撑到 g ≥ 0.7 | — | V=120、g ≤ 0.5（120×0.5=60） | 见下方"注意"：这条**不是**精确等于 `V_min` 的判据 |
| **背景同色相，只差亮度**（红球 + 全屏红底） | 背景 V ≤ 60 | — | 背景 V ≥ 70 | 背景 S=255 ≥ `S_min=110`、V ≥ `V_min=70` → **整幅画面进掩膜**，球没了（是 n=0，不是误检） |
| **背景同色相，只差饱和度**（红球 + 掺红的灰底） | 掺红比例 α ≤ 0.25（背景 S≲102） | — | α ≥ 0.35（背景 S≈132） | **规律：背景饱和度必须 < `S_min`**（见 §3.4 的每色 S_min 表） |
| **高斯模糊**（虚焦） | σ ≤ 12 px 仍"命中"，但半径**系统性变大** | — | 未在 σ≤12 内出现 n=0 | 模糊不杀检出，它**杀精度**：σ=3 时半径 +0.4~1.3 px（取决于亚像素开关），σ=12 时 +2.9 px（见 4.3a） |
| **加性噪声** | σ ≤ 40（score 从 0.96 掉到 0.85） | — | σ ≥ 60 | 噪声把边缘打成碎点，开运算后面积不够 |
| **运动模糊**（方向性，长度 L） | L ≤ 0.4×直径 | L ≈ 0.5×直径（d=40 时 L=20） | L ≥ 0.75~1.0×直径 | 沿运动方向的拖影把圆拉成胶囊 → 圆度/填充率同时掉 |
| **出画**（球被画框切掉） | 切掉 ≤ 25% 直径 | — | 切掉 ≥ 38% 直径 | 剩一段弧 → 径向一致性断裂 → `score=0` |
| **球面镜面高光斑**（白点半径 sr，距圆心 d） | 高光斑整体在球内（`d + sr ≤ 0.9R`）完全无害 | — | 高光斑**碰到外轮廓**时（`d+sr ≳ R`）：圆度 0.91 → 0.65~0.74，填充率同时掉 → n=0 | 白点 S≈0 不进掩膜 → 掩膜被咬出一个缺口；缺口在**内部**无害，碰到**边缘**才致命 |
| **同色干扰物** | 真球仍是候选之一（n=2） | **top-1 可能变成干扰物** | — | 两候选 `score` **完全相同**（0.9575 vs 0.9575），排序由 `findContours` 的返回顺序决定（见 4.3c） |
| **预设与球色不匹配** | — | — | 立刻 n=0 | `white_ball`/`orange_ball` 对红球 = 0 检出 |

> **关于"光照梯度"这一条的注意**：它不是"暗侧 V ≥ `V_min` 就过、否则不过"这么精确。
> 球 V=200、g=0.30 时暗侧末端已经掉到 V=60（低于 70）却仍然命中 —— 因为掉下去的那一条太窄，
> 拟合圆把它当成"轮廓上的小缺口"吃掉了；而 V=120、g=0.5（末端同样 60）就失败 —— 因为
> **整块**暗侧都压到了 70 附近，缺口从"一条"变成"一大块"。所以安全口径应当是：
> **暗侧最暗处 V ≳ `V_min` + 余量（实际采集时按 ≥ 1.3×`V_min` 要求）**。

图：`fig_thresholds.png`（6 条轴的 HIT/MISS 曲线）、`fig_diameter.png`、`fig_lighting.png`、
`fig_bg_same_hue.png`、`fig_blur.png`、`fig_noise.png`、`fig_motion_blur.png`、`fig_clipping.png`、
`fig_highlight.png`、`fig_touch_cloth.png`、`fig_presets.png`、`fig_distractor.png`。

### 4.3 三个比"漏检"更危险的静默误差

**(a) 虚焦把半径系统性放大，深度就系统性偏近。**
单目测深是 `Z = f·(D/2)/r`（`geometry.py:638`），半径 +3% ⇒ 深度 −3%。实测（球真半径 40 px）：

| 高斯 σ | 0 | 1.5 | 3.0 | 8.0 | 12.0 |
|---|---|---|---|---|---|
| 半径偏差，亚像素**关** | +0.35 px | +1.00 | +1.40 | — | — |
| 半径偏差，亚像素**开**（默认） | +0.47 px | +0.54 | +0.43 | +0.92 | +2.91 |
| 对应深度偏差（亚像素开） | −1.2% | −1.4% | −1.1% | −2.3% | −7.3% |

这是**系统偏差**，不是抖动：卡尔曼滤波和多次平均都消不掉。项目现在是用
`CameraConfig.ball_diameter_m` 填"有效直径"（21.6 mm 而非名义 25 mm，`config.py:346-351`）把它
手工吸收掉的 —— 所以**换球、换镜头、换对焦距离之后，这个常数必须重新标**。
注意 σ≤3 时亚像素把这部分偏差压到 0.5 px 以内；真正危险的是**明显虚焦**（σ≥8）。

**(b) 亚像素细化：在"刀切边"上略偏，在"模糊边"上明显更好。**
带符号误差（真值 − 检测，px；正值 = 检测偏小）：

| 直径 | 模糊 σ | 关掉亚像素 | 开启亚像素 |
|---|---|---|---|
| 40 | 0 | −0.19 | **−0.66**（更差） |
| 40 | 3.0 | −1.26 | **−0.65**（好一倍） |
| 80 | 0 | −0.35 | −0.47 |
| 80 | 3.0 | −1.40 | **−0.43**（好 3 倍） |
| 140 | 3.0 | −1.50 | **−0.44** |

结论：**保持 `subpixel_refine=True`**。合成图的边是"阶跃 + 抗锯齿"，几乎没有梯度可插值，所以
亚像素在 σ=0 时反而引入 ~0.5 px 的固定偏差；真实相机一定有镜头模糊/衍射，σ>0 时它把误差压回
0.4~0.7 px。真实场景的具体收益**未验证**，但方向是明确的。

**(c) 同色干扰物：`detections[0]` 会被抢走。**
两个同半径、同颜色的圆（真球 + 干扰物），`score` **逐位相同**（0.9575 / 0.9575）——
因为它只由圆度/填充率/径向一致性/尺寸算，**完全不含颜色强度和位置信息**。
换干扰物位置会让 top-1 翻转：

| 干扰物位置 | top-1 |
|---|---|
| (150,120) | 真球 |
| (400,80) | 真球 |
| (100,420) | **干扰物** |
| (560,400) | **干扰物** |

而 `pipeline.py:212` 是 `best = detections[0]` —— **同色干扰会直接抢走"本帧检测"**（跟踪器还会拿到
两个候选做关联，但"本帧检测"这条已经错了）。降级到 `fusion` 也救不了"两个同色物都在动"的情况
（它只取每个成员最好的一个候选投票），真正的解法是**采集时不放同色物**，其次是给 `color` 加
"与上一帧预测位置一致"的门（见 §7 第 2 条）。

### 4.4 同色桌布的"桥接"：5 px 的缝就足够毁掉它

`fig_touch_cloth.png`：球底边在 y=260、同色桌布从 y=265 开始（**中间还有 5 px 灰缝**），
闭运算 `close_ksize=7` 直接把两块桥接成一块，最小外接圆半径超 `max_radius` → **n=0**。
这一条对"红球放在红桌布上"是致命的，而且**肉眼看起来球是好好的**。

### 4.5 耗时（1080p，本机 Windows 11 + conda py3.14，合成图，不含采集/跟踪/绘制）

## 5. 选型与配置建议

### 5.1 决策表

| 现场条件 | 用哪个 | 为什么 |
|---|---|---|
| 球色饱和、背景是白墙/灰地/木质（色相远离球色） | **`--method color`** + 对应 `--preset` | 54 fps（本项目实测），精度最高（直接拿轮廓 + 亚像素） |
| 背景有**同色**的大面积物（红桌布/红衣服/红箱子） | 先改**采集**（换背景/铺白纸）；改不了 → `fusion` | color 会整幅进掩膜直接 n=0（§4.2） |
| 画面里有**另一个同色圆物**（红球、红杯子、红色广告牌） | 采集时移走；否则 `fusion` + 人工 seed / 限定 ROI | color 的 top-1 会被抢（§4.3c） |
| 球会**停住**（摆到顶点、放在桌上） | `color`（不要用 `motion` 当主力） | `motion` 靠"球在动"，静止即刻失效 |
| 相机**手持/云台** | `color`（`motion_compensation=auto` 会切对齐差分） | color 不受相机自运动影响（`motion` 会） |
| 球很小（直径 < 20 px） | 先**拉近/换长焦**，再考虑 `color` | 实测 20 px 可用、16 px 只在不虚焦时可用；再小会被 `min_radius=8` 直接挡掉，且测深精度不够 |
| **完全无法控制环境**、且要 30 fps 以上 | 没有现成方案 | 本项目没有"环境不可控 + 纯色球"的验证过的组合 |

### 5.2 具体命令

### 5.3 参数怎么配（纯色哑光球）

1. **只改 HSV**：先 `--preset`，再用 `calibrate_color.py` 微调。**不要凭肉眼猜 HSV**。
2. `min_radius` 按"球在画面里最小时的半径 × 0.8"设。这是压误检最省事的一招
   （`config.py:184` 的注释也是这个意思）。
3. `max_radius` 按"球最近时的半径 × 1.2"设。留太大，同色大色块会进来。
4. `min_circularity` / `min_fill_ratio` / `min_radial_consistency` **保持默认**（0.55 / 0.72 / 0.90）。
   它们已经有真机实测依据（0.62 → 0.55 把检出率从 72.5% 提到 100%），而且 §4.2 的高光/出画
   失效正是靠它们"正确地失败"（宁可 n=0，也不要假圆）。
5. `subpixel_refine` **保持 True**（§4.3b）。
6. `open_ksize` / `close_ksize` 默认 5/7；**如果现场有同色表面靠近球**，把 `close_ksize` 降到 3
   （代价：球暗侧断边补不回来）。这是"桥接"失效唯一的一行补救。

## 6. 采集要求（按重要性排序，都是 §4 实测出来的硬约束）

1. **背景与球的饱和度差**：背景 S 必须 **< 该球色的 `S_min`**（白 80 / 橙 110 / 绿 70 / 蓝 90 / 红 110 / 黄 100），
   或者色相与球相差 > 20°。最保险：白/灰/黑背景。
2. **画面里不许有同色物体**（包括另一个球、杯子、衣服、广告牌、红色桌面）。
3. **球不许贴在同色表面上**：同色表面与球之间至少留 **> 2×`close_ksize` ≈ 14 px** 的空隙。
4. **光照**：球的**暗侧最暗处 V ≥ 1.3×`V_min`**（红 91 / 橙 143 / 绿 78 / 蓝 78 / 黄 130 / 白 228 ——
   白球几乎没有余量，靠颜色分白球本来就不该指望）。
   实践含义：**别用单侧强光**，用柔光/双侧补光；红球在阴影里会直接消失。
5. **球在画面里的直径**：**≥ 20 px，建议 ≥ 40 px**（40 px 时亚像素能到 0.4~0.7 px 半径精度，
   对应深度 1~2%；20 px 时同样的绝对误差翻倍到 3~5%）。
6. **运动模糊 < 0.5×球径**：按曝光时间算 —— 球速 v、曝光 t，拖影 ≈ v·t。球径 40 px、球速 300 px/s
   ⇒ 曝光必须 < 0.067 s。**这是硬约束，靠减曝光/加光，不靠算法。**
7. **球不出画超过 25%**：轨迹的起止段会丢，规划拍摄范围时留余量。
8. **高光斑别落在球的边缘**：哑光球也有小高光，通常在球心附近、直径 < 0.3 球径 —— 无害；
   但"光滑/半光塑料球 + 点光源"会把高光推到边缘并放大，那就开始丢检。采集时把光源放得散一些。

## 9. 2026-11-06 落地：点选取色 / 自动取色 / 帧间一致性 / 融合聚类 / 种子半径

> 本节记录的是**代码已经这样做**的事实，不是计划。判据在
> `tests/selftest_plugins.py` §11（12 条）与 `tests/selftest_gui_budget.py` 的
> 工作台 argv 断言；真机只做了"链路冒烟"，不作为精度证据。

### 9.1 点选球心后，color 一定给得出 Detection

`ColorBlobDetector.seed(x, y, r, frame_index)`：

1. **第 seed_frame 帧取色**：从点击点周围 `[0.45r, 0.80r]` 的**圆环**取 HSV
   （避开球心高光与最外圈混色）。H 用"覆盖 95% 样本的最短弧"，跨 0° 自动拆
   两段；S/V 取 5% 分位减余量。取到的区间**覆盖预设**，所以"预设选错了"不再是
   点选后的失败原因。
2. **半径带**：只接受 `[0.60, 1.70] × seed_r` 的候选。球在轨迹里远近变化
   ±40% 仍能跟；"另一个同色但大小不同的圆"被挡掉。
3. **种子帧空间门**：候选必须落在点击点周围 `max(10px, 2r)` 内。
4. **兜底**：种子帧一个候选都没有（例如白球贴白墙、掩膜为空）→ **直接用种子
   作为 Detection** 输出，`extra["seed_anchor"]=True`。用户点过的地方不允许
   报"没看见"；**只在这一帧**，之后不拿旧位置冒充观测。
5. **边缘跟随**：之后某帧颜色分割失败时，沿"上一帧位置 + 速度"用亚像素射线
   找球缘（`refine_circle_subpixel_checked`），`extra["edge_follow"]=True`。
   任何球都有边缘，这一路不依赖颜色可分；搜索窗 ±0.30r，位移超过 0.35r 就
   放弃（不硬吸到背景上）。

实测（合成 640×480）：白预设 + 红球 → 不点选 0 检出；`seed(320,240,40)` 后
1 检出，圆心/半径误差 ≤1.5 px。完全同色的灰画面上，种子帧输出
`seed_anchor`、下一帧为 0（不编造）。

### 9.2 `--preset auto`：不点选、不知道球色也能起步

- 六个预设 + 一个"画面主色"候选各跑一遍（在 **480 宽**的缩图上），取形状得分
  最高的区间；锁定 45 帧，连续 8 帧 0 候选就重选（`ColorConfig.auto_lock_frames`
  / `auto_unlock_after`）。
- 主色估计只看 `S≥60, V≥40` 的像素，色相直方图按 S 加权找峰，向两侧扩到峰值
  的 1/4；扩到 >70° 就判"没有明确主色"（避免把整幅彩色画面当成一个目标）。
- 掩膜覆盖率 >40% 的候选扣分（背景被吃进来的典型形态）。
- 实测：红球 `auto_range=red_ball`；不在六预设里的紫色球
  `auto_range=auto:dominant`，同样命中。成本只在"选区间"那一次，缩图上七次
  掩膜；锁定期内仍是单次全分辨率检测。
- **GUI 新开的纯色球窗口默认就是 auto**（没保存过预设偏好时）。
  用户显式选过「不使用」的偏好不会被覆盖。

### 9.3 `color` 的帧间一致性（B-176）

候选按分数排序后，先取"并列第一档"（≥ 最高分 × 0.92），再按
`距离(上一帧位置 + 速度×帧差) / 半径` 最小者优先。分差明显时不重排 ——
连续性只用来打破同分，不用来推翻明显更好的候选。

### 9.4 `fusion`：top-K + 聚类投票（不再只取每个成员的第一名）

- 每个成员交 `fusion_topk`（默认 3）个候选；候选按中心距聚类，簇的票数 =
  支持它的**不同成员数**。
- 簇得分 = 簇内代表候选的分数 + 0.12×(成员数−1)；只有一路支持且低于
  `min_score` 的簇丢弃。
- **代表候选按 `fusion_members` 的顺序取**（color 在前），不是按 score 取：
  实测 hough 在合成圆上能报 0.99，但圆心比 color 差 2~5 px；按 score 取会让
  fusion 比单跑 color 更差（跟踪 RMSE 0.54→5.18 px 那次）。
- 两簇票数/分数都接近（差 ≤0.03）时，取离上一帧位置更近的簇。

### 9.5 `specular`：种子半径是尺度锚，不是"框的一半"

- 输出半径 = `seed_r × (当前框半径 / 初始框半径)`，倍率夹在
  `[0.60, 1.60]`（`SpecularConfig.seed_scale_*`）。旧版直接报框半径：
  金属球 seed 92.5、框半径 70 → 半径系统性小 24%，而 `Z=f·D/(2r)` 会把它
  变成系统性偏远的深度。
- 初始框改成 `1.8×r`（下限 24 px；r≥20 时再抬到 `init_box`，上限 `max_box`）。
  旧版固定 64 px，对 r=10 的塑料球等于把 3 倍球径的背景框进来。
- 有种子时不再用全局 `min_radius/max_radius` 拦半径：那是给自动检测的物理约束，
  拿它拦人工点选的小球会把整段判成 0 检出。
- CSRT 初始化失败时，**种子帧仍输出 Detection**（`state="seed-anchor"`），
  下一帧继续重试；不会拿旧位置一直冒充。

### 9.6 种子不再等于"必须用 specular"（B-179）

旧链路有三处"有种子 → 强制 specular"：`_gui_bench.offline_cmd`、
`run_stereo_video._pick_detector`、`run_video` 的 `--seed` 分支。对金属球是对的，
对纯色塑料球是反的（color 本来就能找到，换成 specular 反而丢掉轮廓精度）。

现在：

- `seeds.json` 增写 `ball_kind`（`metal` / `plastic` / 空），GUI 点选时按
  「球种类」写入；
- `_pick_detector`：`plastic` → 保留 color；`metal` 或**旧文件无该字段** →
  specular（兼容旧会话）；
- 显式 `--method` 一律优先；`--seed-json` 也传给 color（取色 + 锚半径）；
- `--detect-width` 与种子互斥（种子是原图坐标）：specular 直接报错，color
  忽略种子并说明。

### 9.7 新的可调字段（`ColorConfig` / `SpecularConfig`）

| 字段 | 默认 | 管什么 |
|---|---|---|
| `ColorConfig.mode` | `fixed` | `auto` = 从画面主色取区间 |
| `auto_lock_frames` / `auto_unlock_after` | 45 / 8 | 自动取色的锁定与重选 |
| `seed_sample_lo` / `seed_sample_hi` | 0.45 / 0.80 | 种子取色的圆环 |
| `seed_hsv_margin_h` / `seed_hsv_margin_sv` | 6 / 22 | 取色区间的外扩 |
| `seed_radius_lo` / `seed_radius_hi` | 0.60 / 1.70 | 种子半径带 |
| `seed_gate_ratio` / `seed_gate_min_px` | 2.0 / 10 | 种子帧空间门 |
| `seed_edge_follow` | True | 颜色失败时用亚像素射线找球缘 |
| `DetectorConfig.fusion_topk` | 3 | 每个融合成员交几个候选 |
| `SpecularConfig.seed_scale_lo` / `hi` | 0.60 / 1.60 | 框缩放 → 半径倍率的夹紧 |

### 9.8 证据边界（别把这一节当"真实精度"）

- 12 条行为判据都是**合成图**（`selftest_plugins.py` §11）；它们证明的是
  "机制成立、失败形态正确"，不是"真实相机也这样"。
- 真机只跑了两段 20 对的冒烟：
  - `20261019-221550 --method specular`：17/20 匹配，Z 0.249–0.257 m，
    与改前同档；说明半径锚定没有破坏配对。
  - 同一段 `--method color --preset auto`：两路都检出（无左=0/无右=0），
    但 6/6 被极线门拒绝 —— 金属球本来就不该用 color，这是**预期失败**，
    不是 color 的新缺陷。
- 单目端到端（合成 320×240、红球 24 帧）：
  - `--method color --seed 100,120,20` → **没有被切成 specular**，24/24 有效帧，
    半径 20.6 px；
  - `--method color --preset auto`（不点选）→ 24/24 有效帧，半径 20.6 px。
- 纯色塑料球的真实录像仍然**没有**。换成真球后第一件事仍是录一段、用
  `calibrate_color.py` 看掩膜，再决定用 `auto` 还是固定预设。
