# 文件结构

> 一页看清每个目录干什么。改代码前先看这里，别把东西放错地方。
> ⚠️ **规则（放置 / 命名 / 依赖方向）的权威是根目录 `AGENTS.md`**，本文只负责**目录逐项说明**。
> 入口文档是 `docs/项目总纲.md`（项目是什么 + 文档怎么配合）。

    Three-dimensional-sphere-motion-trajectory-recognition/
    │
    ├── run.bat             ★ 主入口：双击即可（环境检查 → 启动）；参数路由的唯一产地
    │                           支持参数 cli/setup/check/precheck/calibrate/verify/run/test/install
    ├── install.bat             安装：转发 run.bat install（环境安装器）
    ├── uninstall.bat           卸载：整个安装目录送进 Windows 回收站，拒绝开发仓库、二次确认
    ├── launcher.exe            可选无黑框启动器：编译产物，不入库、不进纯净包（Go 重建）
    ├── LICENSE                  MIT 许可证（随源码包与 setup.exe 分发）
    ├── installer/               Windows 安装程序（Inno Setup）的**重建脚本**，产物不入库
    │   ├── sphere_motion.iss        安装定义：装到 {userpf}\SphereMotion（C 盘用户级 Programs，免管理员）；卸载可选只删程序或连数据删除；
    │   │                            [Code] 向导里选解释器（自带/本机），写 config/python_env.txt
    │   ├── build_installer.bat      一键编译：内嵌 Python + 纯净包 + launcher.exe → outputs/releases/*-setup.exe
    │   ├── build_runtime.py         内嵌 Python 运行时单一真相：下载(固定 sha256)+装依赖+精简+校验
    │   └── verify_payload.py        不装 Inno 也能先验源码 payload 完整性（缺文件/假 exe/图标路径）
    ├── outputs/release_stage/runtime/python/   内嵌 Python 3.14（构建产物，gitignore，不入库）
    │                                         安装后固定到 %LOCALAPPDATA%\SphereMotion\runtime（C:）
    │                                           只进 setup.exe，不进源码 zip
    ├── apps/gui_main.py              图形界面（被 .bat 调用）
    ├── apps/cli_main.py        命令行界面（被 .bat 调用；无 tkinter 时自动改用）
    │
    ├── sphere_tracker/          单目核心库（逐帧：检测 → 跟踪 → 预测）
    │   ├── config.py            所有可调参数（dataclass），含颜色预设
    │   ├── video_profiles.py    分辨率/帧率档位单一来源（8 档 P8K/P5K/P4K/P1440(默认)/P1080/P720/P540/P480；
    │   │                        PROBE_CEILING=P4K(自动探测上限)、FPS_TIERS=24/30/60/120/240/500/1000；
    │   │                        DEFAULT=1440p、DEFAULT_FPS=24，fps 保留小数；档位解析 parse/resolve）
    │   ├── types.py             Detection / TrackState / FrameResult / FrameContext
    │   ├── geometry.py          圆拟合、径向一致性、亚像素边缘细化、相机模型
    │   ├── plugins.py           ★ 插件注册表：kind → name → 工厂（唯一分派来源）
    │   │                        （六个扩展点全走它；见 docs/插件化架构.md）
    │   ├── quality.py           画面质量指标（清晰度/亮度/过曝）：纯计算，apps 与 stereo 共用
    │   ├── discovery.py         会话目录枚举：**全仓库唯一口径**（递归 + 命中即剪枝，
    │   │                        宽/严两档判据，`recursive=False` = 深度压到 2）。
    │   │                        纯 stdlib，不拉 cv2/scipy —— 放 `stereo/` 会让
    │   │                        `import apps.data_manager` 从 0.29s 涨到 1.56s
    │   ├── video_files.py       原始录像文件名唯一产地（left/right.mkv|mp4|avi，优先级 mkv>mp4>avi；
    │   │                        只认会话根目录、单路放行、是文件才算；纯 pathlib 不拉 cv2）
    │   ├── detectors/           ★ 检测器集合，按"线索来源"分文件
    │   │   ├── base.py          基类 + 轮廓打分等公共工具
    │   │   ├── registry.py      把 7 个检测器登记进 plugins（import 即注册）
    │   │   ├── factory.py       按名字造单个检测器（查注册表；避开循环导入）
    │   │   ├── color.py         颜色分割（主力；预设 / auto 取色 / 点选取色 + 帧间一致性）
    │   │   ├── hough.py         霍夫圆（几何补充）
    │   │   ├── motion.py        背景差分（含相机运动补偿）
    │   │   ├── specular.py      镜面金属球：人工 seed + CSRT + 种子半径锚定
    │   │   ├── fusion.py        多线索 top-K 聚类投票融合
    │   │   └── neural.py        YOLO / SAM（可选）
    │   ├── camera_motion.py     相机自运动估计（手持/云台拍摄）
    │   ├── track.py             卡尔曼 + 机动检测 + 重初始化
    │   ├── multi_target.py      二维多目标关联：贪心一对一 + 匀速外推 + 半径法重识别
    │   │                        （只吃像素 (x,y)，不做三维；`swap_events` 是记账不是修复。**未接主流程**）
    │   ├── predict.py           轨迹预测（最长有效后缀拟合 + 已知重力）
    │   ├── sources.py           视频源：摄像头（自动模式探测）/ 文件 / 图片序列；open_camera_source 统一 MF/OpenCV 工厂
    │   ├── mf_camera.py        Windows Media Foundation 采集：按设备 symlink 打开、native type 选档、NV12/MJPG/YUY2 解码（新增，默认不启用）
    │   ├── camera_autobind.py  自动绑定纯逻辑：父设备 serial 锚点 + 排除法（不开相机/不写配置）
    │   ├── camera_fingerprint.py 相机画面指纹：一次登记，之后按场景认回左右（分不清拒绝）
    │   ├── camera_registry.py   摄像头设备管理：枚举身份/端口、固定角色、**标「无关」**、解析索引、探测与自动挑优
    │   ├── viz.py               HUD 与叠加绘制
    │   └── pipeline.py          单帧总流程编排
    │
    ├── calib/                   双目标定（离线、一次）
    │   ├── board.py             标定板检测与质量指标（两级检测）
    │   ├── capture.py           自动挑帧（七道门限）
    │   ├── stereo_calib.py      标定核心（离群剔除 + 整体精化 + 质量判定）
    │   ├── methods.py           标定方法注册表：joint / chain + 各自的约束（同一份清单）
    │   │                        （轴向 / 中轴90° 两个新求解器走独立 CLI 入口，未注册进这张表）
    │   ├── axial_calib.py      模式 A 轴向标定求解器：solve_axial_intrinsics / solve_axial_stereo
    │   │                        / AxialIntrinsics（板正对 + 已知沿光轴推进量 + 已知方格边长）
    │   ├── device90_calib.py   模式 B 中轴90°求解器：solve_device90 / R_AB_matrix / board_center
    │   │                        / Device90Diagnostics（板绕中轴转90°、两路互成90°，无需共视）
    │   ├── angled_quality.py   大角度标定质量：F 极线距离 + 交会角
    │   ├── params.py            StereoRig：保存/加载/校正/三角测量/极线误差
    │   ├── relative_pose.py     链式外参：单相机同框双板求 T_AB（两路无共视也能定外参）
    │   └── world_frame.py       世界系：棋盘 PnP 求 T_world_cam（save/load/apply）
    │                            （导出可视化时可选启用；采集端无 GUI 入口）
    │
    ├── stereo/                  双目（逐帧：把两路合成三维）
    │   ├── sync.py              双路视频同步（闪光/拍手对齐），算出帧偏移
    │   ├── pair_source.py       成对帧源：按 sync_offset / 时间戳取"同一时刻"两帧
    │   │                        （统一封装 camera / video / 图片目录；
    │   │                         canary（时间戳安全接管）为默认，index 仍可强制）
    │   │                          timestamp/canary 走时间戳计划，见下）
    │   ├── fov_align.py         FOV 自动对齐：SIFT/ORB + RANSAC homography；窄视场为参考，裁宽视场；两路统一到不放大任何一路的共同尺寸（逐轴取小后向下取偶）；估计不足抛 ValueError（不静默退化）
    │   ├── timestamp_pair.py   时间戳配对计划：读 *_times.csv，掉帧处跳过、不漂移
    │   ├── triangulate.py       极线约束配对 + 三角测量 + 三维轨迹（parallel）
    │   ├── profiles.py          双目参数档：匹配门限 / 质量阈值（按装置切换）
    │   ├── angled_geometry.py  大角度几何：F / 极线 / 原始射线交会
    │   ├── angled.py           大角度匹配 + 重建（不校正；left_camera）
    │   ├── stereo_mode.py      模式/旧数据兼容 + 交会角估算
    │   ├── record_plan.py      录制参数体检：模式/分辨率/标定三者是否成立（开相机前判，`output_size` 是写盘尺寸的唯一来源）
    │   ├── trajectory.py        三维轨迹后处理：Savitzky-Golay + 常速度 Kalman
    │   ├── depth_fusion.py      双目视差 / 单目球径深度 + 逆方差融合
    │   ├── predict3d.py         三维弹道外推 + 反弹检测（g 为已知常向量；**未接主流程**）
    │   ├── visualization.py     标准数据：seeds / traj3d.json / visualization.json
    │   ├── sessions.py          采集会话：session.json 的读写与校验（data/ 的契约）
    │   ├── round_trip.py        往返一致性：一次来回切成去程/回程，量同一 X 处两腿差多少
    │   └── fov_policy.py        装置级 FOV 应用策略：resolve_fov_apply 唯一判定点
    │
    ├── apps/                    可执行程序（给人用的）；下面按「干什么」分六组
    │   ├── 【入口】能直接跑起来的
    │   │   ├── run_realtime.py     实时单目跟踪
    │   │   ├── run_video.py        离线视频处理
    │   │   ├── record_stereo.py    双路无损录制（HFYU/FFV1 + 时间戳 + session.json；沿用标定 FOV；
    │   │   │                        --container mkv|avi；mkv 默认，avi 可选，mp4 因静默降 h264 排除）
    │   │   ├── record_mono.py      单目录制：一台相机 -> 一个视频 + 一份能自证的元数据
    │   │   ├── run_stereo_video.py 离线双目：读会话 -> traj3d.csv + 标准 JSON + 标注视频
    │   │   ├── run_all.py          一条命令编排 check -> 三维 -> 导出（缺什么跳过并说明；退出码 3 = 有跳过）
    │   │   │                        （**GUI 未接**）
    │   │   ├── calibrate_stereo.py 自动双目标定（启动时自动估计并应用 FOV 对齐）
    │   │   ├── calibrate_axial.py  轴向标定 CLI（模式 A）：平行双目 + 大板正对 + 已知沿光轴推进量
    │   │   │                        （--root/--delta-z/--assume-parallel）
    │   │   ├── calibrate_device90.py 中轴90°标定 CLI（模式 B）：A/B 板正对图 + 已知内参
    │   │   │                        （--left-dir/--right-dir/--intrinsics/--rot-axis/--rot-angle/--z-a/--z-b）
    │   │   ├── calibrate_mono.py   单目内参标定：一组棋盘图 -> config/mono_calibration.json
    │   │   ├── verify_stereo.py    标定复检（装置是否被碰动；实时相机按标定 FOV 归一化）
    │   │   ├── view_3d.py          交互式 3D 轨迹查看器（读 visualization.json；窗口内可换任意会话）
    │   │   ├── export_visualization.py  把会话导出为 traj3d.json / visualization.json
    │   │   ├── seed_picker.py      GUI 点选左右球心 -> derived/seeds.json
    │   │   ├── run_tests.py        ★ 回归测试运行器（fast / full 两档，项目里唯一跑全套的地方）
    │   │   └── setup_env.py        一键环境安装器：建隔离环境、装依赖，并登记给所有启动入口
    │   │                           选项：--verify（只体检）/ --isolate（强制 .venv）/ --ai（额外 YOLO/SAM）
    │   │                           / --adopt（登记现成环境）/ --force（重建）/ --dry-run（只演算）
    │   │                           需要机器先有可运行的 Python 3.10+；环境指针写 config/python_env.txt
    │   ├── 【GUI 外壳】窗口框架，不含业务
    │   │   ├── _gui_app.py         应用外壳：唯一 Tk 根 + AppState + 窗口单例表 + 门厅 + 控制台
    │   │   ├── _gui_widgets.py     基础控件：样式 / 卡片 / 参数行 / 按钮层级 / 换行回排 / 状态条
    │   │   ├── _gui_console.py     控制台窗口：任务表 + 运行日志（单例；**唯一**能中断任务的窗口）
    │   │   ├── _gui_mono.py        单目模式窗：① 内参 -> ② 球与量程 -> ③ 开始
    │   │   ├── _gui_stereo.py      双目模式窗（parallel / angled 共用一份代码，按 mode 参数化）
    │   │   ├── _gui_bench.py       会话工作台：在已录会话上按 ①–⑤ 走完离线链路
    │   │   ├── _task_runner.py     任务进程管理：启动、读输出、逐行落盘、停整棵进程树
    │   │   ├── _window.py          窗口助手：全屏 / 初始尺寸 / 按键约定（7 个程序共用）
    │   │   ├── _collapsible.py     可展开/收起的设置区（基本/高级）
    │   │   └── _gui_geometry.py    窗口工作区自适应 + 换行宽度计算
    │   ├── 【对话框】点了才出现的窗口
    │   │   ├── profile_dialog.py   装置档案：列出 / 切换 / 新建当前装置（含它配的标定）
    │   │   ├── cameras_dialog.py   相机管理：列设备 + 多路同时预览 + 按名字绑左右 / 主 / 无关
    │   │   ├── fov_dialog.py       FOV 管理器：查看 / 测量 / 清除这台机器两路相机的固有视场差
    │   │   ├── tools_dialog.py     「标定与训练」工具台：六条只能在命令行走的流程搬到界面
    │   │   ├── junk_dialog.py      垃圾管理器：先看清、再勾选、才删除；另有三个「一键」入口
    │   │   ├── cleanup_dialog.py   清理/回收站：预览、软删除、恢复、彻底删除
    │   │   ├── data_manager.py     ★ 数据管理面板：勾选会话、脱敏、按类别打 zip、导出轨迹数据
    │   │   └── help_window.py      操作说明窗口：左侧分类树、右侧正文、顶部搜索
    │   ├── 【数据 / 清理】纯逻辑，不带界面
    │   │   ├── _session_index.py   组织层：collections.json（虚拟分组树）+ index.json（派生索引）
    │   │   ├── _data_export.py     导出纯逻辑：脱敏 / 文件分类 / manifest / zip
    │   │   ├── package_export.py   P2 目录包：export_package / read_package / import_package（自包含交付）
    │   │   ├── _mono_sessions.py   单目会话：一个目录 = 一次录制 + derived/（与双目同构）

    │   │   ├── _stereo_layout.py   会话的磁盘布局：按装置几何分区后，怎么找、怎么判定这段会话属于哪套装置
    │   │   ├── _cleanup.py         清理纯逻辑：路径安全 / 移到 _trash / 恢复 / 清除
    │   │   ├── _junk.py            垃圾盘点：只认白名单里「可再生的东西」，别的一律不碰
    │   │   └── _workbench.py       会话摘要/按钮状态（只读，无 Tk）
    │   ├── 【共用】跨模块的薄层
    │   │   ├── _actions.py         界面动作 -> 命令行：argv 拼装的唯一产地（两套界面不再各拼一遍）
    │   │   ├── _common.py          app 层共用：日志装配、单目/双目参数块与打开

    │       ├── build_opening_report.py   ★ 一键重建开题报告 PPT（主入口）

## `logs/` 里会出现什么（按来源分，删了只是丢历史）

```
logs/
├── tasks/<日期>/      启动器每个任务的完整输出（命令行 / PID / 全部输出 / 退出码 / 耗时）
├── calib/<年月>/      双目标定、单目标定、采板图
├── capture/<年月>/    双目 / 单目录像
├── realtime/<年月>/   实时检测（含每 5 秒一行健康度）
└── misc/<年月>/       训练、一次性脚本
```

> 路径只能来自 `sphere_tracker.paths.log_dir()`；新入口登记在
> `apps/_common.LOG_TAGS`。任务按**日**分片、其余按**月** —— 量级不同。
>
> 2026-11-04 之前日志平铺在 `outputs/logs/`（9196 个文件）。老日志已搬进
> `logs/`；若再看到 `outputs/logs`，那是旧版本写的残留，「一键清日志」会清掉。
