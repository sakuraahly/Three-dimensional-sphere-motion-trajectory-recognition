## 五条放置规则

1. **库代码放 `sphere_tracker/`、`calib/`、`stereo/`**，不要写进 `apps/`。
   判断标准：能被 import 复用 = 库；跑一次就有结果 = app。

2. **测试放 `tests/`，一次性工具放 `apps/tools/`**。
   回归测试是这个项目的质量底线 —— 任何代码改动后都要能一键复跑（现有**八个**，
   清单见上面的目录树；其中 `selftest_preview_lib.py` 依赖 PPT 用的
   python-pptx / Pillow，缺了会整体跳过并算通过，纯运行环境也能跑全套）。

3. **能重新生成的东西一律不进版本库**（`outputs/`、`config/`、权重、视频素材）。
   需要长期保存的标定结果，手动拷到 `docs/` 或删掉 .gitignore 里对应那行。

4. **交付物不放 `outputs/`**。`outputs/` 的语义是"删了也能重新生成"，
   而开题报告、答辩稿这类东西删了就没了。它们放 `docs/` 或你自己的课程目录。

5. **根目录的 `启动程序*` 是"面向人的入口"，属于规则 1/2 的有意例外。**
   它们不是库、也不是算法程序，只是"收集参数 → 调用 `apps/` 里已有程序"的薄壳；
   放根目录的唯一价值就是让人（和老板）一眼看到、双击即用，放深了反而失去意义。
   **除这四个文件外，根目录不要再放别的脚本** —— 新功能仍按规则 1/2
   落到 `apps/`、`sphere_tracker/`。

## `outputs/` 里会出现什么（都可以放心删）

| 条目                              | 是什么                                   | 怎么再生                             |
| --------------------------------- | ---------------------------------------- | ------------------------------------ |
| `videos/annotated.mp4`            | 标注后的视频                             | `apps/run_video.py`                  |
| `traj.csv` / `synthetic_traj.csv` | 轨迹导出                                 | 同上 / `tests/selftest_synthetic.py` |
| `final_preview/`                  | PPT 排版预览 PNG                         | `apps/tools/preview_pptx.py`         |
| `_pair_source_tmp/`               | `selftest_pair_source.py` 的临时素材     | 每次跑测试自动重建                   |
| `_camera_registry_tmp/`           | `selftest_camera_registry.py` 的临时配置 | 每次跑测试自动重建                   |
| `_preview_lib_tmp/`               | `selftest_preview_lib.py` 的临时 PNG     | 每次跑测试自动重建                   |
| `images/`                         | 逐帧导出                                 | `run_video.py --frames-dir`          |

> ⚠️ `outputs/` 被整个 gitignore 忽略（见 `.gitignore`）。
> **往里放交付物 = git 里没有副本**，文件一丢就找不回来。

## 依赖方向（不要制造环）

    config / types / geometry        （最底层，不依赖任何本项目模块）
        ↑
    detectors/  camera_motion/       （检测与运动估计）
        ↑
    track / predict / sources / viz / camera_registry
        ↑
    pipeline                         （编排）
        ↑
    calib  →  stereo                 （双目，依赖库但不被库依赖）
        ↑
    apps / tests                     （只调用，不被调用）

> `camera_registry` 与 `sources` 同层：它只**惰性** import 一次 `sources`
> （`camera_registry.py:397` 的 `from .sources import CameraSource`，
> 不探测相机就用不到 cv2），其余只用标准库；反过来 `sources` 不 import 它，
> 所以不成环。`stereo/pair_source.py` 也依赖它来解析角色名。

反向依赖（比如 `geometry.py` 去 import `pipeline`）会立刻把项目变成一团乱麻。
