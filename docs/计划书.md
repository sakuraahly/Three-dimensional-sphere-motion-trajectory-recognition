## 1. 最终交付物

一套能实时运行的**双目球形物体三维轨迹识别与预测系统**：

1. 两台相机实时采集 → 2D 检测 + 跟踪（任意球形物体，不依赖特定颜色）
2. 三角测量得到三维坐标 (X, Y, Z, t)
3. 三维轨迹平滑（Savitzky-Golay / Kalman）
4. **预测未来 0.1–0.5 s 的三维位置**
5. 三维轨迹可视化（Plotly 或 Unity）
6. （可选）PID 云台跟踪

### 验收标准（全部要可量化、可复现）

| 项 | 指标 | 现状 |
|---|---|---|
| 2D 检出率 | ≥ 95%（球完整可见时） | ✅ 100%（合成） |
| 2D 圆心精度 | ≤ 1.5 px | ✅ 0.54–0.87 px（合成） |
| 半径精度 | ≤ 0.5 px | ✅ 0.06–0.23 px（合成） |
| 双目极线误差 | ≤ 0.3 px | ✅ 0.067 px（合成，**待真机验证**） |
| **三维定位误差** | **≤ 10 mm @ 1 m** | ⏳ 合成 1.0–3.4 mm，**真机未测** |
| 预测误差 @0.2 s | ≤ 5 px（2D）/ ≤ 30 mm（3D） | ⏳ 2D 合成 1.2–2.5 px |
| 实时帧率 | ≥ 25 fps | ✅ 34 fps（单目） |

### M2 视频同步 ✅ 模块完成 + 取帧已接入，⏳ 待真机验证

`stereo/sync.py` 已实现并验证（人为平移 0/±8/-11/+37 帧全部找回，置信度 1.000）。
做法是闪光/拍手对齐：两路亮度序列求差分后做归一化互相关，取相关性最大的偏移。

它按帧号把两路配到同一物理时刻。正负号语义与 `stereo.sync.apply_offset` 一致，
并有 `tests/selftest_pair_source.py` 兜住（把帧号编进合成画面逐帧核对）。

      （消除 app 间互相 import，详见交接文档 8.3 之 (1)）

**剩余**：
- [ ] 真机录一段带闪光的视频，验证真实条件下的偏移估计
      （注意：**实时相机不支持偏移**，必须录成文件再用 `find_offset` 处理）

**注意**：

### M3 极线配对 + 三角测量 ✅ 模块完成 + 代码侧已接进双目链路，⏳ 待真机

`stereo/triangulate.py` 已实现并验证：
- `match_epipolar()`：利用极线约束把二维搜索降成一维（右图给 3 个候选含 2 个干扰，配对率 100%）
- `StereoReconstructor`：逐帧配成三维轨迹，输出交会残差作为置信度
- 合成真值下三维误差均值 1.31 mm、交会残差中位 0.105 px

**代码侧已经打通并回归**（`tests/selftest_stereo_branch.py`）：
两路各自渲染真实画面 → 各自跑 `SpherePipeline` → `StereoReconstructor` → 比真值。
clean 配对率 100%、三维 RMSE 15.6 mm（折算 1 m 处 1.13 mm）；
realistic 配对率 99.4%、三维 RMSE 31.6 mm（折算 1 m 处 2.27 mm）。
详见交接文档 4.4。

**剩余：**
- [ ] 真机标定 + 真机录两路视频，跑同一套评估（当前全部是合成真值）
- [ ] 接到 `apps/run_realtime.py`：现在实时程序只跑一路，要做双路实时
      （代码侧的**算法链路已验证**，剩下的是采集与显示编排）
- [ ] 单路丢失时的兜底：用极线搜索 + 模板匹配在另一路补检

**验收**：静止球的三维坐标重复性 ≤ 5 mm；已知距离的球深度误差 ≤ 2%。

**注意**：三维绝对误差随距离**平方**增长（`εZ = Z²/(f·B)`）。
本装置 1 px 视差误差 = 7.5 mm 深度误差 @ 3.73 m。
所以"4 m 处 30 mm"和"1 m 处 10 mm"不是一回事，比较时必须折算到同一距离。

## 3. 关键技术决策（已定，别推翻）

| 决策 | 理由 |
|---|---|
| 用**几何 + 亚像素**而非深度学习做半径 | YOLO 零样本半径误差 0.4 px 且会把橙色圆判成 frisbee；几何+径向细化能到 0.06 px |
| 用**棋盘格**标定 | 三维坐标由定义精确已知，不依赖任何测量仪器，精度只取决于打印 |
| 标定**只收静止帧** | 静止目标在任意时刻看起来一样 → 顺带解决左右不同步问题 |
| 分级检测（粗检 + 精准复核） | `EXHAUSTIVE` 找不到板会穷举 302 ms，不能每帧跑 |
| 相机运动估计用**多数派优先** | 相位相关会锁到运动物体上，静止场景报 6–16 px 假位移 |
| 线程化采集 + 取最新帧 | 顺序读两路要等两次帧间隔，处理慢了还会积压延迟 |
| 极线约束配对 | 把右图搜索从二维降成一维，是双目实时的前提 |
