> **这份手册写给"要用这套系统的人"**：不想看代码，只想把它跑起来看效果，或者要去做真机标定。
> 以操作为主，**每条命令都能直接复制粘贴**。
>
> - 项目是什么、文档怎么配合读 → 入口文档 [`项目总纲.md`](项目总纲.md)
> - 深入原理、看踩过的坑 → [`交接文档.md`](交接文档.md)

## 1. 这是什么 / 能做什么 / 不能做什么

### 1.1 一句话

**用两台普通 USB 摄像头（双目），实时识别一个球形物体在三维空间中的位置，重建它的运动轨迹，并预测未来位置。**

深度（前后距离）不是靠"球看起来多大"猜的，而是靠**两台相机的视差**算出来的 —— 这才是"双目"的全部意义。

### 1.2 能做什么

| 能力 | 说明 | 怎么用起来 |
| --- | --- | --- |
| **检测** | 四条互补线索：颜色分割 / 霍夫圆 / 背景差分 / 投票融合；可选 YOLO·SAM | `--method fusion`（默认） |
| **亚像素定位** | 径向一致性判据 + 边缘细化，半径误差 0.06 px 量级 | 默认开启，无需操作 |
| **跟踪** | 卡尔曼滤波 + 机动检测 + 反弹重初始化，能扛短暂遮挡与漏检 | 默认开启 |
| **单目测深** | 球直径先验 `Z = f·R/r`，需先标定焦距、量准球径 | `--ball-diameter` + `--focal` |
| **轨迹预测** | 已知重力约束 + 最长有效后缀拟合，预测 0.1–0.6 s 后的位置 | `--horizon`（默认 0.6 s） |
| **双目三维** | 棋盘格标定 → 视频同步 → 极线配对 → 三角测量 → 输出 (X, Y, Z) | 见 §4 六步流程（**真机未验证**） |
| **实时与离线** | 实时窗口交互；也可批处理视频/图片并导出 CSV | `run_realtime.py` / `run_video.py` |

### 1.3 不能做什么（先看清楚，省得白忙）

| 限制 | 说明 |
| --- | --- |
| **不依赖特定颜色只是目标，颜色仍是主力** | 橙色球只是已验证样例；球与背景同色时检出率会掉 |
| **拍摄时曝光 / 白平衡 / 焦距必须固定** | 颜色线索靠阈值，自动曝光一抖阈值就废了 |
| **三维可视化没做** | 只有实时窗口的俯视/侧视小面板，没有可交互三维轨迹图 |
| **真机标定从未跑过** | 所有双目精度数字都来自**合成真值**，不是真实相机 + 真实打印标定板 |
| **多球跟踪没做** | 现在跟的是"一个球"，画面里两个球会互相抢 |
| **双目还没接进实时主流程** | `stereo/` 模块已就绪并测过，但实时窗口目前只跑一路（单目） |
| **不适合户外 / 高速工业场景** | 目标是实验室条件：固定机位、照明良好、球完整可见 |

## 2. 三步跑起来

### 2.1 环境要求

Windows 上已配好，**不需要额外安装任何包**。Python **必须用绝对路径**：

```powershell
$PY = "$env:USERPROFILE\miniforge3\envs\myenv\python.exe"
cd D:\MY_CODING_PROGRAM\Three-dimensional-sphere-motion-trajectory-recognition
```

> ⚠️ **别用裸 `python`**：它会解析到 msys64 那个没装 opencv 的解释器，报 `No module named 'cv2'`；下面所有命令都复用 `$PY`。

### 2.2 最省事的入口：双击 `启动程序.bat`（唯一的入口）

**项目根目录只有这一个需要你双击的文件。** 它会自动做完三件事：

1. **找 Python** —— 不是随便找 `python.exe`，而是逐个候选**真的试一次
   `import cv2, numpy`**，谁通过用谁。所以 PATH 里那个没装 opencv 的 msys64
   Python 会被自动跳过，你不会再看到 `No module named 'cv2'`；
2. **缺依赖就问一句，然后自动装** —— 找不到可用的 Python 时，它会找到任何一个
   能跑的 Python，问你一句要不要装，同意就用清华镜像装 `requirements.txt`
   （镜像失败自动退回官方源），装完复验 `import cv2`；
3. **启动界面** —— 默认图形界面；这台机器没有 `tkinter` 就**自动换成命令行界面**。

启动时会打印实际用的解释器与版本，例如：

```
[1/3] 检查 Python 环境 ...
      找到：%USERPROFILE%\miniforge3\envs\myenv\python.exe
      Python 3.14.7 / opencv 5.0.0 / numpy 2.5.3
[3/3] 启动图形界面 ...
```

#### 只想重做某一步？给 `启动程序.bat` 加一个参数

**不需要额外记别的文件**。在文件夹里按住 Shift 右键 →"在此处打开 PowerShell 窗口"，
或者直接在地址栏敲 `cmd` 回车，然后：

```bat
启动程序.bat            :: 图形界面（默认，等于双击）
启动程序.bat cli        :: 命令行界面
启动程序.bat setup      :: 相机设置（左 / 右 / 无关）
启动程序.bat check      :: 相机检查（有没有漂移）
启动程序.bat precheck   :: 标定前置检查（两路是否都看到棋盘）
启动程序.bat calibrate  :: 双目标定
启动程序.bat verify     :: 标定复检
启动程序.bat run        :: 实时检测
启动程序.bat test       :: 回归测试（默认快速档，约 1 分钟；加 full 跑全套 22 个）
```

> **日常使用不必敲这些**：双击 → 图形界面第 1 步就有
> `相机设备管理（识别 / 固定 / 标无关）`、`检查相机映射`、`标定前置检查`、
> `运行标定 / 复检`、`「无关」相机清单` 等按钮，参数化只是给"反复重标定"这种
> 场景省两下点击。

**这些参数与图形界面里的按钮是同一套命令**，界面与经过测试的底层链路始终一致。

> **为什么只有一个 .bat**：`.bat` 不适合承载逻辑（没有数组/异常，字符串处理靠
> `for /f` 硬凑），菜单必须活在 Python 里；而"图形 / 命令行"只是同一套菜单的
> 两种呈现，所以用 `cli` 参数区分，不额外给命令行版一个文件。
> 详见 `docs/文件结构.md` 第 5 条。

#### 「无关」是什么

一台相机有三种**并列**的明确去处 —— 在 `identify`（图形界面第 1 步的
『相机设备管理（识别/固定/标无关）』，或 `启动程序.bat setup`）的画面里按键：

| 按键 | 含义 |
| --- | --- |
| `l` | 这台是**左**相机 |
| `r` | 这台是**右**相机 |
| `n` | 这台**「无关」** —— 永远不要用它 |
| `m` | 单目**主**相机（只看一路时用） |
| `s` | 跳过，不改配置 |
| `q` | 退出 |

**「无关」的用处**：笔记本内置相机、红外相机这类**不该参与双目**的设备，
标一次就再也不用管 —— 自动挑相机（`--auto-cameras`、`--camera auto`）
会跳过它们，不会再出现"左边是外接、右边却挑到笔记本内置"。

- 左 / 右 / 无关**三者互斥**：改标一个，旧标记自动摘掉（不可能既是左相机又是「无关」）。
- 记的是**设备身份**，不是编号 —— 换 USB 口之后标记依然有效。
- 万一**其它相机都不够用**，程序会**兜底动用**「无关」的相机，但一定会打印警告 ——
  它不会静默用错，也不会让你空手而归。
- 显式写编号（`--camera 3`）**仍然会用它**：你点名的那台优先级最高。
- 管理：`& $PY apps\tools\cameras.py ignored` 看清单、
  `unignore 3` / `unignore --all` 取消；图形界面有对应的
  `「无关」相机清单` / `清空「无关」标记` 两个按钮。

> "这条失败里有多少是代码的锅"。

先设好这两行（后面全部命令都基于它）：

$PY = "$env:USERPROFILE\miniforge3\envs\myenv\python.exe"

### 3.1 实时检测

```powershell
# 不写编号：启动时自动挑最优（优先外接、避开标了「无关」的、跳过全黑流）—— 推荐
& $PY apps\run_realtime.py
# 指定编号（单目用；角色名 left/right 只对双目有意义）
& $PY apps\run_realtime.py --camera 0
# 指定编号 + 分辨率 + 帧率（编号会漂移，见 §5）
& $PY apps\run_realtime.py --camera 0 --width 1280 --height 720 --fps 60
# 白球预设 + 球直径/焦距
& $PY apps\run_realtime.py --camera 0 --preset white_ball --ball-diameter 0.04 --focal 831
# 录制标注后的画面（按原始分辨率存，不受 --display-width 影响）
& $PY apps\run_realtime.py --camera 0 --record outputs\videos\session.mp4
# 真纹理场景要跑 hough/fusion，必须同时降检测分辨率（否则几秒一帧，见下）
& $PY apps\run_realtime.py --method fusion --detect-width 960
```

> `--camera` 取值：`auto`（默认）/ 编号 / 角色名。**优先 `auto`**。
> 「无关」只在**自动挑选**时生效 —— 你显式写 `--camera 3` 仍然会用它（显式指定优先级最高）。
>
> ⚠️ **`main` 角色已经删掉了**（2026-10-14）：它指的是笔记本内置相机，
> 而那台已被标成「无关」且实测**打不开**。保留一个必定报错的选项只会误导人。
> 单目要用内置相机就直接写编号 `--camera 2`（能打开的话）。

`--method`：`color`（**默认**，最快）/ `fusion`（最稳，但**最慢**）/ `hough` / `motion` / `yolo` / `yolo_sam`。
`--preset`：`white_ball` / `orange_ball` / `green_ball` / `blue_ball` / `red_ball` / `yellow_ball`。

> **图形界面里的默认值也是 `color`**（2026-10-14 对齐）。此前界面默认写的是
> `fusion`、命令行默认是 `color` —— 于是**从界面走的人必然吃上 265 ms/帧**
> （实测 `loop 3.7 fps`、丢帧 91%），而文档三处都写着"默认 color"。
> 界面的下拉框仍可切到 `fusion`，只是**默认不再替你选最慢的那个**。
> 这条现在由 `tests/selftest_launcher_params.py` 第 0 节钉住（两个变异都会报红）。

**⚠️ 方法选择要看画面纹理，不能只看"哪个词听起来稳"**（2026-10-14 实测，1920x1080）：

| 方法 | 简单画面（纯色底 + 一个圆） | **真实房间（书架、床、杂物）** |
| ---- | --------------------------- | ------------------------------ |
| `color` | 17.7 ms → 56 fps | **17.8 ms → 56 fps** |
| `motion` | 18.5 ms | 15.5 ms |
| `hough` | 132 ms | **4384.9 ms → 0.2 fps** |
| `fusion` | 181 ms | **3740.5 ms → 0.3 fps** |

`hough` 先做 Canny 边缘，**纹理一多边缘就爆炸**。真实房间**永远**是纹理丰富的，
所以"合成图上测得挺快"没有参考价值。**默认因此从 `fusion` 改成了 `color`。**

要用 `hough`/`fusion` 就必须配 `--detect-width`（见下），否则几秒一帧。

**两个显示/性能参数**：

| 参数 | 默认 | 作用 |
| ---- | ---- | ---- |
| `--display-width` | **960** | 显示图宽度。`cv2.imshow` 缩 1080p 要 17.7 ms/帧，先缩到 960 只要 1.84 ms（**便宜 9.6 倍**）。实测 `loop` 65.2 → 78.5 fps。给 `0` = 不缩（旧行为） |
| `--detect-width` | 0（不缩） | **检测**跑在多宽的图上，坐标自动换算回原图（实测误差 1~2 px）。缩到 960 约再快 3 倍 |
| `--log-every` | 5 秒 | 每隔几秒往日志写一行健康度（`0` = 不写） |

| 键 | 功能 | 键 | 功能 |
| --- | --- | --- | --- |
| `q` | 退出 | `c` | 切换检测方法 |
| **`f` / F11** | **全屏** | **`ESC`** | **全屏时=退出全屏**；不在全屏时才退出程序 |
| `r` | 重置轨迹（球飞出去后重新开始） | `m` | 开/关分割掩膜小窗（调阈值必备） |
| `s` | 保存当前标注帧 + 当前配置 | `p` | 开/关轨迹预测 |
| `v` | 开始/停止录制 | `3` | 开/关三维视图小面板（俯视 X-Z + 侧视 Y-Z） |
| `空格` | 暂停 / 继续 | | |

> ⚠️ **`Esc` 的优先级是刻意的**：全屏之后第一反应就是按 Esc 退出来，
> 如果它直接退出程序，你会把正在跑的东西关掉。

HUD（窗口左上角）实时显示：`cap` / `loop` / `detect ms` / `age` / `drop` / `method` /
`score` / `r`（像素半径）/ `track #` / 像素坐标 `px` / 速度 `v` / 加速度 `a` /
三维 `3D X Y Z m` / 预测 `predict` / 相机 `cam MOVING|still`。

> **`cap` 与 `loop` 为什么要分开看**：只有一个裸 `FPS` 时，
> "相机只给了 15 fps"和"我们处理得慢所以只有 15 fps"**在画面上完全一样**，
> 优化方向只能靠猜。`cap` 明显高于 `loop` = 瓶颈在我们这边；反过来 = 相机那边。
> `age` 是"当前这帧是多久以前抓的"，它一大就说明在积压（画面会显得顿）。
> `drop` 是取走前被覆盖的帧数。采集停住时会显示 `** STALL **`。

**日志**：每次运行都会写 `outputs/logs/realtime_<日期>_<时间>.log`，
里面有环境、相机模式、每 5 秒一行健康度、**逐帧检测明细**（DEBUG）、
你按过的每个键、以及结束时的一份完整快照。**卡顿了就把那一行健康度发出来。**

## 4. 第一次上手的推荐顺序（真机双目）

**照顺序做，别跳步。** 每一步都写清"在干什么、为什么"。

> 💡 **不想敲命令的话**：这一节的第 1～6 步都能用同一个入口直接做 ——
> `启动程序.bat setup` / `check` / `precheck` / `calibrate` / `verify` / `run`，
> 或者双击后在图形界面里点按钮。下面给的是等价命令，便于理解和脚本化。

### 第 1 步 · 固定左 / 右 / 无关角色（`启动程序.bat setup`）

```powershell
& $PY apps\tools\cameras.py identify
```

逐个索引弹窗显示画面，你按 `l` / `r` / `n` 确认哪台是左、哪台是右、哪台**「无关」**，程序把**设备身份**（不是编号）写进 `config\cameras.json`。

- **为什么**：编号会随 USB 口漂移（见 §5），角色名不会。做完这一步，以后启动一律用 `--left left --right right`。
- 左右约定：**人面对镜头时，左手边那台为"左"**。
- **不打算用的相机就在这一步按 `n` 标成「无关」**（笔记本内置、红外相机）。
  本机枚举到的 4 台里，`#3 Integrated IR Camera`（红外、无彩色、OpenCV 打不开）
  就是典型该标「无关」的；标掉之后自动挑相机不会再考虑它。
- ✅ **本机 `config\cameras.json` 已存在**（2026-10-10 跑过 `identify`）：
  `left` = `#1 aoni A25`、`right` = `#0 aoni A25`。
  （`main` 角色已删除 —— 内置相机被标「无关」且实测打不开。）
  所以下面的示例都用角色名 `left` / `right`；**没做过这一步的机器**请改用
  `--auto-cameras`（自动挑两台），别用会漂移的编号。

### 第 2 步 · 探测两路的分辨率 / 帧率

```powershell
& $PY apps\tools\cameras.py list --probe          # 快，推荐
& $PY apps\tools\list_cameras.py --max-index 5    # 慢，但报实测帧率
```

- **为什么**：双目要求两路**同时**稳定出图；某台只有 10 fps 就会卡住实时双目（要求 ≥25 fps）。
- **请求分辨率 ≠ 实际分辨率 ≠ 实际帧率**：`CAP_PROP_FPS` 返回的是"你请求的值"，不是真值（实测请求 60、实际 29.8）。
- 参考基线（`config\camera_modes.json` 当前缓存，**编号↔设备的对应以当场 `cameras.py list` 为准**，缓存随插口/协商变化，必须当场复测）：

| 编号 | 后端 | 请求 | 实际 | 实测帧率 |
| --- | --- | --- | --- | --- |
| 0 | DSHOW | 1024×768 | 1280×720 | 16.58 fps |
| 1 | DSHOW | 1920×1080 | 1920×1080 | 29.47 fps |
| 2 | MSMF | 1280×720 | 1280×720 | 41.47 fps |

> 历史上编号 1 缓存过 **9.9 fps**，那条旧记录**已经被上面的重新探测覆盖**了。
> 但要小心两点：
> 1. **缓存是按"编号"存的，编号一漂移这份表就对不上了** —— 它只能当参考，
>    真实帧率以当场 `list_cameras.py` 的输出为准；
> 2. **"哪个编号是笔记本内置相机"目前没有定论**：`README.md` 的枚举样本说 0/1 = 外接
>    aoni、2/3 = 内置/红外，而 `docs/交接文档.md` §7.3 的老记录说是 0/2 = 外接、1 = 内置，
>    两者矛盾且都无法在没相机的地方证实。**先跑 `identify` 目视确认。**
>
> 不管哪台是哪台，**内置相机不要用于双目**（没法刚性固定在横梁上）。
> 另外注意上表编号 0 只有 16.58 fps，**低于双目 ≥25 fps 的要求**。

### 第 3 步 · 标定前置检查（两路都看到棋盘、视野重叠）

```powershell
& $PY apps\tools\check_stereo_setup.py --left left --right right --cols 8 --rows 5 --square 25 --seconds 8
```

举着打印好的棋盘格在两路画面里慢慢移动，让它都出现过。输出形如：

```
左路看到棋盘      : 87/240  (36%)
右路看到棋盘      : 90/240  (38%)
两路同时看到      : 85/240  (35%)
左 / 右 分辨率    : (1280, 720) / (1280, 720)
[通过] 两路都能稳定看到棋盘 —— 视野重叠良好，可以开始标定。
```

- **为什么**：标定能成功的**第一个前提**就是"棋盘同时落在两个相机的视野里"。不做这步，标定时会一直收到 0 对帧，却分不清是视野不重叠还是相机坏了。
- `[失败] 只有右路能看到棋盘` 之类：先把两台相机的朝向调近、让视野重叠。
- 分辨率不一致会被警告：**标定要求两路完全一致**，先设成同一分辨率。

### 第 4 步 · 刚性固定（这一步是标定的硬前提）

把两台相机**锁死在同一根横梁 / 支架上**，之后不要再动。

- **为什么**：标定解出的旋转 `R`、平移 `T` 描述"两台相机之间的相对位姿"。**装置一动，R/T 立刻作废** —— 而画面看起来完全正常、指标也好看，只有三维结果系统性偏，这种错最难发现。
- 整体移动没问题（R/T 是常数，得到的是"相机坐标系下的轨迹"）；**两台各自移动完全不行**。

### 第 5 步 · 双目标定

```powershell
& $PY apps\calibrate_stereo.py --left left --right right --cols 8 --rows 5 --square 25
```

把板举到**两路都能看到**的位置，慢慢移动，**每个姿势停稳约 1 秒**（程序只收停稳的帧）。收满 25 对后自动标定，
输出质量报告并保存 `config\stereo_calibration.npz`（参数）+ `config\stereo_calibration.json`（人读报告）。

- **期望**：极线误差 **< 0.3 px**（验收线）。没通过质量判定不会保存，按提示重拍。
- **判定分四级**：优秀 / 可用 / **勉强可用**（精度刚过 ok 线但**基线没错** —— 会保存，
  报告里写清差在哪、怎么改）/ **不可用**（基线对不上 / 有效对 < 8 / 求解发散）。
- ⚠️ **判"不可用"时不会保存任何文件** —— 那是设计（"失败却留下一个能读的标定文件"更危险），
  不是程序坏了。此时 `config\` 下**不会有** `stereo_calibration.*`，`verify_stereo.py` 也就无从跑起。
  **要看差在哪，读那份日志**：`outputs\logs\calibrate_<时间>.log` 里有完整拒收分布与逐项指标。
  目前 `config\` 下**没有任何 `stereo_calibration.*`** —— 即还没有一次可用的真机标定结果。
- 可选参数：`--target 25`（收多少对）、`--min-pairs 10`、`--baseline-mm <你量到的毫米数>`（预期基线，用来核对 —— **必须自己量，别照抄范例数字**）、`--save-pairs outputs\pairs`（另存收下的图像对，便于复查）、`--report-png outputs\calib_check.png`（验证图）。

> ⚠️ **`--baseline-mm` 要量当前装置的两镜头中心距，不是抄别人的数字。**
> 这一条是**唯一能发现"左右对应关系错配"的物理量**（详见 `真机标定操作清单.md` §2）。
> 给错比不给更糟：不给只是"守卫关着"，给错会让程序把**正确**的标定报成"基线对不上"，
> 或者把偏了的放过去。**重新摆过相机就要重新量。**
- **同步**：**标定不需要左右同步** —— 板是静止的，静止目标在任意时刻看起来都一样。

> ⚠️ **只有拍运动物体（小球）时才必须同步。** 实测右路只滞后 1 帧（17 ms），三维误差就涨 17–34 倍。

### 第 6 步 · 复检并记下基线

```powershell
& $PY apps\verify_stereo.py --calib config/stereo_calibration --left left --right right
```

```
标定时记录的极线误差：0.0670 px
本次复检：8 帧，极线误差 RMS 0.0812 px（最大 0.1203 px）
变化量：+0.0142 px
[通过] 装置未发生明显变动，可以继续使用现有标定参数。
```

- **为什么**：判断装置有没有被碰动。未动是 0.08 px 量级，碰动 2° 后是 27.9 px，差 250 倍，一看就知道。
- **判定**：极线误差 > 0.6 px，或比标定时增大超过 `--tolerance`（默认 0.15 px）→ `[不通过]`，需重新标定；**把"标定当时"那个数抄进实验记录**，以后每次拍摄前对比。

## 5. 相机为什么用"角色名"而不是编号

`cv2.VideoCapture(0)` 里的 `0` 由系统枚举顺序决定：换一次 USB 口、多插一个设备，编号就可能变。
本机实测就漂过：早期是"0、2 = 外接，1 = 内置"，换了个 USB 口之后变成"0、1 = 外接，2 = 内置"。
把 `--left 0 --right 1` 写死，索引一变就会**悄悄用错相机**（画面完全正常），标定白做。

| 做法 | 命令 |
| --- | --- |
| **固定**（推荐） | `cameras.py identify` → 之后用 `--left left --right right` |
| **按端口/身份指定** | `--left port:Port_#0001.Hub_#0003`、`--right id:USB\VID_...`、`--right name:aoni` |
| **让它自动挑** | 不指定（`run_realtime.py` 默认）或 `--auto-cameras` |

**配置与实物对不上时，程序不会替你猜**：已 `identify` 确认过的角色若身份消失，会直接报错并附当前设备清单；交互式终端下还会把清单摆出来让你自己选编号。

```powershell
& $PY apps\tools\cameras.py check    # 有 [危险] 项（如索引被别的设备占了）时退出码为 2
```

> ✅ **本机现状（2026-10-10）**：`config\cameras.json` **已存在** ——
> `left` = `#1 aoni A25`、`right` = `#0 aoni A25`。
> 所以双目**优先用角色名**（`--left left --right right`），
> 不要再用编号：本机 `left` 是 `#1`、`right` 是 `#0`，**照直觉写 `--left 0 --right 1`
> 正好是反的**（画面一切正常，但标定出来的 R/T 是反的）。
> 没跑过 `identify` 的机器请用 `--auto-cameras`（自动挑两台）。

## 6. 标定板：打印与核对

`assets\boards\` 里已有可直接打印的文件：

```
chessboard_8x5_25mm_a4-landscape.pdf / .png     ← 内角点 8x5，方格 25 mm，A4 横版
chessboard_8x5_20mm_a4-portrait.pdf / .png      ← 内角点 8x5，方格 20 mm，A4 竖版
```

打印与核对三条（**一条都不能省**）：

1. **必须选"实际大小 / 100%"打印**，不要选"适应页面 / 缩放"。缩放过的板方格不是 25 mm，焦距与基线会系统性偏。
2. **打印后用尺子量方格边长**：量到多少，`--square` 就填多少（量出 24.6 mm 就写 `--square 24.6`）。
3. **贴在硬纸板 / 亚克力上**。板不平（卷曲、起皱）会让标定白做 —— 角点检测会系统性偏。

参数要与板严格对应：板是"内角点 8×5"就填 `--cols 8 --rows 5`（**是内角点数，不是方格数**；方格数是 9×6）。`--cols / --rows / --square` 在 `make_calibration_board.py`、`check_stereo_setup.py`、`calibrate_stereo.py`、`verify_stereo.py` 里是同一套参数名，默认值都是 `8 / 5 / 25.0`。

## 7. 看数字：指标含义与验收线

### 7.1 指标表

| 指标 | 含义 | 验收线 | 现在最好成绩（**合成真值**） |
| --- | --- | --- | --- |
| **检出率** | 球完整可见时能检出来的帧比例 | ≥ 95% | 100% |
| **圆心误差** | 检测球心与真值的像素距离（RMSE） | ≤ 1.5 px | 0.54–0.87 px |
| **半径误差** | 像素半径与真值之差（RMSE）—— 单目测深的命根子 | ≤ 0.5 px | 0.06–0.23 px |
| **跟踪误差** | 滤波后轨迹与真值的中位偏差 | — | 0.65 px |
| **预测误差** | 预测未来位置与真值之差（2D，@0.2 s） | ≤ 5 px | 1.20–2.49 px |
| **极线误差** | 立体校正后同名点偏离同一水平线的像素数（越小越好） | ≤ 0.3 px | 0.067 px（**真机未测**） |
| **三维定位误差** | 重建 (X,Y,Z) 与真值之差，**折算到 1 m 处** | ≤ 10 mm @ 1 m | 1.13–2.27 mm（**真机未测**） |
| **实时帧率** | 实时处理速度 | ≥ 25 fps | 34 fps（单目，合成条件） |

这些数字在跑回归测试时会直接打印（`selftest_synthetic.py`、`selftest_stereo_calib.py`、`selftest_stereo_branch.py`）。
实时运行时 HUD 左上角的 `FPS` 是当场实测值 —— **它就是帧率，不要信 `--fps 60` 这个请求值**。

### 7.2 必须折算到 1 m（这条最容易读错）

深度误差随距离**平方**增长：

```
εZ ≈ Z² · δd / (f · B)        Z=距离  δd=视差误差(px)  f=焦距(px)  B=基线(m)
折算到 1 m 的误差 = 实测误差 × (1 / Z)²
```

所以**"4 m 处的 30 mm"和"1 m 处的 10 mm"完全不是一回事**：

- 在 3.73 m 处量到三维 RMSE **15.6 mm** → 折算到 1 m 是 `15.6 × (1/3.73)² ≈ 1.13 mm`；在 4 m 处量到 **30 mm** → 折算到 1 m 是 `30 × (1/4)² ≈ 1.9 mm`，**远好于** 10 mm 验收线。
- 本装置（f≈889 px、B=150 mm）在 3.73 m 处，**1 px 视差误差 = 7.5 mm 深度误差**；所以 4 m 处三维 RMSE 落在 15–35 mm 是这条定律的**必然结果**，不是实现差。

> 严格说，随距离平方增长的是**深度分量**（`εZ`），横向分量随距离**线性**增长（`εX ≈ Z·δp/f`）；项目里"折算到 1 m"统一按 `Z²` 折算整条三维 RMSE，属于**偏严**口径，测试会自己打印这一行，别自己换个口径再对比。

### 7.3 这些数字是"合成真值"，不是真机能力

**合成真值** = 程序渲染出来的"假视频"，每个像素的正确答案已知。它能验证"几何链路和算法写对了"，但**不等于真实相机能做到** —— 真机的镜头畸变、光照变化、同步误差、滚动快门都比合成场景恶劣。
**双目这一整条（标定、同步、配对、三角测量）从未在真实相机 + 真实打印标定板上跑过**，这是当前最大的未知数；把上面那些数字当**上限参考**，不要当性能承诺。

## 8. 故障排查表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 裸 `python` 报 `No module named 'cv2'` | `python` 解析到 msys64 那个解释器，没装 opencv | 用绝对路径 `& "$env:USERPROFILE\miniforge3\envs\myenv\python.exe" ...`（先设 `$PY`） |
| 相机打不开 / 画面全黑 / `can't be used to capture by index` | ① 编号漂移 ② 别的程序占着相机 ③ 两台同型号走同一集线器同时打开会失败 | 跑 `cameras.py check` → `cameras.py list --probe` → `list_cameras.py`；关掉占用程序；**把两台相机分别插到机身上两个不同 USB 口（别走同一集线器）**；两路必须同一后端（`--backend auto/dshow/msmf`） |
| 两路分辨率不同（如 1280×720 vs 1280×1080） | 系统给每台相机协商出的模式不同 | 预览不会崩：程序**各自独立缩放、再补齐到同一高度**；但**标定要求两路完全一致**，先设成同一分辨率再标定（前置检查会警告） |
| 标定老说"棋盘还在移动，请停稳再收" | 板没停稳，或帧积压（读到旧帧） | 每个姿势**停稳约 1 秒**；实时相机走 `LatestFrameCamera` 取最新帧、不排队积压；手别抖 |
| **左 / 右装反** | 画面正常、单看指标也好看，但配对率 0%（"视差必须为正"的静默陷阱） | 现已自动判视差符号（`StereoRig.disparity_sign()`，`T[0] < 0` 时 `describe()` 打警告）；跑 `verify_stereo.py` 兜底；重跑 `identify` 把左右改正 |
| 分不清"请求分辨率 / 实际分辨率 / 实际帧率" | `CAP_PROP_FPS` **返回的是你请求的值**，不是真值（实测请求 60、实际 29.8） | 看 HUD 的 `FPS`，或 `list_cameras.py` 的实测帧率；录像/评估一律用实测值 |
| 某台相机帧率只有 ~10 fps，卡住实时双目（要求 ≥25 fps） | 分辨率/后端协商到低帧率模式 | 换一档分辨率（如 640×480）、换后端（`--backend dshow/msmf`）、换 USB 口；**A25 是 USB 2.0 设备，插蓝色 3.0 口也不会变快**，换口只为"分总线" |
| 处理视频时播放速度不对 | 把 `CAP_PROP_FPS`（请求值）当真实帧率用了 | 本项目时间戳走 `perf_counter`（真实时间），速度与预测时间轴是对的；自己写脚本时别用 `CAP_PROP_FPS` |
| 标定收不到帧 / `[失败] 只收到 N 对，少于 10 对` | 视野不重叠、板太小/太暗/贴边、移动太快 | 先跑 `check_stereo_setup.py`；板更大更清晰、慢一点、每个姿势停稳 1 秒、覆盖画面各区域 |
| 复检 `[不通过]` | 装置被碰动，或相机取下重装 | 重跑 `calibrate_stereo.py`；标定完**记下当时那条基线值**，以后每次拍摄前对比 |
| 检不到球 / 检到乱七八糟的东西 | 颜色阈值不对（曝光/白平衡一变就变） | 跑 `calibrate_color.py` 看掩膜里是不是只有球是白的；按 `1`-`6` 换预设；**拍摄时固定曝光/白平衡/焦距** |
| 深度不对（球在动 Z 却不动） | `--ball-diameter` 填错（填错多少，深度就错多少） | 用卡尺量球径，单位是**米**：`--ball-diameter 0.04` |
| 在 AI / 沙箱进程里查不到 USB 和相机 | 沙箱不在交互式桌面会话里，DShow/MSMF 按会话枚举相机 | **这不是你的机器坏了**；相机相关实测必须在自己的终端里跑 |

## 9. 已知限制（诚实清单）

| 限制 | 影响与说明 |
| --- | --- |
| **真机标定从未做过** | ⛔ 当前最大的未知数。所有双目精度都来自合成真值；不跑一次不知道真机能否达标（验收线 0.3 px / 10 mm@1m） |
| **三维可视化未做** | 只有实时窗口的俯视/侧视小面板；没有可交互三维轨迹图（plotly 未装，matplotlib 已装可作备选） |
| **反弹后 3–4 帧跟踪变差** | 机动检测需要观察窗口（速度突变要两次观测才测得出），约 0.05–0.07 s 后恢复，**物理限制**不是 bug |
| **多球跟踪未做** | 画面里两个球会互相抢；跟踪器支持多目标，但缺外观特征做关联 |
| **双目未接进实时主流程** | 实时窗口现在只跑单目；`stereo/` 已就绪并测过，缺的是采集与显示编排 |
| **三维轨迹平滑未做** | 导师建议 Savitzky-Golay 作首选、卡尔曼作升级项；目前只有 2D 卡尔曼 |

## 10. 出问题时按这个顺序查

1. **先跑回归测试**：`& $PY tests\selftest_synthetic.py` —— 通过说明是"相机/参数"问题，不是代码问题。
2. **再看相机**：`cameras.py check` → `cameras.py list --probe` → `list_cameras.py --max-index 5`。
3. **再看视野与标定**：`check_stereo_setup.py` → `calibrate_stereo.py` → `verify_stereo.py`。
4. **再看颜色与参数**：`calibrate_color.py`（掩膜对不对）、`--ball-diameter`（球径填对没）；还不行就翻 [`交接文档.md`](交接文档.md) §5「踩过的坑」与 §7「硬件现状」。

## 11. 两个最耗时间的坑（都有工具了）

### 11.1 "某一路画面明显不如另一路"——先分清是**带宽**还是**光学**

跑：

```powershell
启动程序.bat diag
# 等价于：& $PY apps\tools\camera_quality.py --left left --right right --together
```

它会逐台量，然后**给结论**。判据是这两种故障各自特有的指纹：

| 现象 | 带宽/链路不足 | 光学/曝光问题 |
| --- | --- | --- |
| 实测帧率 | 明显偏低；两路同开时骤降 | 正常 |
| **残帧**（下半幅是常量） | **会出现**（传输没传完） | 不会 |
| 实际分辨率 | 被驱动降到更低档 | 正常 |
| 清晰度（Laplacian 方差） | 正常 | **明显偏低** |
| 过曝 / 动态范围 | 正常 | 可能过曝，或范围被压扁 |

**关键认知：带宽不足不会让画面变"糊"，只会让它变"卡"。**
如果你看到的是"一边清楚一边像蒙了雾"，**那几乎一定不是 USB 的问题** ——
去擦镜头、撕保护膜、查起雾、查逆光，比换线换口有效得多。

**唯一的定性归因办法 —— 交换测试（5 分钟）**：

1. 把两台相机的 **USB 口对调**（连数据线一起对调），再跑一次 `diag`；
2. 问题**跟着相机走** → 是相机（光学/传感器）；问题**留在原来的口/线** → 是链路；
3. 再把两台插到**不同的 USB 控制器**上（机身不同的口，别都走同一个扩展坞）测第三次。

`--together` 会额外测"两路同开"：单开正常、同开掉速，才是真的带宽紧张。
本机两台 aoni 都在同一条 USB 2.0 总线上（见 [`交接文档.md`](交接文档.md) §7.1），
所以**分总线**是唯一值得试的方向 —— 注意 A25 是 USB 2.0 设备，插蓝口也不会变超速。

### 11.2 "标定收不到帧 / 手一抖就不收"

先看**标定窗口右上角那两行**（新加的）：它会逐路告诉你状态。

```
左: 未找到板
右: 清晰度  210 面积 4.2% 曝光 118
```

一眼就能看出是**哪一路**的问题。如果两路都写"未找到板"，右下角还会给出会诊，例如：

```
last: 左路未检测到棋盘（右路正常）｜左：画面动态范围被压到只剩 58 级（均值 196）——
      像蒙了一层雾：先擦镜头、撕掉保护膜，检查有没有起雾/结露、或有没有东西紧贴镜头
```

**90% 的"收不到帧"其实是画面质量问题，不是门限太严**（`x122 两路未同时检测到棋盘`
通常意味着一路压根看不见板）。先按 §11.1 把那一路修好。

如果画面已经正常、只是**手抖**，按"代价从小到大"这样处理：

| 办法 | 怎么做 | 代价 |
| --- | --- | --- |
| **① 让板"靠"住（最推荐）** | 把板**靠在椅背 / 纸箱 / 墙上 / 书架**上，或夹在书立、谱架上。你只需要它**停住 1 秒**，不需要三脚架 | 无。**这一步通常直接解决问题** |
| **② 提高快门（减少运动模糊）** | 开灯 / 加台灯，让画面更亮，自动曝光就会用更短的曝光时间；手抖带来的模糊随之变小 | 无 |
| **③ 放宽"停稳"门限** | `启动程序.bat` 之后在命令行加：`--stationary-px 8`（默认 3） | 中度。这条门限**同时替代了左右同步**，放太松 = 两路拍到不同位姿 → R/T 会系统性偏 |
| **④ 手持宽松预设** | `& $PY apps\calibrate_stereo.py --left left --right right --relaxed` | 较大。它同时放宽停稳(10px)、清晰度(28)、板的最小面积、贴边余量 |

> ⚠️ **`--relaxed` 是"用精度换成功率"**，程序会明确打印这句话。
> 判据：标定完看 **极线误差**，验收线是 **≤ 0.3 px**；
> 如果超了，或者代进三维后抖得厉害，就处理好光照与支撑、**去掉 `--relaxed` 重标一次**。

**为什么"停稳"这条门限不能随便关掉**：两台 USB 相机**没有硬件同步**，
程序只能保证"这一对帧是同一轮读出来的"。板在动的时候，左右两路实际拍到的
**位姿不同**，三角测量的约束就是错的 —— 而且这种错**不会报错**，
只会让标定结果整体偏掉、事后查不出来。所以"板静止"是用**静态目标在任意时刻
看起来都一样**这个性质，来替代时间同步。这是设计决定，不是苛刻。

**另一个常见误判**：`--cols/--rows` 填错（比如板是 9x6 内角点却填 8x5）。
角点数对不上时，检测器只会返回"找不到"，表现为和"画面太糊"一模一样。
用 `& $PY apps\tools\make_calibration_board.py --all` 生成时，
文件名里就写着内角点数，照着填。

## 12. 图形界面：窗口、任务、日志（2026-10-14）

### 12.1 所有视频窗口都能全屏

| 键 | 作用 |
| --- | --- |
| **`f` 或 F11** | 切换全屏 |
| **`Esc`** | **全屏时 = 退出全屏**；不在全屏时才退出程序 |

窗口打开时取"画面的 1.5 倍"与"屏幕的 90%"里较小的那个，所以不会只占屏幕中间一小块。

> **`Esc` 这条是刻意的**：全屏之后第一反应就是按 Esc 退出来；
> 如果它直接退出程序，你会把正在跑的东西关掉。
>
> **例外**：颜色标定（`calibrate_color.py`）里 `f` 已经是"冻结画面"，
> 所以那个程序**全屏只用 F11** —— 抢掉别人已经用的键比没有全屏更糟。

**哪些程序有**：实时检测、离线视频、标定前置检查、双目标定、相机识别、
颜色标定、焦距标定 —— 共 7 个。

### 12.2 任务：能中断跑飞的程序

启动器里有一张「任务」卡片，列出**启动器起过的每个程序**：

| 按钮 | 做什么 |
| ---- | ------ |
| **中断选中** | 先请求**优雅退出**（让程序自己收尾），3 秒不退再强制结束**整棵进程树** |
| **强制结束选中** | 立刻杀掉（会二次确认），来不及保存已完成的结果 |
| **全部中断** | 一次停掉所有在跑的任务 |
| **查看输出** | 把该任务的命令行 / PID / 耗时回显到日志区 |
| **打开日志文件** | 用系统默认程序打开该任务的完整日志 |
| **清理已结束** | 清掉已结束的记录（在跑的**绝不动**） |

**为什么"杀整棵进程树"重要**：`terminate()` **只杀直接子进程**。
我们的子进程是 python，它自己还有子进程。**父进程死了子进程还活着 —— 相机就还占着**，
下一次运行打不开相机，而用户看到的是"停了但相机用不了"。

**关窗口也会先收干净**：点关闭时如果还有任务在跑，会先停掉它们（含子进程树）再退出。
**旧版直接 `destroy()`，子进程不会被杀**。

### 12.3 日志都在哪

| 文件 | 内容 |
| ---- | ---- |
| `outputs/logs/task<NN>_<时间>_<标题>.log` | **每个任务一份**：命令行、PID、全部输出、退出码、耗时 |
| `outputs/logs/realtime_<时间>.log` | 实时检测：环境、相机模式、**每 5 秒一行健康度**、逐帧明细（DEBUG）、按过的键 |
| `outputs/logs/calibrate_<时间>.log` | 双目标定：**每一次拒收的原因**（这是查"为什么收不满"的唯一依据） |
| `outputs/logs/check_stereo_setup_*.log` | 标定前置检查 |

> **卡顿/失败时最有用的一条**是实时日志里的「健康度」行：
> ```
> 健康度 cap 31.6  loop 85.1  detect 7.9 ms  age 1.4 ms  drop 2
> ```
> `cap` 远低于 `loop` = 相机慢；反过来 = 我们慢。`age` 一大就是在积压。

### 12.4 标定参数面板

「第 1 步 · 相机标定」下有 **『基本设置』/『高级设置』** 两个页签，
默认值**就是正式档（25 对 / 最少 10 对）**，直接点「运行标定」即可。

| 页签 | 放什么 |
| ---- | ------ |
| **基本设置** | 目标/最少对数、标定板（内角点列·行、方格边长 mm）、分辨率、帧率 |
| **高级设置** | 停稳上限、清晰度下限、放宽模式、**预期基线 mm**、存图像对、验证图 |

参数会被校验（非数字、越界、"最少对数 > 目标对数"都会被拦下并说明原因）。

> **⚠️ 「预期基线 mm」默认是空的，这是故意的。**
> 程序**无法知道**你装置的中心距 —— 编一个数字进去会让基线核对**锚在错的值上**，
> 比留空更糟。**强烈建议用尺子量一下两镜头中心距填进去**：
> 这是唯一能发现"对应关系错配"的护栏（错配会把基线吹到真值的 8~15 倍）。
