# data/ — 真机录制会话

> **这里放"删了就没了"的数据。** 与相邻目录的区别：

| 目录 | 语义 | 丢了怎么办 |
| ---- | ---- | ---------- |
| `outputs/` | 可再生的运行产物（标注视频、CSV、调试图） | 重跑一次就回来 |
| `assets/` | 入库的静态素材（标定板 PDF、示例图） | 从 git 恢复 |
| **`data/`（这里）** | **不可再生的真机录制** | **只能靠备份** |

## 目录形态（2026-10-30 起）

```
data/stereo/<YYYYMMDD-HHMMSS>/    双目会话
data/mono/<YYYYMMDD-HHMMSS>/      单目会话
```

一个目录 = 一次采集，但**目录名按类型分**。以前双目放在 `data/sessions/` ——
`sessions` 是个通用词，里面却只有双目，而单目又另起 `data/mono`，
于是"会话"在磁盘上指了两样东西（用户原话："命名有歧义"）。
路径的唯一来源是 `sphere_tracker/paths.py`；旧位置 `data/sessions/` 仍被读取
（`stereo_roots()`），但不再写入，迁移用 `apps/tools/migrate_data_layout.py`。

## 双目会话长什么样

```
data/stereo/20261019-101500/
  session.json           ← 唯一权威元数据（相机 / 视频 / 标定 / 同步 / 环境）
  left.mkv               ← 左路原始视频（无损 FFV1）
  right.mkv              ← 右路原始视频（无损 FFV1）
  calib/                 ← 本次使用的标定快照（npz + json）
  derived/               ← CSV / 3D 图 / 标注视频（可再生产物，可删）
  notes.md               ← 现场备注（可选）
  left_times.csv         ← 逐帧采集时间戳（P1 录制器写；用来对齐/诊断）
  right_times.csv
```

- 目录名是 `YYYYMMDD-HHMMSS`，由 `stereo/sessions.py` 生成；重名自动加后缀。
- `session.json` 的字段见 `stereo/sessions.py` 的文档串与
  `docs/planbooks/2026-10-19_数据采集与结构整理.md` §4。
- **原始视频不要重命名、不要转码**；要标注/压缩就写到 `derived/`。

## 单目会话长什么样

```
data/mono/20261029-205522/
  clip.mkv               ← 原始视频（HuffYUV 无损，约 82 MB/s；10 秒 ≈ 800 MB）
  clip.mkv.json          ← 录制器写的实测值（分辨率 / 帧数 / 编码器）
  session.json           ← 会话元数据（相机、预期参数；实测值由 sync_from_take 补回）
  derived/               ← traj.csv / annotated.mp4 / visualization.json（可删）
```

- 单目**也要 `derived/visualization.json`** 才能进 3D 查看器；它由
  `run_video --vis-json` 写，**不写就只是"跑完了"，查看器里看不到**。
- 单目的深度靠球径先验（`Z = f·D/(2r)`），不是视差。`visualization.json` 里
  记着 `ball_diameter_mm` 与 `fx` —— 看到这两个数就该知道"这个 Z 是算出来的"。
- 录 10 秒约 800 MB，注意磁盘；`--codec mp4v` 可压小但丢无损。

## 会话怎么组织：`collections.json` 与 `index.json`（2026-11-09）

数据管理面板现在可以像文件资源管理器那样，把会话拖进「实验1 / 实验2 / 梨子」
这样的分组里。**分组结构存在 `collections.json`，不在磁盘上动一个字节。**

两个 JSON 都放在**数据根的同级**：默认根是 `data/stereo`，所以它们就是
`data/collections.json` 与 `data/index.json`；用「数据目录…」把面板指到
`E:/实验数据/stereo` 时，两个文件跟到 `E:/实验数据/` 旁边
（`apps/_session_index.paths_for_root()`）。好处是配置跟着那份数据走，
不会出现"换一块盘以后还显示上一棵树的分组"。

⚠️ **这两个文件都只在本地**，和 `data/stereo/` 一样**不进版本库、不进纯净交付包**：
会话本身不进 git，那么"指向这些会话的分组"单独进也没意义 ——
收包的人只会看到几个空的「实验1 / 实验2」目录，比没有更困惑。
要带着分组换机器，就连整份 `data/` 一起拷（或备份），不要指望 git。

**这两个文件不是一回事，别一起备份、也别一起删**：

| 文件 | 是什么 | 丢了怎么办 |
| ---- | ------ | ---------- |
| `collections.json` | **用户数据**：你手工点出来的分组树（`sid → 目录`） | 丢了要**重新点一遍**，没得重建 |
| `index.json` | **派生缓存**：时间 / 状态 / 帧数 / 大小的快照 | 删了自动重建，不心疼 |

一句话：`collections.json` 是"你组织的"，`index.json` 是"程序算出来的"。

### 为什么是"虚拟"分组，而不是真的挪目录

想把 `data/stereo/20261105-101500/` 放进「实验1/梨子」，最直觉的做法是把目录
挪到 `data/stereo/实验1/梨子/` 下面。**没这么做**，有四个理由：

- **会话路径被多处代码假设成两层**（`<根>/<时间戳>` 或 `<根>/<模式>/<时间戳>`），
  多一层就有扫描器看不见它 —— 会话在界面上**静默消失**，不报错（`apps/_session_index.py`
  的模块文档串里数了 7 处，旧枚举规则见 `apps/_stereo_layout.py`）。
- **`session.json` 里记的标定路径、`derived/` 里的相对引用会跟着错**，
  挪完要逐条改 JSON，改漏一处就是"打开就报找不到标定"。
- **挪 1.3 GB 会失败在半途**（U 盘、文件被占用、断电），而"挪了一半"没有任何
  回滚 —— 一半会话在新位置、一半在旧位置，两边都缺东西。
- **用户要的是视图，不是搬家**：同一段会话同时属于「11 月实验」和「梨子」
  是很自然的诉求，物理目录只能放一处。

所以 `collections.json` 里只记 **`sid`（`session.json` 的 `id`）→ 节点**，
磁盘一动不动；真要交付给别人时用导出包物化，不在本地搬家。这也顺带保证：
你在资源管理器里把会话拖进别的目录，分组**不会失效**（sid 跟着文件走，不跟路径走）。

### 怎么用 / 什么规则

- 一段会话**没被分到任何目录**时，界面上落在「**散会话**」里
  （`apps/_session_index.UNFILED_LABEL`），不会丢。
- 分组是层级路径，用 `/` 分隔，例如 `实验1/梨子`；根节点 `col-root`
  （名字「全部会话」）不算一级分组，它的 `session_ids` 表示"根层散会话"。
- 目录名会**从磁盘兜底**：没在 `collections.json` 里登记的会话，按它所在的
  相对目录显示分组（`data/stereo/实验1/<时间戳>` → `实验1`）。所以在资源管理器里
  自己建的目录也能如实显示，不会被当成不存在。
- **会话可以放在任意深度**（`实验1/梨子/<时间戳>` 也认）：枚举是**递归 + 命中即
  剪枝**（认出是会话就不再往里走），所以自建多层目录不会让会话消失。以前只认两层，
  用户自建目录会让那些会话在**所有面板里静默消失、不报错**。
- **允许手改 `collections.json`**（它是给人看的 JSON）。读的时候会自动修：
  父子关系成环 → 挂到根；`parent_id` 指向不存在的节点 → 挂到根；同一个 `sid`
  出现在两个目录 → **保留第一个**。**每一处修正都会在数据管理面板的日志区里
  以 `[配置] …` 打出来**，不会闷着改。
- **文件写坏了不会被打包成空配置覆盖掉**：解析失败时只在面板里按空配置显示，
  原文件原样保留（只在面板里点保存时才覆盖，且先留
  `collections.json.bak-<时间>`，保留最近 5 份）。
- ⚠️ **`index.json` 里的 `stereo_mode` 可能是 `null`** —— 那是"**没有记录**"，
  不是 parallel。2026-11-04 分区改造之前的会话都没有这个字段；默认成 parallel
  会让 90° 装置录的会话看起来"可用"，用错几何解算出来的深度系统性偏错且不报错。

## 校验

```powershell
$PY = "$env:USERPROFILE\miniforge3\envs\myenv\python.exe"
& $PY apps\tools\check_dataset.py data\stereo\20261019-101500
& $PY apps\tools\check_dataset.py --root data\stereo            # 全部
```

校验内容：两路视频能否打开、分辨率是否与 `session.json`/标定一致、
帧数差、标定 sha256、基线（算法 vs 物理测量）偏差、同步偏移范围。
**录完立刻跑一次**；等处理时才发现录坏了，代价是重录。

## 备份

`data/` 默认被 `.gitignore` 忽略。**每次采集后至少复制到一块外部硬盘/网盘**；
不要只留在这台机器上。需要进版本库的只有元数据时，用
`check_dataset.py --export-meta <目标目录>`（计划 P1）；原始视频不进 git。
**唯一进版本库的是这份 `README.md`**：`collections.json`（分组结构）虽然是人手工
组织的、丢了要重新点一遍，但它和会话绑在一起，只在本地 —— 备份 `data/` 时
把它一起带上，别只指望 git。

## 不要放

- 交付物（开题报告、答辩稿）→ `docs/` 或课程目录；
- 可再生的处理结果 → `outputs/` 或本会话的 `derived/`；
- 示例图片/标定板 → `assets/`。
